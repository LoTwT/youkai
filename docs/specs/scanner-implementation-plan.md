## 1. 目标、依据与起点

目标是在已验证的显示配置下，完成三种客户端的 S 级驱动盘扫描、保存、截图校对和自有文件导出，并交付 Windows 安装包及 Mac DMG。范围以[公共架构第 6 节](scanner-architecture.md#6-首版功能范围)为准，交付判断以 [T7](t7-public-release-acceptance.md#2-首版交付门槛)为准。

本文只维护实施顺序、阶段产物和交接要求。接口或行为调整时，先更新下表中的权威规格，再更新涉及的任务。

| 依据 | 用途 |
| --- | --- |
| [公共架构](scanner-architecture.md#3-最小合理边界) | 模块关系、会话控制、结果记账、保存恢复和目录边界。 |
| [T1](t1-mygo-ui-distribution.md)、[T2](t2-platform-capture-input.md)、[T3](t3-ocr-runtime-model-samples.md) | 原生 UI 与构建、平台能力、OCR 和样本；固定版本与摘要从专项文档读取。 |
| [T5](t5-zzz-inventory-traversal.md)、[T6](t6-review-export-workflow.md)、[JSON v1](scan-json-format.md) | 页面与遍历证据、用户操作、校对及文件契约。 |
| [T7](t7-public-release-acceptance.md) | 最低系统候选、离线安装、打包路线及完整验收。 |

当前仓库已建立 Go 工程：`go.mod` 固定模块路径与 MyGo v0.5.5 工具依赖，`mygo.json` 与 `cmd/youkai/` 入口就位，其余包按里程碑逐步增加。开发机为 macOS arm64、Go 1.27.2，Xcode 开发目录已选中，`hdiutil`、`codesign`、`makensis` 可定位；PATH 中的 `clang` 指向 Homebrew LLVM，正式构建需明确所用编译器与 SDK。MyGo 使用项目固定的 Go 工具依赖（v0.5.5），不依赖全局 `mygo` 命令；环境与常用命令见[开发指南](../development.md)。

采用一个 Go 模块、一个应用进程、一个活动扫描会话，按公共边界组织普通包，平台桥接只覆盖必要的原生 API。最小路线是单输入控制者、一个 OCR 工作者和有界队列。

### 开发与 Windows 测试方式

用户决定（2026-10-16）：在当前 Mac 上开发，不转到 Windows 开发；Windows 测试使用 GitHub Actions 构建的安装包，用户不在 Windows 上安装开发工具。测试时机按进展安排：可在中间节点由用户到 Windows 上测试，也可先在 Mac 上完成一个较大阶段，再集中做一轮 Windows 测试。

- 交给用户测试的 Windows 制品统一来自 GitHub Actions 的 Windows runner 构建的安装包（MyGo 在 Windows 上可自动下载 NSIS）；需要快速排查与 VC++ 运行库无关的问题时，可由 Mac 交叉编译免安装包补充。
- 日常在 Mac 上做 Windows 交叉编译检查，尽早发现平台隔离和编译问题。cgo（OCR 绑定）的 Windows 交叉编译需要 mingw-w64 工具链，本机已安装（`/opt/homebrew/bin/x86_64-w64-mingw32-gcc`）。交叉编译通过不代表能在 Windows 上运行，VC++ 相关问题也不在其覆盖范围内。
- 以下内容只能在 Windows 实机验证：DLL 与 VC++ 运行库加载、截图、SendInput、托盘与全局快捷键、安装包和游戏响应。每次交给用户测试时附上制品版本、测试步骤和预期结果，结果写回对应记录。
- 风险较高的节点建议尽早安排 Windows 测试，不要等到 M4：M1 末的安装包与 ORT 加载，以及 M2 的 Windows 采集与输入。具体合并到哪一轮测试由进展决定。

### 已定的工程约定

用户于 2026-10-16 确认：

- **标识：** Go 模块路径为 `github.com/LoTwT/youkai`；应用标识（bundle identifier）为 `com.lotwt.youkai`，显示名 `Youkai`。应用标识会写入数据目录、单实例锁、协议注册和 macOS 权限记录，发布后不再更改。
- **VC++ 运行库：** 采用应用本地部署，随应用放在 EXE 目录，不运行需提权的安装器；所需 DLL 取自 GitHub Actions Windows runner 上 Visual Studio 的 `VC\Redist\MSVC` 目录，不从 vc_redist 安装器解包。见 [T3](t3-ocr-runtime-model-samples.md#绑定与运行库的实际交接)。
- **许可证：** MIT，仓库根目录 `LICENSE` 复制自 `LoTwT/ts-starter`。随包的 ORT（MIT）、模型（Apache 2.0）等第三方声明另行附带，见 [T7](t7-public-release-acceptance.md#2-首版交付门槛)。
- **版本号：** 首个发布版为 `0.0.1`，按语义化版本递增。MyGo 在 `mygo.json` 未填 `version` 时默认使用 `0.1.0`，因此必须显式填写；同一版本号写入安装包、DMG 和 JSON 的 `producer.version`。
- **构建与发布：** 正式发布由 GitHub Actions 构建两个平台的制品，随版本发布在 GitHub Releases（`LoTwT/youkai`）上；Windows 上的测试同样使用 GitHub Actions 产出的安装包（用户不在 Windows 上安装开发工具），快速排查非 VC++ 问题时可由 Mac 交叉编译免安装包补充，见[开发与 Windows 测试方式](#开发与-windows-测试方式)。
- **自动更新：** 首版包含，使用 MyGo v0.5.5 内置更新，从 GitHub Releases（`LoTwT/youkai`）获取经 MyGo 更新密钥签名的版本；范围与规则见[架构第 6 节](scanner-architecture.md#6-首版功能范围)，交付证据见 [T7](t7-public-release-acceptance.md#2-首版交付门槛)。发布时以标签版本为准（`test-v*` 测试渠道、`v*` 正式渠道，靠 `updates.tagPrefix` 隔离），仓库内 `mygo.json` 不随发布改版本号；发布 workflow、密钥管理与升级实测清单见[发布与自动更新](../release.md)。
- **第三方大文件：** ORT 运行库和 OCR 模型不进 Git，由仓库内脚本按固定 URL 与 SHA-256 下载到被忽略的目录；VC++ 运行库文件取自 GitHub Actions 的 Windows runner（见 VC++ 条目），同样不进 Git。本地构建、测试和 CI 都调用同一脚本，摘要不符即失败。
- **PR 检查：** Mac 本地测试与 Windows 交叉编译通过即可合并；只能在 Windows 实机验证的内容记入待测清单，在用户的 Windows 上集中测试后再修。GitHub Actions 在 PR 上运行轻量检查：格式、`go vet`、`go test`，覆盖 macOS 与 Windows 两个 runner；不在 PR 上打安装包、跑长时间测试或游戏相关检查。供 Windows 测试的安装包由 GitHub Actions 按需构建（见[开发与 Windows 测试方式](#开发与-windows-测试方式)），正式发布制品构建放在发布流程中。
- **本机工具：** 需要新增 mingw-w64 等工具时，先告知用户，由用户优先手动安装。
- **PR 流程：** 本机 git skills 支持栈式 PR，但没有规定拆分或合并方式；仓库允许 merge、squash、rebase 三种合并。具体方式在实施拆分 PR 时按当时要求决定。
- **提交溯源：** 安排任务的会话和实施会话可能不同；Agent-Models 所需的模型与 effort 由用户在实施前告知。
- **以后再定：** 全局停止快捷键在 M2 实测时确定；macOS 首次打开（ad-hoc 签名会被 Gatekeeper 拦截）的说明随 M4 操作说明编写。

## 2. 代码与文件落点建议

获实施授权后按实际功能逐步增加文件，不预生成空接口和目录。

| 拟用位置 | 负责的工作 |
| --- | --- |
| `go.mod`、`go.sum`、`mygo.json`、`cmd/youkai/` | 固定依赖和 MyGo 工具、应用标识、版本与打包配置；入口只组装应用。`mygo.json` 的 `main` 指向 `./cmd/youkai`，不建立 Web 工程。 |
| `internal/app/`、`internal/ui/` | 应用服务持有会话和保存；MyGo 页面、快照订阅、托盘或菜单栏、协议唤起调用应用服务。 |
| `internal/scan/` | 控制流、输入许可、队列、采集序号、处理记账和终结；不放驱动盘字段与游戏坐标。 |
| `internal/platform/` | 按目标平台隔离 Windows 调用与 Mac 薄层原生桥接，提供窗口、几何、权限、采集、输入和停止能力。 |
| `internal/recognition/` | ORT 生命周期、模型资源、预处理、推理和解码；不判断套装或属性是否可信。 |
| `internal/game/zzz/` | 驱动盘类型、资料目录、布局、页面前提、详情归属、遍历及字段校验。 |
| `internal/record/` | 检查点、证据文件、历史、修订、JSON 与档案往返、清理。 |
| `resources/`、包内 `testdata/` | 前者只放随包模型、字符表、游戏资料、目标平台原生库和声明；后者放获准保留的测试输入与预期。真实用户截图和完整样本集不自动纳入 Git 或安装包。 |

调用方向沿用[公共架构图](scanner-architecture.md#3-最小合理边界)：平台和识别包不依赖 MyGo 或 ZZZ，游戏适配器不持有 UI，持久化与界面通过应用服务协调。

上述判定中，安装版扫描生命周期与第 5 项的干净环境（无系统 VC++）Windows 随包运行库不可或缺性是仅有的两处证据缺口，均经用户决定随收尾接受、不补测；其余剩余验证项及去向见第 5、6 项说明。

通过条件：用户可以完成准备、扫描、校对、保存、导出、重开和清理的完整流程；失败不会伪装成完整库存，字段校正不改变覆盖结论；所有已采集项都能解释去向，重复盘各自保留。

## 4. 需要尽早取得的证据

开发侧负责结论与规格回写，并提供构建、检查步骤和诊断，用户提供设备操作、游戏样本和预期结果复核。不能以 Mac 构建成功替代 Windows 实测。

| 问题 | 最迟处理时点 | 证据不足或失败时 |
| --- | --- | --- |
| 两平台资源、cgo、部署目标与 Windows VC++ 前提 | M1 已核（干净环境 VC++ 经用户决定不补测，2026-10-18，见[第 3 节 M1](#m1正式工程资源与会话底座)）；最低系统随 M4 验收 | 先修复加载和打包；需换绑定或运行库时在相同输入上比较，回写 T3/T7。 |
| Mac 云客户端的采集、输入、全局停止键和坐标 | M2 首项 | 预检失败禁止输入；平台能力不能支撑既定客户端时，提供重现结果和替代成本，由用户决定范围调整。 |
| 锁定、弃置和装备代理人能否可靠读取 | M2 首批样本 | 核对同帧、悬停或只读页面路径及耗时；必需字段缺失阻止自动接受，不可行时明确提出取舍，不输出默认状态。 |
| 布局、筛选、顶部、选中与末尾证据 | M2 定字段与起点；M3 完成遍历判据 | 视觉证据缺口须解决或显式重新确认范围；不以等待时长或图像重复代替证据。 |
| 超时、OCR 线程、队列与性能预算 | M2 建基线，M3 封存验收前冻结 | 先分离导航等待和 OCR 耗时；换模型时沿用同组调参样本比较；不在看到验收结果后放宽门槛。 |

最脆弱的假设是：三种客户端的画面足以确认当前物品、实际位移和结束位置，且 Mac 云客户端能接收受控输入。若不成立，换 OCR 模型不能补救，应停止扩大自动遍历，带实测证据讨论范围。

## 5. 验证命令与执行记录

下列命令已投入使用：格式、`go vet` 与 `go test` 随双平台 CI 在每个 PR 运行，`mygo vet` 在 macOS runner 运行，其余按需在本地执行；完整环境与命令以[开发指南](../development.md)为准。两平台分别准备目标 C 编译器，在调用进程中显式设置 `CGO_ENABLED=1`，不依赖全局 MyGo 或全局 ORT 路径。

```text
go test ./...
go tool mygo vet .
go test -race ./internal/app ./internal/scan ./internal/record
```

竞态检查覆盖有并发生命周期和持久化测试的包，不能证明原生调用安全。`mygo vet` 接收应用目录，会先运行 `go vet ./...` 再检查原生 UI，不能写成 `mygo vet ./...`。[vet_ui.go](https://github.com/egoist/mygo/blob/4d8673cd2658a2c6e86b26c44751e57bf8174f91/cmd/mygo/vet_ui.go)

以下两条生成两平台制品，完整命令（先 fetchdeps 下载资源、显式 `CGO_ENABLED=1`、macOS 另设部署目标）见[开发指南的打包与安装包](../development.md#打包与安装包)；本地与 Package/Release workflow 均已实际执行，须确认确实生成了安装包或 DMG，跳过打包的退出成功不算通过：

```text
go tool mygo build -platform windows/amd64
go tool mygo build -platform darwin/arm64
```

入口与构建方式依据 [config.go](https://github.com/egoist/mygo/blob/4d8673cd2658a2c6e86b26c44751e57bf8174f91/cmd/mygo/config.go)、[build.go](https://github.com/egoist/mygo/blob/4d8673cd2658a2c6e86b26c44751e57bf8174f91/cmd/mygo/build.go) 和[分发说明](https://github.com/egoist/mygo/blob/4d8673cd2658a2c6e86b26c44751e57bf8174f91/docs/distribution.md)。

自动测试优先覆盖数据损失和错误归属风险：迟到结果不跨会话写入、相同盘不合并、取消后不接纳新输入、写入失败可恢复上一检查点、修订确认与导出一致、导入和清理不越出目标目录。原生权限、失焦与坐标、首次打开、中文输入法和游戏响应必须在对应系统核验。

实测记录至少包含构建与资源版本、系统与显示配置、输入及人工预期、实际结果、失败复现和结论。可复用的开发命令写入 `docs/development.md`；首份实测报告产生后再建立报告文件并加入索引。

## 6. 成本、交接与变更控制

成本沿用[公共估计](scanner-architecture.md#8-工作量主要风险与改变结论的证据)：约 40–70 个开发日，不是交付日期承诺；M2 完成后依据实际成本复估，用户测试与样本标注需要可安排的时间。

构建端需要取得公开依赖和模型；安装后的识别、校对与导出不需要 API key 或新账户。不购买发布者证书；自动更新采用 MyGo 内置机制（见[架构第 6 节](scanner-architecture.md#6-首版功能范围)），不自建更新服务，也不新增浏览器界面。

每个里程碑交接提供可运行内容、修改文件、已过检查、未过项和下一步。JSON 契约变更先说明兼容策略，不原地改写用户已保存的库存。构建完成不等于已获提交、推送或发布授权。
