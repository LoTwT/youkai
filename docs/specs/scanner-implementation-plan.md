# 扫描器首版实施清单

更新日期：2026-10-16。状态：主控整理的执行建议，四个工程里程碑均未开始。当前授权仍为评估和文档维护；本文没有将已确认的产品选择扩大为应用实施、依赖安装或发布授权。

首版作为一次完整交付，内部按下列四个里程碑检查进展。期间的构建供开发和用户测试，不作为删减范围的正式版本，也不另做独立 UI 验证版。

## 1. 目标、依据与起点

目标是在已验证的显示配置下，完成三种客户端的 S 级驱动盘扫描、保存、截图校对和自有文件导出，并交付 Windows 安装包及 Mac DMG。平台、实体和字段范围以[公共架构第 6 节](scanner-architecture.md#6-首版功能范围建议)为准，交付判断以 [T7](t7-public-release-acceptance.md#2-首版交付门槛)为准。

本文只维护实施顺序、阶段产物和交接要求。发生接口或行为调整时，先更新下表中的权威规格，再更新涉及的任务。

| 依据 | 本清单如何使用 |
| --- | --- |
| [公共架构](scanner-architecture.md#3-最小合理边界) | 模块关系、会话控制、结果记账、保存恢复和目录边界；T4 不另建一套状态。 |
| [T1](t1-mygo-ui-distribution.md)、[T2](t2-platform-capture-input.md)、[T3](t3-ocr-runtime-model-samples.md) | 原生 UI 与构建、平台能力、OCR 和样本方案；固定候选版本及摘要从专项文档读取，不在本文复制。 |
| [T5](t5-zzz-inventory-traversal.md)、[T6](t6-review-export-workflow.md)、[JSON v1](scan-json-format.md) | 页面与遍历证据、用户操作、校对及文件契约。 |
| [T7](t7-public-release-acceptance.md) | 最低系统候选、离线安装、无付费证书的打包路线及完整验收。 |

当前仓库只有规划和合成文件示例，没有 `go.mod` 或应用代码。已取得源码及候选制品的静态证据，没有运行 MyGo、OCR 或游戏扫描。

本轮只读环境检查确认本机是 Go 1.27.2 macOS arm64，Xcode 开发目录已选中，`hdiutil`、`codesign`、`makensis` 可定位；PATH 中的 `clang` 指向 Homebrew LLVM。工具存在不等于构建通过，正式构建需明确所用编译器与 SDK。未发现全局 `mygo` 命令，后续使用项目固定的 Go 工具依赖；Windows 工具链尚未检查。用户会在测试前准备两台设备及客户端，实际可用条件由测试记录确认。

采用一个 Go 模块、一个应用进程、一个活动扫描会话。按公共边界组织普通包，平台桥接仅覆盖必要的原生 API。最小路线仍是单输入控制者、一个 OCR 工作者和有界队列；目前没有证据需要动态插件、多截图后端、GPU 推理或辅助服务。

## 2. 代码与文件落点建议

以下是获实施授权后的落点建议，当前不创建这些目录。整体预计涉及超过 8 个实现文件；按实际功能逐步增加，不预生成空接口和目录。

| 拟用位置 | 负责的工作 |
| --- | --- |
| `go.mod`、`go.sum`、`mygo.json`、`cmd/youkai/` | 固定依赖和 MyGo 工具、应用标识、版本与打包配置；入口仅组装应用。MyGo 配置的 `main` 指向 `./cmd/youkai`，纯原生模式不建立 Web 工程。 |
| `internal/app/`、`internal/ui/` | 应用服务持有会话和保存操作；MyGo 页面、快照订阅、托盘或菜单栏、协议唤起调用应用服务。 |
| `internal/scan/` | 控制流、输入许可、队列、采集序号、处理记账和终结；不放驱动盘字段与游戏坐标。 |
| `internal/platform/` | 按目标平台隔离 Windows 调用与 Mac 薄层原生桥接，提供窗口、几何、权限、采集、输入及停止能力。 |
| `internal/recognition/` | ORT 生命周期、模型资源、图像预处理、推理和解码；不判断套装或属性是否可信。 |
| `internal/game/zzz/` | 明确类型的驱动盘、资料目录、布局、页面前提、详情归属、遍历及字段校验。 |
| `internal/record/` | 检查点、证据文件、历史、修订、JSON 和档案往返、清理；复用明确的 ZZZ 载荷，避免另造通用物品字典。 |
| `resources/`、包内 `testdata/` | 前者仅放随包模型、字符表、游戏资料、目标平台原生库和必要声明；后者放获准保留的测试输入与预期结果。真实用户截图及完整样本集不因测试需要自动纳入 Git 或安装包。 |

调用方向沿用[公共架构图](scanner-architecture.md#3-最小合理边界)。平台和识别包不依赖 MyGo 或 ZZZ，游戏适配器不持有 UI；持久化与界面通过应用服务协调。共享状态由内核和公共结果契约各自维护，包数不等于需要相同数量的公共接口。

## 3. 四个内部里程碑

### M1：正式工程、资源与会话底座

关联 T1、T3、T4、T7。先让双平台正式工程具备可安装、可诊断、可停止和可保存的基础。

- [ ] 建立 Go 原生应用、固定候选依赖和目标平台构建配置；资源根与用户数据根分开，开发与正式记录分开。设置实际部署目标，并落实拟声明最低系统的测试环境；环境缺口在此记录，M4 未实测前不宣布支持。
- [ ] 接入一套 OCR 绑定和 CPU 运行库，以绝对路径加载固定模型与字符表；完成预处理、解码、取消、再次运行和资源释放。用可控图片做内部集成检查，不增加首版“任意图片导入识别”功能。
- [ ] 实现应用持有会话、进程全程的数据根占用、跨数据根的扫描占用和 MyGo 窗口复用；用两个独立进程验证同根编辑竞争、导出与删除竞争、路径别名、持有者崩溃后恢复，以及不同数据根只能一个扫描。实现输入许可、有界队列、接纳序号和终结记账，用可控平台事件验证队列满、迟到结果、重复通知和并发停止。
- [ ] 实现证据先写入、检查点更新、上一有效版本恢复及当前保存修订；接入正式界面的准备、进度和结果视图，能展示失败与未处理项。
- [ ] 在对应主机生成早期安装包与 DMG；补齐 Windows VC++ 分发版本及安装处理，核对 Mac 编译器、SDK、原生库系统标记和本地签名。记录缺失工具，只准备这条路径确实需要的工具。

通过条件：两个目标平台的安装后应用都能加载随包资源，完成可控识别、停止、保存、重开及再次运行；缺库或模型损坏有可定位的结果。并发与写入故障测试证明已接纳记录不会无故消失或被迟到结果改写。原生调用结束后才释放对象。此时尚不能宣称游戏兼容或完整离线首装通过。

### M2：三种客户端的单件完整流程

关联 T2、T3、T4、T5、T6。M1 的可运行工程、输入许可和停止入口就绪后，M2 先接入最小平台预检，优先完成 Mac 云客户端的采集、受控输入与停止验证；这项风险检查不等待 Windows 完整单件功能做完。随后可先贯通 Windows 完整客户端，再完成两种云客户端；三种场景均通过后，才把投入扩大到整仓遍历。这些工作都接入正式工程，不另建 UI 验证版。

- [ ] 为每种客户端记录首组显示配置、窗口身份、输入坐标和图像单位；明确云视频区域，核验用户手动准备的仓库起点。Windows 从既定二选一候选中选一组实测，Mac 按实际画面测绘。
- [ ] 接入采集、短输入和权限检查；验证前台、几何变化、失去目标、撤权和全局停止键。输入许可在预检前保持关闭，停止后不因重新隐藏窗口而恢复。
- [ ] 先按 T3 建立物品来源和调参/封存划分，隔离开发库存序列与未见物品；每客户端收集约 20 至 30 件典型盘作为调参样本，人工独立标注。优先包含锁定、弃置、已装备和未装备状态，确认读取是否需要悬停或只读切页；同时取得短跨页、重复盘和末端序列，提前核对 T5 所需证据是否可观察。不能点击会修改游戏物品状态的按钮。
- [ ] 接入固定游戏资料与字段校验，核对全部槽位、0 至 15 级及套装范围所需规则；资料缺失与字段未知进入明确的问题状态，不套用满级表或猜测默认值。
- [ ] 在实际单件流程中贯通“验证选中及详情归属 → 采集 → OCR → 保存 → 截图校对与修正 → 数据 JSON／完整档案 → 重新打开”。阶段测试主动停止时保留部分覆盖结论，不把采到一件当作整仓完成。
- [ ] 记录冷启动、单件延迟、OCR 与等待游戏时间、CPU 和内存；在真实游戏同时运行时调整线程、队列和超时。参数由主控依据调参集冻结，不用封存验收集调参。

通过条件：三种客户端分别留下真实截图、输入响应和单件往返证据；保存和校对始终对应同一件盘。管理状态的实际读取路径、首组显示参数和停止键已经查明，并写回所属规格；锁定仍是必需项，装备代理人与弃置按“可行即纳入”执行。遇到无法实现的范围，带具体证据回到主控处理，不自行删减首版。

### M3：整仓扫描与完整日常使用

关联 T4、T5、T6，并继续验证 T1、T2、T3。

- [ ] 按 T5 实现范围核验、选择与详情就绪、滚动衔接、末尾和空仓判断；保留真实重复盘，无法证明位置或详情归属时停止并保存部分结果。
- [ ] 串联正常结束、主动停止、失焦、断流和保存失败；分别呈现输入许可、原生任务和保存状态，恢复记录不自动续扫。
- [ ] 完成全部结果浏览、问题项导航、截图查看和字段编辑；人工确认绑定当前修订，自动接受与待校对项按 JSON 契约筛选，导出显示纳入、排除和覆盖结论。
- [ ] 完成历史重开、档案导入导出、默认目录、占用提示及手动清理；验证当前规则重校验不覆盖原始审计、旧确认不能绕过冲突，混合品质的访问/跳过/采集与衔接账目可保存并读回。验证忙碌保护、删除中断、缓存与证据区分、外部文件保护，以及升级或卸载保留历史。
- [ ] 完成两种关窗模式、托盘或菜单栏、明确退出、第二实例及 `youkai://open` 唤起；扫描中恢复主窗先停止输入，任何入口不自动开始扫描。
- [ ] 按 T3 补足三组调参及封存样本，按物品来源分组防止跨客户端泄漏；按 T6 用 1,000 与 10,000 条合成记录检查列表、图片缓存和连续校对，两平台实际检查中文输入法与文件对话框。

通过条件：用户可以完成准备、扫描、校对、保存、导出、重开和清理的完整流程。失败不会伪装成完整库存，字段校正不会改变覆盖结论；所有已采集项均能解释去向，重复盘各自保留。界面压力输入不能替代真实扫描准确性验收。

### M4：双平台交付验收

关联 T7，按既有专项标准汇总全部证据。

- [ ] 冻结待验收构建、依赖、模型、资料目录及显示配置，记录版本和摘要；先完成字段标注复核，再打开封存集评估，逐客户端报告自动错误、正确完成比例及校对量。
- [ ] 三种客户端分别完成至少三次人工基准库存扫描；逐件和逐出现次数核对字段、遗漏、重复、详情归属与末尾，不以总数相等证明正确。
- [ ] 在拟声明的最低系统及支持配置完成实测；在无开发工具的环境断网安装，验证固定图片识别、校对、保存和文件往返。云游戏另在联网条件验收。
- [ ] 覆盖 T7 的异常停止、保存恢复、存储清理、网页唤起和平台首次打开行为；采用最终签名与打包后的制品复核资源及摘要，不用开发运行代替安装验收。
- [ ] 交付 Windows 安装包、Mac DMG、精确支持矩阵、简体中文操作说明、随包声明与测试报告；列明必须保持游戏前台、手动准备起点、首次打开步骤和已知限制。

通过条件：T7 交付表有逐项证据，没有影响已承诺范围的未处理失败。T3 的有限样本零自动接受错误与各组自动正确完成候选门槛分别判定，T5 的遍历完整性另行判定。验收失败先修复并重测受影响范围；封存样本一旦用于调参，应另建独立验收集。未取得证据的配置不写入支持列表。

## 4. 需要尽早取得的证据

主控负责下表结论与规格回写；开发侧提供构建、检查步骤和诊断，用户提供实际设备操作、游戏样本及预期结果复核。远端设备没有执行通道时，只记录实际收到的证据，不能以 Mac 构建成功替代 Windows 实测。

| 问题 | 最迟处理时点 | 证据不足或失败时的处理 |
| --- | --- | --- |
| 两平台资源、cgo、部署目标与 Windows VC++ 前提 | M1；M4 补干净环境与最低系统验收 | 先修复加载和打包；若需换绑定或运行库，在相同输入上比较，回写 T3/T7。不把缺少验证改成已兼容。 |
| Mac 云游戏的采集、输入、全局停止键和实际坐标 | M2 首项，具备最小预检与停止保护后 | 预检失败禁止输入；如果平台能力不能支撑既定客户端，提供重现结果和替代成本，由主控处理范围，不等待完整单件功能或整仓开发结束。 |
| 锁定、弃置和装备代理人是否可可靠读取 | M2 首批真实样本 | 核对同帧、悬停或只读页面路径及耗时；必需字段缺失阻止自动完整接受。不可行或代价超出原假设时明确提出取舍，不能悄悄输出默认状态。 |
| 全等级资料、布局、筛选、顶部、选中与末尾证据 | M2 定字段与起点，并取得短跨页和末端序列；M3 完成遍历判据 | 已确认范围的资料和视觉证据缺口必须解决或显式重新确认范围；不以合法数值猜测、等待时长或图像重复代替证据。 |
| 超时、OCR 线程、队列与性能预算 | M2 建基线，M3 在封存验收前冻结 | 先分离导航等待和 OCR 耗时，再调整瓶颈；需要更换模型时沿用同组调参样本比较，保留拒识和人工校对量。不得看到验收结果后反向放宽门槛。 |

本方案最脆弱的假设是：三种客户端的可观察画面足以可靠确认当前物品、实际位移和结束位置，且 Mac 云客户端可接收受控输入。如果不成立，单纯换 OCR 模型不能补救；应停止扩大自动遍历，回到平台或页面交互路径核对，带实测证据讨论范围变化。正常失败则按公共契约保留部分记录，不冒充完成。

## 5. 验证命令与执行记录

下列命令是后续项目建成后的执行入口，本轮未运行。两平台分别准备目标 C 编译器，在调用进程中显式设置 `CGO_ENABLED=1`；不依赖全局安装的 MyGo 或全局 ORT 搜索路径。

```text
go test ./...
go tool mygo vet .
go test -race ./internal/app ./internal/scan ./internal/record
```

竞态检查覆盖有并发生命周期和持久化测试的包，在支持的目标工具链执行；它不能证明原生调用安全。`mygo vet` 接收应用目录，固定版本会先运行 `go vet ./...` 再检查原生 UI，不能将它写成 `mygo vet ./...`。[固定源码](https://github.com/egoist/mygo/blob/4d8673cd2658a2c6e86b26c44751e57bf8174f91/cmd/mygo/vet_ui.go)

以下两条分别在对应主机、项目根目录执行；检查确实生成安装包或 DMG，不能把跳过打包步骤的退出成功算通过：

```text
go tool mygo build -platform windows/amd64
go tool mygo build -platform darwin/arm64
```

入口 `main` 配置与上述构建方式已从固定版本的 [config.go](https://github.com/egoist/mygo/blob/4d8673cd2658a2c6e86b26c44751e57bf8174f91/cmd/mygo/config.go)、[build.go](https://github.com/egoist/mygo/blob/4d8673cd2658a2c6e86b26c44751e57bf8174f91/cmd/mygo/build.go)和[分发说明](https://github.com/egoist/mygo/blob/4d8673cd2658a2c6e86b26c44751e57bf8174f91/docs/distribution.md)核对；需要的 cgo 和系统工具仍需实际工程证明。

自动测试优先覆盖有数据损失或错误归属风险的行为：迟到结果不得跨会话写入、相同盘不合并、取消后不再接纳新输入、写入失败可恢复上一检查点、修订确认与导出一致，以及导入和清理不越出目标目录。原生权限、失焦与坐标、安装首次打开、中文输入法和三客户端游戏响应必须在对应系统核验。

执行时只为已开展的工作增加记录，至少保留“构建与资源版本、系统和显示配置、输入及人工预期、实际结果、失败复现和结论”。可复用的开发命令进入 `docs/development.md`，首份实测报告产生后再建立对应报告文件并加入索引，不预建空报告。

## 6. 成本、交接与变更控制

沿用[公共成本估计](scanner-architecture.md#8-工作量主要风险与改变结论的证据)：在既定条件下约 40 至 70 个开发日，不是交付日期承诺。四个里程碑横跨原工作项，不能再把里程碑与 T1 至 T7 的估算相加。M2 完成后依据实际桥接、采样和页面成本复估；用户测试与样本标注需要可安排的时间。

构建端需要取得公开依赖和模型，安装后的本地识别、校对与导出不需要 API key 或新服务账户；游戏登录和云游戏网络仍由用户的现有客户端负责。按 T7 不要求购买发布者证书，不新增在线更新服务或浏览器界面。外部工具兼容、新游戏和更多显示尺寸有具体需求后另行评估。

每个里程碑交接应提供可运行内容、修改文件、已过检查、真实未过项及下一步，继续在主控讨论。工程调整可回退应用和依赖选择，历史、截图及外部文件保留；JSON 契约变更先说明兼容策略，不原地改写用户已保存库存。构建制品完成不等于已获提交、推送或公开发布授权。

本清单完成时只新增和更新文档，已做源码命令核对及本机工具只读检查；没有创建应用工程、安装依赖或执行上述验收。
