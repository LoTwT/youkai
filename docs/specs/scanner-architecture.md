# MyGo + Go 扫描器架构

更新日期：2026-10-21。状态：产品范围已由用户确认；模块边界与会话契约的 M1 底座（工程与构建、OCR、会话与占用锁、持久化、主窗口、打包与自动更新）已实施并经两平台实机验证（结论见[实施清单 M1](scanner-implementation-plan.md#m1正式工程资源与会话底座)），M2 起的采集、输入、遍历与游戏适配仍为设计方案。2026-10-20 冻结 M3 的数据模型、JSON/CSV 导出、截图与历史清理、默认目录和窗口关闭行为；相关实现按[实施清单 M3](scanner-implementation-plan.md#m3整仓扫描与完整日常使用)的顺序推进。

本文维护公共架构：模块边界、应用层与会话契约、OCR 集成要求、结果与存储语义、首版范围、验收与成本。专项细节由 T1–T7 和 [JSON/CSV v2](scan-json-format.md) 维护，实施顺序见[首版实施清单](scanner-implementation-plan.md)，背景见 [Handoff](../scanner-handoff.md)。

## 推荐结论

MyGo + Go 值得继续。MyGo 承担窗口、交互与分发，Go 管理串行游戏操作、识别任务和资源生命周期。主要风险不在桌面框架，而在窗口操作是否可靠、截图是否对应目标、OCR 是否可信，以及原生运行库能否随安装包运行。

采用一个应用进程、一个活动扫描会话、内置游戏适配包和本地 CPU ONNX 推理。先以绝区零驱动盘完成扫描、校对、导出闭环；第二款游戏出现后再提炼共同接口。不做动态插件、工作流语言、独立扫描服务或可替换一切的框架。

界面采用用户确认的 MyGo 原生 UI（动机是轻量），跳过独立 UI 验证版，界面检查并入正式功能验收，见 [T1](t1-mygo-ui-distribution.md#1-已确认选择与界面建议)。单件 OCR 演示或“导入截图 → 识别 → 导出”工具都不算首版交付。

## 2. 界面选择与应用层

界面为结果列表、证据图和字段表单，支持筛选与“下一个待校对项”；中文输入、键盘操作、图片缩放、长列表与内存检查并入正式验收。以下为应用层公共契约：

- 原生 UI 只调用应用服务的开始、查询、停止、修订和导出能力；会话、结果和保存状态不属于窗口。应用服务拥有进程级资源和退出协调，窗口隐藏或重建不新建会话。
- 每次开始操作带进程内唯一请求标识。服务接纳时即占用唯一活动位置并返回会话标识；同一请求重复到达返回原会话（即使已结束），活动期间的其他请求返回已有会话及忙碌状态。界面未收到结果时按请求查询，不自动重新发起。重启只恢复保存结果，不重放开始请求。
- 状态快照是权威依据，通知只表示有变化；两者带会话标识与递增修订号。界面订阅后重取快照，丢弃旧会话和旧修订；通知可合并，慢 UI 不阻塞采集、停止或保存。
- 进度只显示可证实的阶段与计数。后台进度和完成提示不激活主窗口，也不自动开始下一次扫描。
- 图片以会话内稳定证据标识关联，按需加载并限制解码缓存；不为显示图片增加 Web 服务，不接受 UI 拼接的任意文件路径。
- 修订命令带目标观测标识和该物品的期望修订号；其他物品或进度变化不制造冲突，旧提交不覆盖新结果。保存失败保留待保存修改和上一份已保存结果，不显示为已保存。

UI、菜单与关闭回调只安排异步工作，不等待采集或 OCR；后台不持有服务锁等待 UI 线程（[线程模型](https://mygo.egoist.dev/docs/architecture)）。窗口可见性、输入许可与退出意图互不代替，顺序见第 5 节。`Hide`、`ShowInactive`、`OnClose`、`OnBeforeQuit` 与托盘是可用基础，但不激活窗口不保证不遮挡游戏。[窗口](https://mygo.egoist.dev/docs/windows) · [应用生命周期](https://mygo.egoist.dev/docs/app) · [托盘](https://mygo.egoist.dev/docs/menus#tray-icons)

重复启动使用 `RequestSingleInstanceLock` 与 `OnSecondInstance` 复用窗口，第二实例通知仍经过第 5 节的“先停止再恢复”入口。v0.6.2 在监听出现非地址占用错误或五次重试耗尽时仍返回 true，开发版锁标识另加 `.dev`，因此框架返回值不能证明本进程独占游戏输入；跨进程占用由第 5 节单独约束。[单实例实现](https://github.com/egoist/mygo/blob/cf26587264f26ea68bd1b8abbf5c9723f35e0a70/single_instance.go)

### 浏览器唤起桌面应用

用户确认通过网页唤起已安装的桌面应用（2026-10-16）；注册依据见 [T1](t1-mygo-ui-distribution.md#浏览器唤起的新增需求与构建依据)。首版只提供打开主窗口的深链接，拟定为 `youkai://open`，经 MyGo 的 URL 接收能力接入同一应用服务，不增加本地 HTTP 服务或浏览器扩展。只解析已支持的 scheme 和路由；链接不启动扫描、不执行命令、不接收本地路径或上传地址。

- 应用未运行时启动并在初始化完成后处理请求；已运行时交给现有实例并恢复主窗口。连续点击合并，启动期间的请求不能丢失。
- 准备或采集中收到请求，先关闭输入许可并进入统一停止，再显示收尾状态；正常收尾中只显示进度，不取消剩余识别。
- 退出中收到的链接不撤销退出。浏览器的外部应用确认按实际行为处理，不承诺静默启动；普通深链接没有回执，网页不能据此判断安装或打开成功。

## 3. 最小合理边界

```text
MyGo UI
   |
应用服务（组装、资源路径、保存、退出）
   |                 |
扫描会话内核       ZZZ 结果与导出
   |
   +-- 游戏适配器：ZZZ 页面、遍历、就绪判定、字段语义
   |       |                  |
   |    平台能力           识别能力
   |    窗口/截图/输入      模型/推理/解码
   |
   +-- 有界任务、结果记账、状态、取消
```

箭头表示调用或组装关系；平台和识别实现不反向依赖 MyGo 或 ZZZ，均在同一模块内以普通包维护。

| 边界 | 首版职责 | 不承担 |
| --- | --- | --- |
| 扫描内核 | 单会话互斥、取消、采集序号、有界队列、错误和未处理项记账、终态封存。 | 驱动盘字段、游戏坐标、翻页与遍历完整性判断。 |
| 平台实现 | 目标窗口身份、前台与权限、几何与单位转换、截图、短输入投递和原生资源释放。 | 判断页面内容、决定翻页策略、把“已投递”当作游戏动作成功。 |
| 游戏适配器 | 页面前提、过滤范围、布局锚点、选中与详情就绪、遍历与终止证据、ROI、字段语义。 | 调用 MyGo、决定退出、另维护一套并发状态。 |
| 识别实现 | 模型资源、预处理、推理、CTC 解码、原始文本与分数。 | 把相近名称或合法数值直接判为正确。 |
| MyGo 应用层 | 组合模块、交互状态、校对、导出、资源加载和进程生命周期。 | 在按钮回调里操作游戏，或依赖页面存储唯一结果。 |

首版使用明确的 ZZZ 驱动盘结果类型，不提前压成通用键值字典；接入第二款游戏时再决定公共容器。

唯一输入控制者串行执行“选择 → 验证选择 → 等待就绪 → 采集”，采集与 OCR 可以重叠，OCR 不操作游戏。先用一个识别工作者和小型有界队列；增加并发须同时限制 ORT 内部线程。队列只存所需裁剪和元数据：1920×1080 RGBA 单帧约 7.9 MiB，48 帧约 380 MiB。下一件选择前先取得处理容量，队列满时等待，不继续点击、丢弃任务或无限缓存；等待中仍响应取消和平台故障，恢复后重查目标与几何。

只处理明确故障：详情短暂未就绪可在截止时间内重新观察；动作效果不明时不重复点击或滚动；暂时无帧可有界等待，采集流失效则停止本次采集，不在重建后沿用旧位置；无法证实滚动位置时停止。首版不提供配置脚本、插件注册或用户可调的并发参数。

### 平台观测与内核的交接

平台细节见 [T2 第 3、4 节](t2-platform-capture-input.md#3-图像窗口与输入坐标)，公共约束如下。两平台底座之上由统一平台端口（`internal/platform`，PR 4a）承担会话语义：Preflight 与 Open、目标解析与观测、帧与有界输入、故障分类与停止序列都在端口层，内核与游戏适配器只面向端口，平台底座（`platform/macos`、`platform/windows`）只面向原生机制，不反向依赖端口。

- 图像、目标窗口和输入请求绑定同一会话、目标实例与几何版本；图像像素、屏幕物理像素、macOS 点和视频区域明确区分，旧版本坐标不得用于新输入。
- 区分本机采集时间、后端帧时间/状态和游戏动作证据，注明时钟域，缺失保持未知。平台不从重复图像推断断流或末页，T5 不把新帧当作动作已生效。
- 输入结果区分未派发、投递计数可知、投递结果未知和释放结果；只有 T5 能确认游戏状态，平台不自行重放。
- 采集后端的最新帧缓存与内核已接纳的证据任务分开管理，后者不能被后续帧覆盖；旧流回调和迟到任务不得写入新会话。
- 输入许可关闭、采集流停止、在途回调结束、OCR 返回和结果保存分别记录；窗口或权限故障直接触发统一停止，不等待 UI 或 OCR。

ZZZ 侧消费这些约束的遍历骨架（页面匹配契约、导航状态机与详情归属规则）位于 `internal/game/zzz/collect`：它只面向端口的值类型与自己的窄会话接口，布局锚点与像素匹配实现随 [T5](t5-zzz-inventory-traversal.md) 的标定接入（4b）。

## 4. OCR、原生资源与构建

推荐本地 CPU ONNX Runtime 加一个经过固定资源验证的识别模型。首轮组合为 yalue v1.36.0 + ORT 1.29.0 CPU + PP-OCRv6 small，版本、摘要、模型形状与字符表见 [T3](t3-ocr-runtime-model-samples.md#固定组合与制品静态核查)；Microsoft 官方 Go 包为替代，用同一运行库和资源比较。不选 GPU、Python 服务或自写 ORT FFI；实测确认 OCR 是瓶颈后再评估加速。

### 必须核对的集成点

1. **构建主机。** 接入 cgo 与平台原生接口后需要对应编译工具链；平台依赖按目标隔离，避免 Win32 依赖阻塞 macOS 构建。正式制品分别在 Windows 与 macOS 构建。
2. **初始化时机。** 包初始化不加载模型或探测游戏；应用就绪后安排后台预检或首次扫描时加载，就绪回调不做耗时工作。若缺库会阻止进程启动，由打包和安装诊断处理。
3. **运行依赖。** 固定绑定、C API 头文件、运行库、模型与字典的组合并记录摘要；Windows 还需 VC++ Runtime（[ORT 要求](https://onnxruntime.ai/docs/install/)），采用随应用放置的本地部署，见 T3。
4. **打包布局。** 模型、字典、许可放公共资源；原生库按系统和架构组织。用 `PathResources` 解析绝对路径交给识别实现，开发测试显式传入资源根，不依赖工作目录或全局 PATH。
5. **安装前提。** Windows 核对运行库前提和缺失时的安装路径；macOS 核对架构、最低系统、本地签名和其他机器上的加载。权限归 T2，打包与首次打开归 T7。
6. **释放顺序。** ORT 环境属于进程，模型会话与工作者有明确拥有者，张量与 RunOptions 在调用结束后释放。取消先触发终止，再等待运行退出；原生崩溃无法靠 `recover` 隔离。

模型与运行库随包提供（[T1 产品决定](t1-mygo-ui-distribution.md#已确认的产品选择)），本地 OCR 和导出不依赖网络；云游戏仍需联网。只有出现不可接受的原生崩溃或必须保证硬性终止时间，才把 OCR 移入同仓库辅助进程。

## 5. 扫描会话与结果语义

### 生命周期

状态顺序为：准备 → 采集 → 收尾 → 正常结束、取消或失败；没有活动会话时应用显示空闲。库存覆盖、字段质量和保存进度分别表达。

- 应用服务启动并拥有会话任务，生命周期不依附按钮回调、窗口或查询 context，创建时即占用活动位置。准备阶段完成独占、保存位置、权限、资源、停止方式、目标窗口与范围检查，输入许可初始关闭；等用户切回游戏且目标就绪后才进入采集。预检失败返回原因，不做试探点击。
- 扫描器可见性不是扫描状态。隐藏扫描器不取消会话；采集中游戏失焦、最小化、已知遮挡或身份歧义、权限撤回、几何或缩放改变、页面或筛选失效时，关闭输入许可并收尾。准备阶段尚未移交焦点不算失焦。
- 停止是单向的：游戏重获焦点、重新隐藏扫描器或权限恢复都不恢复输入。重新开始需完成上次收尾并重新预检，首版不承诺暂停续扫。
- 全局停止快捷键直接进入同一幂等停止入口，不依赖可见窗口；开始前验证可注册。每次只发短小输入，并在操作前核对窗口、坐标版本和许可；检查与 OS 接收之间的焦点竞争需测量，不承诺零误发。
- 取消先停止派发输入，再取消未完成识别：排队条目记为取消未处理；在途识别发出终止并等待返回，封存前返回的有效结果可为该条目接纳一次。清理由会话拥有者执行；释放扫描器自身按下的键鼠属于清理。
- 正常结束时排空任务，每个采集序号都得到成功、待校对、失败或取消未处理的结局；单条 OCR 失败不能卡住后续结果。
- 收尾完成后封存原始观测，不再接纳迟到写入；之后字段只能经人工修订改变，资料重校验单独记录。资源仍运行或结果未保存时禁止新会话和校对提交；原生推理未返回时显示“已停止操作，正在结束识别”，保存失败显示待保存并提供重试。

| 阶段 | 进入与离开条件 | 输入、查看与校对 |
| --- | --- | --- |
| 准备 | 服务已接纳开始；预检通过进入采集，取消或失败也先收尾。 | 禁止遍历输入，显示准备进度和停止方式。 |
| 采集 | 控制者按 T5 证据推进；范围结束、用户停止或故障转收尾。 | 每次短操作重查许可；恢复交互窗口先停止。 |
| 收尾 | 排空或终结任务，等待原生资源结束、逐项记账和最后保存。 | 禁止普通输入，可查看收尾状态；保存或清理失败停留此阶段。 |
| 已结束 | 所有观测有结局，资源已释放，结果已保存，记录终止原因。 | 可校对、导出或开始新会话，不续用上次导航位置。 |

停止通过 Go 取消机制通知采集与识别，但保存和清理有独立的收尾生命周期，不继承已取消的扫描 context；`CancelFunc` 不等待工作结束，需分别等待生产者、工作者与平台回调。[Go context](https://pkg.go.dev/context#CancelFunc)

保留首个停止触发及阶段，后续故障另记；用户取消不能掩盖随后的保存失败。单件文字歧义归待校对，单件识别错误归该条目；运行库失效、目标失效、导航失配或存储故障停止整个会话。超时只停止继续尝试，不承诺原生调用在期限内返回。

### 跨进程占用与观测接纳

跨进程保护分两个占用域，均使用可核验的 OS 排他原语：

- **数据根占用：** 应用启动后解析实际数据目录身份并取得占用，之后才读取设置、恢复检查点、打开历史或清理。路径别名归入同一占用域。占用持续到本进程全部文件操作结束后退出。同根第二实例能转交唤起请求时复用已有实例，否则显示占用错误并退出。
- **扫描占用：** 同一 OS 用户下只允许一个 youkai 进程操作游戏，开发版与正式版也共享此限制。进程在准备阶段取得、持有到收尾；其他数据根的进程仍可查看和编辑自己的历史。

先取数据根占用，再按需取扫描占用；获取失败或结果不明时拒绝操作。不把锁文件存在或超时当作可抢占依据，崩溃后的释放交给 OS 语义。T2 核对两平台原语，T4 负责持有与释放。数据根独占后，历史编辑、检查点写入和删除只需在应用服务内协调。

只有 [T5 的详情归属判断](t5-zzz-inventory-traversal.md#4-一件物品何时可以进入识别队列)确认截图属于当前目标、几何和选中物品后，内核才接纳观测、分配会话内单调序号并建立待处理记录。截图所有权须在平台复用原生缓冲前移交或复制。输入已投递但未取得可信详情时只保留导航失败证据，不虚构物品或增加计数；参照物截图不计数。

每个序号恰好得到一次原始处理结局。结果以会话和序号关联、按序号展示，但不要求按序完成；重复提交、旧会话回调和已终结条目的迟到结果不再改写数据。停止与结果并发时以服务接纳顺序判断；临界区内不做截图、推理、磁盘写入或 UI 调用。

原始处理状态为排队、运行、已产出、失败、未处理五类（未处理另记取消或中断原因）；字段质量独立为自动接受、待校对、人工确认或未评价。已采集数始终等于五类之和，封存后排队与运行为零。可用数量按当前字段完整性和校验结果计算。

| 隐藏后继续 | 保留进程和会话，停止方式继续有效；隐藏不授予后台、遮挡或最小化时输入的权限，进度不激活窗口。 |

| 设置为“关闭即停止并退出” | 点击关闭执行明确退出：停止输入、结束工作者、保存、释放资源后正常退出。该偏好可在设置中改回隐藏后继续。 |
| 恢复可交互主窗口 | 托盘、Dock、第二实例和深链接统一处理：准备或采集中先关闭输入许可并请求停止，再显示收尾进度，保存完成后开放校对。菜单可标为“停止扫描并打开”。正常收尾中打开窗口不取消剩余识别。 |

| 明确退出（菜单 / ⌘Q / 托盘退出） | 明确退出优先于隐藏偏好：停止输入、结束工作者、保存、释放资源后正常退出；重复退出连接同一收尾，不转成隐藏。不调用跳过退出事件的 `App.Exit`。 |
| 保存失败或原生调用未返回 | 保持进程和恢复入口，显示未完成项并允许重试，不清空结果、不释放在用原生对象、不谎报退出完成。强制结束只恢复已落盘部分。 |

`ShowInactive` 仍可能遮挡采集区域，首版不承诺边扫边交互。[DXGI AcquireNextFrame](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgioutputduplication-acquirenextframe) 的等待不可取消，若将来采用须使用有限等待；Go context 不会终止任意 Win32 或 C API。

### 完整性与身份

| 维度 | 语义 |
| --- | --- |
| 终止原因 | 正常结束 / 用户取消 / 故障，附首个触发与阶段；异常重开另标中断恢复。 |
| 覆盖范围 | 游戏、实体、语言、筛选条件和可见库存范围，作为分母。 |
| 覆盖结论 | 全部 / 部分 / 无法确认。由适配器提供遍历与结束依据，不按 OCR 成功数推断。 |
| 识别质量 | 每项自动接受、待校对、人工确认或未评价；OCR 分数不是校准概率。 |
| 计数 | 已访问、已采集、已处理、可用、待校对、未处理；已访问须有导航依据，总数未知保持未知。 |

全部覆盖需同时满足范围与起点、排序标签已验证、遍历连续、末端证据和可用的同范围总数，具体见 [T5](t5-zzz-inventory-traversal.md#5-滚动衔接重复物品与末尾)。排序标签未读取或未验证时，覆盖结论只能是部分或无法确认。容量上限或全品质数量不能当作 S 级总数；连续相同画面不能单独证明结束；检测到库存、筛选或排序变化即撤销完整结论。视觉扫描不提供数据库级原子快照。

每件观测用“会话 ID + 采集序号”标识并保留导航证据；属性完全相同的两件盘保留两个观测，相邻且详情完全相同的 S 盘也各算一件，属性哈希只作比较线索，不冒充跨会话游戏 ID。保留原始 OCR 文本、规范化前后值、问题、版本和裁剪；错误或歧义不静默改成某个合法值。管理状态用 `managementState` 的 `locked`、`discarded`、`none` 三态表达，未读到、不可读或证据冲突为 `null`，不转成 `none`；装备整体未读到时 `equipped=null`，未装备与已装备不能互换。

### 保存、校对与导出

首版采用用户数据目录中的会话文件与证据子目录，不增加数据库服务。持久化从扫描过程中开始；只保存声明区域的裁剪证据和必要上下文，不保存完整帧，内存中的图片和缩略图有界。开始前检查保存位置和空间，写入失败时停止采集。

| 保存内容 | 语义 |
| --- | --- |
| 会话外壳 | 格式版本、会话标识、客户端、范围、资源与适配器版本、起止时间、终止原因、覆盖证据及计数；按 [T5 的遍历账目规则](t5-zzz-inventory-traversal.md#6-保存什么证据怎样验收)保留访问位置、非 S 跳过和视口衔接。 |
| 物品观测 | 序号、导航与帧来源、证据标识、原始处理结局、原始结果与规范化字段、问题和质量状态。 |
| 证据 | 字段裁剪、详情上下文和遍历核验所需的裁剪图；不保存完整帧、常驻录像或事件服务。 |
| 人工修订 | 目标物品、物品修订号、修改前后值和确认；不修改原始观测与覆盖依据。 |
| 保存检查点 | 已写入的结果修订号、条目状态和证据引用；区分已保存与未保存内容。 |

界面快照修订号、物品修订号和持久化结果修订号分开使用。人工修改先校验再交串行写入者；保存局部修改与确认整件分开，见 [T6](t6-review-export-workflow.md#2-结果浏览与逐件校对)。人工修改不能把部分扫描改成全部覆盖。

检查点用有界批次写入，每次写新代次文件，完整写入、同步、关闭后才报告已保存，引用的证据须先落盘。保留当前与上一份有效代次。异常后只恢复最近可验证的检查点并标记中断：排队或运行条目转为中断未处理，覆盖不能升级为全部；没有有效检查点时显示无法恢复。断电与磁盘故障另作故障验收。非 Unix 平台的 `os.Rename` 不保证原子，因此采用新代次加保留旧文件；`File.Sync` 与关闭错误都要处理。[os.Rename](https://pkg.go.dev/os#Rename) · [Sync](https://pkg.go.dev/os#File.Sync)

访问账目、物品记录和计数来自同一检查点快照。取消、故障或中断时，已分配访问号但未接纳 S 级、也未确认非 S 跳过的访问转为 `unresolved`（无品质依据用 `unknown`，`sequence=null`）；已接纳的 `capturedS` 不变，只把其排队或运行任务标为中断未处理。访问与物品无法对账的检查点无效，回退上一代次。

导出读取已保存的固定修订；未保存修改先保存或显示阻塞原因。首版只导出可用数据 JSON 与 CSV，二者来自同一修订和同一批记录，都不含截图；不提供 ZIP、archive 视图或档案导入导出。可用数据带筛选方式、来源会话和排除数量，不标作完整库存，消费方不得据此删除未出现物品。文件用途与操作见 [T6](t6-review-export-workflow.md#3-保存重新查看与导出建议)，格式见 [JSON/CSV v2](scan-json-format.md)；外部工具接入有具体需求时再评估（用户 2026-10-16 确认）。

重开历史记录时按 [JSON 当前校验](scan-json-format.md#当前校验)重查当前数据，原始观测和人工修订不变；校验失败或不可用时阻止可用导出，旧确认不能绕过。校验变化增加持久化结果修订，不制造人工修改。

用户已确认导出规则（2026-10-16）：自动识别并通过全部必需检查的记录可直接导出，问题记录经校对确认后纳入，不强制逐件人工确认；导出前展示纳入、排除数量和覆盖结论。说明见 [T6](t6-review-export-workflow.md#导出前校对的已确认规则)。

### 本地目录、保留与清理

用户已确认（2026-10-20）：应用只保存裁剪证据，不保存完整帧；扫描完成且识别数据保存后，提示“保留截图 / 删除截图 / 稍后处理”。历史与截图默认保留，由用户主动清理，不静默删除。

| 用途 | Windows x64 | Apple Silicon macOS |
| --- | --- | --- |
| 持久数据 | `%LOCALAPPDATA%\Youkai\` | `~/Library/Application Support/Youkai/` |
| 可重建缓存 | `%LOCALAPPDATA%\Youkai\cache\` | `~/Library/Application Support/Youkai/cache/` |
| 诊断日志 | `%LOCALAPPDATA%\Youkai\logs\` | `~/Library/Logs/Youkai/` |

路径由平台目录 API 解析（Windows `FOLDERID_LocalAppData`，Mac 用框架目录接口），不拼接用户名。MyGo 的 Windows `PathUserData` 默认在 `%APPDATA%`，应用初始化时用 `App.SetPath` 显式配置数据、缓存与日志路径，使缓存清理只作用于 `cache` 子目录；原始证据不放缓存。开发与正式构建使用不同数据根，缓存和日志也分别命名；开发版继续使用 `Youkai Dev`。[Windows 标准目录](https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid) · [MyGo 目录接口](https://mygo.egoist.dev/docs/app#directories) · [Apple 文件存放](https://developer.apple.com/documentation/foundation/using-the-file-system-effectively)

```text
Youkai/
  youkai.lock
  settings.json
  sessions/
    <local-record-id>/
      checkpoints/
        <saved-revision>.json
      evidence/
        <evidence-id>.png
      resources/
        <resource-id>.json
```

- 每次扫描都有独立的本地记录标识，目录只用该标识；来源会话 ID 与序号按结果契约保留。
- `checkpoints` 保留当前与上一份有效代次；`resources` 保存本次采集配置等复核资料，模型与运行库留在安装资源目录。不做跨会话图片去重，删除一条记录不依赖引用计数。
- `evidence` 只存字段裁剪、详情上下文和遍历核验所需的有限裁剪，不存完整帧、常驻录像或可重放输入脚本。
- 缓存只含可重建的缩略图与索引；活动操作的暂存文件按操作占用，不当作闲置缓存。缓存有界淘汰，日志按大小轮转。
- 历史与截图不按天数或数量自动删除，升级和卸载不主动移除。空间不足时提示清理并阻止开始，不静默删除旧扫描。安装目录、工作目录和系统临时目录不存放持久历史。
- 导出的 JSON/CSV 是独立文件，应用清理不删除它们；导出目标不能位于应用管理的根目录内。首版提供“打开数据目录”，不做目录迁移。

清理约束（界面见 T6）：

1. 扫描完成且识别数据保存后，提示“保留截图 / 删除截图 / 稍后处理”。选择“删除截图”只移除该记录的裁剪证据，保留结果与修订，并在界面标注缺图；选择“稍后处理”不自动再次弹窗。
2. 历史每条记录提供“删除截图”和“删除当前记录”；设置提供“删除全部截图”和“删除全部记录”两个独立入口。删除截图保留记录与数据，删除记录移除结果、修订、证据和专属缓存。
3. 两类删除在执行前都显示涉及记录数、估计容量和待校对项，并要求明确确认；不静默删除，也不因曾经导出而跳过确认。外部导出的 JSON/CSV 不受清理影响。
4. 活动扫描、收尾保存和导出中的记录不可删除并显示原因；未保存编辑同样阻止删除。清缓存、清旧日志和删除历史分开。
5. 删除历史为确认后的“永久删除”，不清空回收站、不跟随记录中的任意路径、不触及安装资源。遍历不跟随符号链接或 junction。
6. 按本地记录取得独占删除权；删除前先持久化并验证删除标记，标记存在的记录显示为待完成清理。逐项删除后最后移除标记和目录；中断或部分失败保留标记与剩余内容，报告失败项供重试。
7. 预览容量为估计值，执行后按实际结果刷新；占用或权限失败如实报告，后台清理不阻塞 UI，也不抢占保存或导出。

## 6. 首版功能范围

以下范围均为用户确认的决定（2026-10-15 至 10-16），技术细节仍待实测：

- **平台与客户端：** Windows x64 支持《绝区零》完整客户端与官方《云·绝区零》Windows 客户端；Apple Silicon macOS 支持 App Store《云·绝区零》客户端。三种场景分别完成真实扫描闭环，Windows 两种客户端可共用平台能力，但入口身份、画面样本和遍历分别验证。见 [T2](t2-platform-capture-input.md#首版平台与客户端范围已确认)。
- **最低系统：** 用户不指定旧系统，按依赖和实测确定，见 [T7](t7-public-release-acceptance.md#4-依赖与最低系统的核对顺序)。
- **显示配置：** Windows 首版认证配置为 1920×1080（窗口/无边框模式），2560×1440 留后续版本；Mac 先支持一组合理且常用的尺寸；后续逐组扩展游戏内置尺寸。见 [T2 第 3.2 节](t2-platform-capture-input.md#32-可验收的窄显示配置候选)。
- **实体与语言：** 仅识别简体中文游戏界面；S 级驱动盘 1–6 号位、0–15 级、固定资料版本全部套装，已装备与未装备均覆盖。youkai 自身界面与说明也仅提供简体中文。稀有度是范围约束，不可改成 A/B；画面无法确认品质时保留异常证据。
- **管理状态：** `managementState` 与装备均按必需字段推进；管理状态只有 `locked`、`discarded`、`none` 三态，未读到、不可读或冲突为 `null`；装备整体未读到时为 `null`。读取路径与待验证项见 [T5](t5-zzz-inventory-traversal.md#4-一件物品何时可以进入识别队列)。
- **操作起点：** 用户手动打开驱动盘仓库并按提示完成筛选、排序和回顶，程序核验后自动遍历；首版不自动完成准备操作。见 [T5](t5-zzz-inventory-traversal.md#1-推荐路径与范围)。
- **完整操作链：** 检查仓库 → 确认范围与前台说明 → 注册停止方式 → 隐藏并让游戏获得焦点 → 扫描至范围结束 → 收尾保存 → 浏览全部结果、对照截图校对 → 导出 JSON/CSV 并能在本机重新打开历史。总数未知时不显示百分比。
- **异常闭环：** 不支持的布局在输入前拒绝；失焦、切页、滚动失配、取消和识别故障都能停止，保留已完成条目和原因并可导出部分结果；没有自动续扫。
- **交付形式：** Windows 安装包与 Mac DMG，随附模型、字典和运行库；无需开发环境即可安装；资源就绪后断网可对固定图片识别和导出。不走官方渠道、不以付费签名或公证为前提，见 [T7](t7-public-release-acceptance.md)。
- **自动更新：** 首版包含（2026-10-16 确认）。使用 MyGo v0.6.2 内置更新（[官方更新文档](https://github.com/egoist/mygo/blob/cf26587264f26ea68bd1b8abbf5c9723f35e0a70/docs/updates.md)），从 GitHub Releases（`LoTwT/youkai`）获取用 MyGo 更新密钥签名的版本；更新公钥自 0.0.1 起随包内置（晚加需用户手动重装一次），更新私钥由用户本人生成并保管在密码管理器与 GitHub Actions secrets，不进仓库。扫描进行中不安装更新，须收尾保存后再安装；测试版与正式版的更新渠道用 `updates.tagPrefix`（`test-v` / `v` 标签）分开，版本规则、发布 workflow 与发布后验证见[发布与自动更新](../release.md)。macOS ad-hoc 签名下更新后录屏/辅助功能权限可能需重新授予，须实测并写进说明。
- **浏览器入口：** 网页唤起桌面应用，按第 2 节验收；浏览器内界面只答复了可行性，不在首版范围。

首版不纳入：第二款游戏、后台遮挡扫描、多客户端并发、动态插件、GPU、云 OCR、自动库存删除同步和跨重启续扫。

“查看全部结果”指本次范围内的全部观测及处理状态，异常与未处理项不会消失。校对只修改扫描器记录，不操作游戏。证据、原始 OCR、序号、版本、终止原因和覆盖结论只读。

### 字段校验范围与资料来源

用户决定（2026-10-16）：校验规则从 fairy 取用所需部分，不整体搬运 fairy 资料；数值“识别到什么就是什么”，不建立逐等级数值表。词条行的解析规则由用户于 2026-10-18 定案，作为权威规则写在下方“词条行解析规则”，T3/T5 引用本节即可。

首版校验只覆盖以下内容。所需资料写成 `internal/game/zzz/` 中的 Go 资料表（套装与代理人的 fairy 数值 ID 和中文名，各词条中文名，各槽位允许的主词条类型与单位，十种副词条类型与单位），从 fairy 固定版本的公开资料（[消费契约](../../../fairy/docs/specs/data/consumption.md)、[驱动盘词条定义](../../../fairy/packages/data/definitions/attributes/drive-disc-affixes.json)）复制一次，文件头注明 fairy 版本、提交和取用日期。不做单独的 JSON 资源或生成脚本；游戏新增套装或代理人时对照 fairy 手动补充并递增表的修订号，更新变得频繁时再考虑脚本。套装与代理人直接使用 fairy 数值 ID（如河豚电音 `31100`、耀嘉音 `1311`），发布后不变。

- 套装与代理人名称能解析到资料中的 fairy 数值 ID；
- 槽位与主词条类型的合法组合，副词条属于十种类型之一且不重复；
- 词条类型与单位一致，等级在 0–15，副词条不超过四条；
- 数值为合法的十进制格式；
- 副词条强化档位在 0–5。

首版不按等级核对主副词条的具体数值，也不从数值推算强化次数；画面显示的强化档位本身按原始观测保存。fairy 当前词条定义标为 `enhancement: maximum`，只有满级数值，也不需要为此补齐。数值是否读对由 OCR 质量门槛与人工校对负责（[T3](t3-ocr-runtime-model-samples.md#4-三组样本与验收)）；读出的数值格式合法、字段完整且识别质量达标即可自动接受。资料中缺少某个套装或代理人时，该记录校验不可用并进入校对，不猜测。

**词条行解析规则（用户 2026-10-18 定案）：**

- **词条行拆分＝表驱动＋辅助规则。** 对行文本按内置词条名表做最长前缀匹配拆出名称，名称栏与数值栏之间有无空格不影响结果（识别模型不输出两栏间的空格）。名称后若紧跟 `+` 与一个 1–5 的数字，则为副词条强化档位（每 3 级触发一次副词条提升、+15 封顶共 5 次，档位只有一位数字）；`+0`、`+6` 等越界或 `+` 后无数字视为识别异常，保留原文与问题，不猜。其余部分为数值（非负十进制、可带小数），行尾 `%` 决定百分比单位。生命值/攻击力/防御力存在固定值与百分比两种同名词条，靠单位区分身份；单位与词条类型的合法性以资料表为准做交叉校验。拆不开或校验不符：保留原始文本与问题，不取最近合法值。
- **强化档位作为原始观测保存。** 副词条画面显示 `+N` 记 N，无 `+N` 记 0，行存在但未读出为 null；主词条无此字段。不做任何数值或强化次数推算（“不按等级核对具体数值”维持不变），以后若引入推算则标为派生值。

套装名行按 `套装名[N]`（半角括号）拆出套装名与槽位，等级行按 `等级N/15` 解析且分母须为 15；结构不符同样保留原文与问题。词条中文名以资料表为单一事实来源：生命值、攻击力、防御力、暴击率、暴击伤害、穿透值、穿透率、异常精通由 `internal/recognition/testdata` 的 6 盘样本实证；5 号位六种伤害加成与 6 号位三种属性（异常掌控、冲击力、能量自动回复）已于 2026-10-19 macOS 实测轮逐名核实（详情页与筛选面板双证据，见[M2 样本采集轮报告](../reports/2026-10-19-m2-macos-sample-round.md)）：物理与以太不带“属性”二字（物理伤害加成、以太伤害加成），火/冰/电/风为“X属性伤害加成”——首版按元素统一格式记录的“以太属性伤害加成”系误记，已随该轮修正。百分比主词条详情页不带“百分比”字样（如“攻击力 7.5%”），与固定值同名、仅靠 % 区分，与上述按单位拆分的规则一致。

与 fairy 只通过公开数据和导出文件衔接：不在 Go 程序中运行 Node，不导入私有 shared，不修改 fairy。Enka 的[接口文档](https://github.com/EnkaNetwork/API-docs/blob/88fc20697fda924430943434c11e0c45eb39509f/docs/zzz/api.md#equipment)可作字段交叉参考，但首版仍是可见画面扫描。

每个支持显示配置须记录系统与架构、客户端、窗口模式、内容区像素与逻辑尺寸、缩放、显示器布局、SDR/HDR、游戏语言与布局版本，云入口另记视频区域与画质。未知配置先拒绝；运行中的几何变化按第 5 节停止；不按比例换算宣布支持。

| 隐藏、恢复、停止与退出 | 在准备、采集、队列满和 OCR 运行中覆盖快捷键、隐藏、恢复、Dock/托盘、两种关窗模式、⌘Q、托盘失败和保存失败。候选目标：200 ms 内关闭新输入许可，通常 5 s 内完成收尾；记录各段时间，内部许可关闭不当作 OS 硬时限。 |
| 反复使用与性能 | 连续扫描/取消至少十轮，检查句柄与资源是否增长；注明 CPU、分辨率、游戏帧率，报告冷启动、每件耗时 p50/p95、总时长、CPU 与进程总内存。 |

平台候选为 Windows GDI 客户区裁剪 + SendInput、macOS ScreenCaptureKit 窗口流 + Quartz 输入，经薄层原生桥接接入 Go，依据见 [T2](t2-platform-capture-input.md)；每平台只选一种实现，不承诺遮挡或最小化后扫描。界面检查按 [T1 正式验收](t1-mygo-ui-distribution.md#正式功能的验收范围)执行。

## 8. 工作量、主要风险与改变结论的证据

假设一人全职、两平台实机与三种客户端持续可用、可标注样本、每种场景先验证一个显示配置，粗估 **40–70 个开发日（约 8–14 人周）**。这是任务分解判断，不是交期承诺；未含设备、云游戏时长和样本等待。范围变化后重算。

| 工作 | 粗估 | 成本来源 |
| --- | --- | --- |
| 双平台 MyGo / cgo / 安装资源贯通 | 4–7 日 | 两套编译环境、资源与原生库加载、安装制品。 |
| 平台窗口、采集与输入 | 7–12 日 | Windows 两种窗口身份与权限；macOS 点/像素映射、权限与原生桥接。 |
| 三种场景语料、OCR 与字段校验 | 8–14 日 | 两种云视频和完整客户端的样本、预处理、拒识与取消。 |
| 仓库遍历与会话控制 | 9–16 日 | 三种布局差异、滚动与末页、重复物品、云延迟与断流回归。 |
| 原生 UI、证据校对与导出 | 5–9 日 | 输入法、图片、托盘与退出、修订保存和导出。 |
| 双平台回归与分发收尾 | 7–12 日 | 两种安装制品、三种场景回归、权限变更和性能记录。 |

| 最脆弱假设 | 改变建议的证据 | 方案调整 |
| --- | --- | --- |
| 两平台画面可可靠采集，输入后的状态能被证实。 | 持续黑屏、云应用不响应输入、选中不可判、实际漏扫。 | 先调整采集、输入与导航；已确认场景仍不可行时报告阻塞并提出范围调整，不能自行取消 Mac 首发。 |
| 固定模型能保持低校对量。 | 独立验收集出现自动接受错误，或拒识率持续高于目标。 | 修正预处理、换模型或缩小布局范围，重估语料工作。 |
| 单进程原生推理稳定且可停止。 | 可复现崩溃、终止超时或持续泄漏。 | 先定位绑定与资源拥有权，仍不满足时隔离 OCR 进程。 |
| 原生 UI 以有限定制满足校对。 | 输入法、键盘校对或图片性能无法合理解决，或需大量自制控件。 | 先调整交互；仍不满足时向用户提出重新评估 UI，保留服务与内核边界。 |
| yalue 是低成本集成候选。 | 官方绑定完成同样的两平台验收且发布问题解决。 | 优先评估官方绑定；结果与游戏逻辑不因此重写。 |
| CPU 识别能跟上受控采集。 | OCR 持续占满队列且是总时长主因。 | 先调整裁剪、批处理和线程，再考虑 GPU；宁可降低采集速度。 |
| 未来游戏可沿用控制流和平台能力。 | 第二款游戏的交互无法自然表达。 | 保留平台与识别复用，修改最小公共生命周期。 |

替换 UI、截图或 OCR 实现不重写已保存结果：导出有独立版本，保留原始证据，不原地迁移用户库存。本地 OCR、校对与导出不需要 API key 或额外账户；游戏账户和云服务由用户现有客户端负责。
