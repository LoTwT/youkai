更新日期：2026-10-16。状态：分析草案，尚未批准应用实施。用户已在 T1 确认原生 UI、双平台首发及产品行为，在 T2 确认 Windows 完整/云客户端与 Mac 云客户端三种场景，并在主控确认首版仅识别简体中文，支持 S 级驱动盘的六个槽位、0 至 15 级、固定资料版本全部套装及已装备和未装备的盘。锁定状态必需；装备代理人与弃置标记按可行即纳入首版推进。首版显示适配采用有限配置，具体参数与识别效果仍待实测；框架、OCR 首轮候选及制品静态核查分别见 T1/T3，系统候选见 T7。应用与依赖实施仍按实际授权范围推进，本机 Go 更新记录见 T1。

初始用户目标、参考扫描器机制与最初授权见 [Handoff](../scanner-handoff.md)，后续澄清以本文引用的专项记录为准。本文维护后续评估、推荐边界和验收建议；不迁移参考扫描器，不改变 fairy 的职责。

## 推荐结论

MyGo + Go 值得继续验证。MyGo 可以承担应用窗口、交互与分发，Go 适合管理串行游戏操作、识别任务和资源生命周期。主要工程风险在窗口操作是否可靠、截图是否对应目标、OCR 是否可信，以及原生运行库能否随安装包正确运行；这些并不由桌面框架解决。

建议采用一个应用进程、一个活动扫描会话、内置游戏适配包和本地 CPU ONNX 推理。先以绝区零驱动盘形成完整的扫描、校对、导出闭环；第二款游戏出现后再提炼共同游戏接口。无需先做动态插件、通用工作流语言、独立扫描服务或可更换所有组件的框架。

界面已由用户确认采用 MyGo 原生 UI，主要动机是轻量；此前的 Web 推荐不再作为当前方向。用户已决定跳过单独的 UI 验证版，先确认待定产品选择，界面检查随正式功能验收。决定、能力依据与待确认项见 [T1](t1-mygo-ui-distribution.md#1-已确认选择与界面建议)。应用服务和扫描逻辑的边界不因这次 UI 选择改变，公共契约仍由主控收敛。

后续已确认的双平台首发、结果处理、关窗、分发与前台扫描方式见 [T1 产品决定](t1-mygo-ui-distribution.md#已确认的产品选择)，三种客户端场景以 [T2 支持范围](t2-platform-capture-input.md#首版平台与客户端范围已确认)为准。Windows x64 同时支持《绝区零》完整客户端与官方《云·绝区零》Windows 客户端；Apple Silicon macOS 支持 App Store《云·绝区零》客户端。用户接受游戏保持前台、完成或停止后再校对，使用时须告知。本文第 2、5 节集中维护应用与会话契约草案，第 6–8 节按三种场景整理范围、验收和成本；用户决定与设计建议分别标注。

最小产品替代方案是“导入截图 → 识别 → 校对 → 导出”的完整工具。它可以独立使用，但不满足自动扫描库存的目标。单件 OCR 演示只证明部分集成能力，不算自动扫描器首版交付。

## 2. 界面选择与应用层

当前采用已确认的 MyGo 原生 UI；轻量是选择动机，具体内存与体积预算尚未约定。界面建议使用结果列表、证据图和字段表单，支持筛选与“下一个待校对项”。中文输入、键盘操作、图片缩放、长列表与内存检查并入正式功能验收。Web 对照资料保留在 [T1](t1-mygo-ui-distribution.md)，TypeScript 绑定、页面重载、WebView 内部资源协议和 WebView2 不属于当前方案的必需项；浏览器唤起桌面应用的外部 URL scheme 按下方新增需求独立评估。

以下为主控汇入 T1 建议后的公共契约草案，不表示用户逐项批准了交互细节，也不表示已实现：

- 原生 UI 仅调用应用服务的开始、查询、停止、修订和导出能力；会话、结果和保存状态不属于窗口。应用服务同时拥有进程级资源及退出协调。窗口隐藏或重建不新建扫描会话。
- 每次明确的开始操作带进程内唯一请求标识；请求被服务接纳时即占用唯一活动位置并返回会话标识。同一请求重复到达时返回原会话，即使它已结束；另一请求在活动期间返回已有会话及忙碌状态，不能只禁用按钮。界面未收到开始结果时按该请求查询，不因没有活动会话就自动发起新扫描。应用重启只恢复保存结果，不重放开始请求。
- 状态快照是权威依据，通知仅表示已有变化；快照和通知带会话标识及递增修订号。界面订阅后重新取快照，丢弃旧会话与旧修订的更新；通知可合并，慢 UI 不阻塞采集、停止或保存。
- 进度只显示可证实的阶段与计数。后台进度和完成提示不自动激活主窗口，也不自动开始下一次扫描。
- 图片以会话内稳定证据标识关联，按需加载并限制解码缓存；原生视图直接使用图像，不为显示图片增加 Web 服务。结果保存与图像存储不接受 UI 任意拼接文件路径。
- 修订命令包含目标观测标识及该物品的期望修订号，服务校验后保存；其他物品或进度变化不制造编辑冲突，旧界面提交不得覆盖同一物品的新结果。保存失败保留待保存修改及上一份已保存结果，并阻止将失败状态显示为已保存。全量浏览包括失败、待校对和未处理条目；可修改字段见第 6 节。

所有 UI、菜单与关闭回调只安排异步工作，不等待采集或 OCR 结束；后台也不持有服务锁等待 UI 线程。官方[线程模型](https://mygo.egoist.dev/docs/architecture)是这一约束的框架依据。无需永久事件日志、独立服务进程或两套 UI。

窗口可见性、输入许可与退出意图互不代替，具体顺序统一由第 5 节维护。MyGo 的 `Hide`、`ShowInactive`、`OnClose`、`OnBeforeQuit` 与托盘接口是可用基础；其中不激活窗口并不保证不会遮挡游戏，框架接口存在也不等于扫描条件已满足。[窗口](https://mygo.egoist.dev/docs/windows) · [应用生命周期](https://mygo.egoist.dev/docs/app) · [托盘](https://mygo.egoist.dev/docs/menus#tray-icons)

重复启动应用优先使用 MyGo 的 `RequestSingleInstanceLock` 与 `OnSecondInstance` 复用窗口；第二实例通知不得直接调用官方示例中的聚焦逻辑，仍经过第 5 节的停止再恢复入口。已读 v0.5.1 在部分监听失败或重试耗尽时返回 true，且开发与正式标识可以使用不同锁，因此框架返回值不足以证明游戏输入已被本进程独占。跨进程扫描占用由第 5 节单独约束，不据此增加另一套窗口通信。[官方单实例接口](https://mygo.egoist.dev/docs/app#a-single-instance) · [固定实现](https://github.com/egoist/mygo/blob/408b4def1f3e6a8d3fac852396b4a46d82ba22a3/single_instance.go)

### 浏览器唤起桌面应用

2026-10-16 用户新增“支持浏览器打开 app”，随后明确选择网页唤起已安装的 youkai 桌面应用。原生 UI 选择继续有效；用户另问浏览器内界面是否可行，属于能力咨询，尚未要求纳入首版。产品要求、注册依据及两种路线的区别见 [T1](t1-mygo-ui-distribution.md#浏览器唤起的新增需求与构建依据)，本节统一入口行为。

建议首版只提供打开主窗口的深链接，示例为 `youkai://open`；这是拟定协议，尚未注册或发布。通过 MyGo 的 URL 接收能力接入同一应用服务，不增加本地 HTTP 服务或浏览器扩展。只解析已支持的 scheme 和打开路由；链接不直接启动扫描、不执行命令、不接收任意本地路径或结果上传地址。以后需要传入游戏选择或回传数据时，再按具体需求扩展协议。

- 应用未运行时启动原生应用，待初始化完成后处理打开请求；已经运行时交给现有实例，隐藏状态下恢复同一主窗口。连续点击合并为打开请求，不创建扫描会话；启动期间的请求也不能丢失。
- 准备或采集中收到打开请求，先关闭输入许可并进入统一停止，再显示收尾状态；不能直接使用聚焦回调绕过第 5 节。用户切到浏览器本身可能已经导致游戏失焦，后续唤起不能恢复这次扫描；若已在正常收尾，则只显示进度，不自动取消剩余识别。
- 正在退出时，新链接不撤销退出、不恢复输入；正常退出完成后用户可再次唤起。浏览器或系统的外部应用确认按其实际行为处理，不能承诺无提示或静默启动。
- 网页调用方可以提供安装说明及手动打开方式，但本次未指定接入网站，也未授权修改 fairy 或发布网页。没有回执的普通深链接不作为网页已确认安装或已成功打开的证据，不能只凭计时器到期断言用户未安装。

## 3. 最小合理边界

```text
MyGo UI
   |
应用服务（组装、资源路径、保存、退出）
   |                 |
扫描会话内核       ZZZ 结果与导出
   |
   +-- 游戏适配器：ZZZ 页面、遍历、就绪判定、字段语义
   |       |                  |
   |    平台能力           识别能力
   |    窗口/截图/输入      模型/推理/解码
   |
   +-- 有界任务、结果记账、状态、取消
```

箭头表示调用或组装关系；平台和识别实现不反向依赖 MyGo 或 ZZZ。它们可以在同一模块内以普通包维护，不需要独立仓库、独立版本或服务进程。

| 边界 | 首版拥有的职责 | 不应承担的职责 |
| --- | --- | --- |
| 扫描内核 | 单会话互斥、取消、采集序号、有界队列、错误和未处理项记账、终态封存。 | 驱动盘字段、游戏坐标、如何证明翻页成功、如何认定库存遍历完整。 |
| 平台实现 | 目标窗口身份、前台与权限状态、窗口和图像几何及单位转换、截图、短小输入投递和原生资源释放。 | 用某种颜色猜“这是驱动盘页面”；自行决定下一行或翻页策略；把输入已投递写成游戏动作成功。 |
| 游戏适配器 | 页面前提、过滤范围、布局锚点、选中目标与详情就绪、遍历和终止证据、ROI、字典与数值语义。 | 直接调用 MyGo、创建窗口、决定应用退出，或自己再维护一套并发扫描状态。 |
| 识别实现 | 模型资源、预处理执行、张量布局、推理、CTC 解码、原始文本与模型分数。 | 将相近名称或“看起来合法”的数值直接判为正确物品。布局和模型参数由适配器明确选择。 |
| MyGo 应用层 | 组合以上模块、交互状态、校对、文件导出、资源加载和进程级生命周期。 | 把游戏操作写进按钮处理函数，或依赖页面存储保存唯一结果。 |

内核只共享控制流、证据和结果状态。首版使用明确的 ZZZ 驱动盘结果类型；游戏特有字段归适配器，类型化应用接口保持该类型，不提前把所有游戏压成任意键值字典或万能 Item。真正接入第二款游戏时，再决定需要泛型结果容器还是少量公共接口。

首版唯一输入控制者串行执行“选择 → 验证选择 → 等待就绪 → 采集”。采集与 OCR 可以重叠，OCR 不操作游戏。先用一个识别工作者和小型有界队列验证；增加并发必须同时限制 ORT 内部线程，防止与游戏争抢 CPU。队列保存所需裁剪和元数据，避免长期保留全部全屏帧：1920×1080 RGBA 单帧约 7.9 MiB，48 帧约 380 MiB，尚未计算模型和 UI。参考项目的队列 48 / 工作者 2 不是这里的默认值。

下一件选择前先取得处理容量；队列满时等待容量，不继续点击、丢弃旧任务或增加无限缓存。等待过程仍接收取消和平台故障，容量恢复后重新检查目标与几何。采集证据的接纳、序号和终结记账统一见第 5 节，不由 OCR 工作者另行编号。

错误处理只覆盖明确故障：详情短暂未就绪可在截止时间内重新观察；已投递动作的效果不明时，不因此重复点击或滚动。暂时无帧可有界等待，明确的采集流失效则停止本次采集，后端重建留到下一次预检；不能重建后直接沿用旧位置继续。无法证实滚动位置时停止，不为了继续进度盲目翻页。首版无需配置脚本、插件注册中心或供用户调整的并发参数。

### 平台观测与内核的交接

主控将 T2 本轮结果汇入以下公共约束草案；后端 API、具体单位和字段依据引用 [T2 第 3、4 节](t2-platform-capture-input.md#3-图像窗口与输入坐标)，不在这里复制平台实现表：

- 图像、目标窗口和输入请求绑定同一会话、目标实例与几何版本；图像像素、屏幕物理像素、macOS 点及视频内容区域明确区分。旧版本坐标不得进入新的输入操作，T5 负责视频区域与页面布局依据。
- 区分本机采集时间、后端实际提供的帧时间/状态和游戏动作证据；时间注明时钟域，缺失信息保持未知。平台不从重复图像推断断流或末页，T5 不把收到新帧当作动作已经生效。
- 输入结果区分未派发、投递计数可知、投递结果未知及必要释放结果，只有 T5 能确认预期游戏状态。平台不自行重放不确定动作，也不以 API 无报错代替输入权限与实际效果检查。
- 采集后端的最新帧缓存与内核已接纳的证据任务分别管理；前者有界并可更新，后者的图像、序号与结果归属不能被下一帧覆盖。旧流回调和迟到任务不得写入新会话。
- 输入许可关闭、采集流已停止、在途回调已结束、OCR 返回及结果已保存分别记录。原生对象由所属实现释放；窗口/权限故障直接触发统一停止，不等待 UI 或 OCR 消费通知。平台桥接由 T2 负责，OCR 原生绑定由 T3 负责，两者的部署目标与资源组合交 T1/T7 共同验收。

## 4. OCR、原生资源与构建

本节维护公共集成要求；库加载细节、模型配套资料与三组语料方案见 [T3 专项评估](t3-ocr-runtime-model-samples.md)。T3 已固定首轮验证候选并完成部分静态制品核查，尚未动态加载或运行识别，未成为经过验收的生产依赖。

### 候选路线

推荐本地 CPU ONNX Runtime，加一个经过固定资源验证的识别模型。根据 [T3 的公开评测复核](t3-ocr-runtime-model-samples.md#公开模型评测与候选顺序)，优先验证 PP-OCRv6 small，保留 tiny 的轻量对照与 PP-OCRv5 基准；这不是已选定依赖。模型文件、字典顺序、输入大小、颜色通道、归一化、缩放补边和 CTC blank 都需要核对。调用同一个 ONNX 文件不等于复现参考实现的 OCR。

首轮使用 yalue 与其对应的 ORT CPU 路径，具体版本、制品摘要、模型形状和字符表统一见 [T3 固定组合](t3-ocr-runtime-model-samples.md#固定组合与制品静态核查)。Windows DLL 依赖与 Mac arm64 库的系统标记已静态核对，实际加载、取消、分发和三组样本仍须验收。Microsoft 官方 Go 包保留为替代，先用同一运行库与资源比较其 context 集成；不能单凭缺少子模块标签或源码所在发行版号判不适用。

两者都需要 cgo 与原生运行库。先不选择 GPU、Python 服务或自行编写完整 ORT FFI：尚无证据表明 CPU 达不到目标，而这些路线会增加运行前提或维护面。若实测性能瓶颈确在 OCR，再评估更多工作者、模型优化或执行提供器。

### 必须核对的集成点

1. **构建主机与目标主机。** 当前原生路线不配置 Web 绑定生成；接入 cgo OCR 与平台原生接口后，开发和打包仍需要对应编译工具链。平台依赖按目标隔离，避免包级 Win32 依赖阻塞 macOS 构建。正式制品建议分别在 Windows 与 macOS 构建；macOS 首发必须完成云游戏扫描，不能以仅能开窗口或暂不支持采集的实现交付。
2. **初始化时机。** 包初始化不加载模型或探测游戏；应用就绪后安排后台预检或首次扫描时加载，错误应可呈现，就绪回调本身不做耗时工作。T3 需核对所选绑定是启动时链接加载还是显式加载原生库：若缺库会直接阻止进程启动，就需通过完整打包和安装诊断处理，不能承诺所有缺库错误都能在 UI 内显示。Web 生成模式与 `App.Run` 返回的注意点仅作为 [T1 路线对照](t1-mygo-ui-distribution.md#web-与原生-ui-的构建差别)，不保留为原生首版的额外验收门槛。
3. **运行依赖。** 固定绑定、头文件/C API、运行库、模型与字典的可验证组合；记录版本与摘要。支持 C API 向后兼容的绑定不要求所有版本号字面相同，但必须通过组合验收。[ORT 官方要求](https://onnxruntime.ai/docs/install/)还列出 Windows VC++ Runtime，不能只检查 `onnxruntime.dll` 是否存在。
4. **打包布局。** 公共资源放模型、字典与许可文件；原生运行库及确实需要的依赖按目标系统和 CPU 架构分别组织，不能只准备 Windows DLL。用 `PathResources` 解析应用资源后，将绝对路径交给识别实现；数据和证据写用户数据目录。开发测试显式传入资源根，不依赖当前工作目录或全局 PATH 恰好有另一份 ORT。
5. **安装前提。** Windows 核对所选运行库的系统前提及缺失时的安装路径；macOS 核对应用与内置原生库的架构、最低系统、本地代码签名及其他机器上的加载行为。录屏和输入相关权限归 T2，当前无需付费证书的打包路线、首次打开与完整离线首装归 T1/T7，均不能由框架能够生成安装包推导为已经解决。当前原生界面不依赖 WebView2；随包提供识别资源不代表系统前提也已全部满足。
6. **释放顺序。** ORT 环境属于进程，模型会话与工作者有明确拥有者，张量/RunOptions 在调用结束后释放。取消先触发终止信号，再等待运行退出；不能并发销毁正在使用的 tensor/session。原生调用不响应或崩溃无法靠 Go `recover` 可靠隔离。

用户已确认 Windows 安装包、macOS DMG，模型与识别运行库随包提供，详见 [T1 产品决定](t1-mygo-ui-distribution.md#已确认的产品选择)。本地 OCR 和导出可以设计为不依赖网络；云游戏仍需要联网，完整离线首装还需核对系统运行前提。

若发现不可接受的原生崩溃或必须保证硬性终止时间，才将 OCR 移入同仓库的辅助进程，并使用有限 IPC。它能隔离故障，但会增加进程管理、协议和打包成本；仅为保留纯 Go 构建表象而引入辅助进程没有收益。

## 5. 扫描会话与结果语义

### 生命周期

2026-10-16，主控接续 T4 并补齐以下契约草案。它承接已确认的前台扫描、结束后校对及两种关窗模式，不是已实施的接口，也不把用户对上一轮 OCR 方向的认可扩大为逐项批准本节细节。状态顺序为：准备 → 采集 → 收尾 → 正常结束、取消或失败；应用没有活动会话时显示空闲，空闲不属于某次会话。库存覆盖、字段质量和保存进度分别表达。

- 应用服务启动并拥有会话任务，生命周期不依附按钮回调、窗口或单次查询的 context；创建时立即占用活动会话位置。准备阶段完成独占、保存位置、权限、资源、停止方式、目标窗口与范围检查，输入许可初始关闭；按下方开始流程等待用户切回游戏，确认目标就绪后才进入采集。预检失败返回明确原因，不执行试探性的游戏点击。
- 扫描器可见性不是扫描状态。隐藏或最小化扫描器本身不取消会话；采集阶段发生游戏失焦、目标窗口最小化、已知遮挡或身份歧义、权限撤回、窗口移动/尺寸或缩放改变、页面或筛选条件失效时关闭输入许可并收尾。准备阶段尚未移交焦点不当作采集中失焦；准备条件仍须在开启输入前全部满足。T2 检查平台条件，T5 检查游戏内容；云流的新帧时间不能单独证明游戏已经响应输入。
- 停止是单向过程，不因游戏重新获得焦点、重新隐藏扫描器或权限恢复而恢复输入。重新开始需要完成上次收尾并重新预检，首版不承诺暂停续扫。完整覆盖仅按游戏证据判断，提前停止通常为部分结果。
- 全局停止快捷键直接进入同一个幂等停止入口，不依赖可见窗口，也不等待 OCR 或图片编码。开始前验证快捷键可注册；每次只发短小输入操作，并在操作前核对窗口、坐标版本和输入许可。检查与 OS 接收之间仍可能发生焦点变化，必须测量这种竞争，不能承诺绝对零误发；已经交给 OS 的事件不可撤回。
- 取消首先停止派发新输入，再取消未完成识别。排队但未运行的条目记为取消未处理；在途识别发出终止请求并等待实际返回，若在封存前仍返回有效结果，可为尚未终结的该条目接纳一次。保留已确认结果和未处理条目的已有证据；清理由会话拥有者执行，不能等待 UI 订阅方消费消息。释放扫描器自己按下的按键/鼠标属于清理，不能撤回已经进入 OS 的事件。
- 正常采集结束时排空已接收任务。每个采集序号都必须得到成功、待校对、失败或取消未处理的结局；某条 OCR 失败不能使后续结果永远卡在排序缓冲中。
- 收尾完成后封存原始观测，不接纳晚到的旧工作者写入；之后字段只通过明确的人工修订改变，资料重校验独立记录。资源仍在运行或结果尚未成功保存时禁止新会话和校对提交。若原生推理未返回，显示“已停止操作，正在结束识别”；保存失败显示待保存，提供重试并保留内存结果及上一份已保存文件，不虚报完成。

| 阶段 | 进入与离开条件 | 输入、查看与校对 |
| --- | --- | --- |
| 准备 | 服务已接纳开始；预检通过后进入采集，取消或失败也先收尾。 | 禁止仓库遍历输入，显示准备进度和停止方式。 |
| 采集 | 唯一控制者按 T5 的页面与详情证据推进；范围结束、用户停止或故障均转收尾。 | 每次短操作重新检查许可；进度只读，恢复交互窗口先停止。 |
| 收尾 | 正常结束排空队列，取消或故障终结未处理任务；等待原生资源结束、逐项记账及最后保存。 | 禁止新普通输入，允许查看收尾状态；保存或清理失败仍停留此阶段并显示原因。 |
| 已结束 | 所有接纳观测都有结局，扫描资源已释放且最终结果已保存；记录正常、取消或失败原因。 | 可校对、导出或明确开始新会话；不续用上次导航位置。 |

停止请求使用 Go 的取消机制通知采集与识别，但保存和清理有应用服务管理的独立收尾生命周期，不能直接继承已取消的扫描 context。`CancelFunc` 只发出停止信号，不等待工作结束，仍需分别等待生产者、工作者与平台回调结束。[Go context 说明](https://pkg.go.dev/context#CancelFunc) 不因切出 UI、取消查询或关闭订阅就取消扫描或保存，也不丢弃仍运行的 goroutine 来宣称收尾完成。

首个停止触发及发生阶段保留，后续故障另行记录；用户取消不能掩盖紧随其后的保存失败。单件文字歧义归待校对，单件识别错误归该条目，仍可继续其他物品；原生运行库失效、目标失效、导航失配或存储故障则停止整个会话。超时用于停止继续尝试并报告原因，不承诺原生调用必然在期限内返回。

### 跨进程占用与观测接纳

应用内唯一会话之外，跨进程保护分为两个占用域，均采用可核验的 OS 排他原语：

- **持久数据根占用：**应用启动时，解析实际数据目录身份并取得占用，之后才读取设置、恢复检查点、打开历史或执行清理；必要的建目录与取锁除外。同一实际目录的路径别名必须归入同一占用域，不能只按未经规范化的路径字符串区分。占用持续到本进程全部保存、导入、导出及清理结束后退出，空闲时也不释放。同根第二实例不打开历史或执行文件操作；能转交唤起请求时复用已有实例，否则显示占用或初始化错误并退出。
- **扫描占用：**同一操作系统用户下，同一 youkai 扫描占用域只允许一个进程操作游戏，开发版和正式版也不例外。已拥有各自数据根的进程在准备阶段取得扫描占用，持有到会话收尾；其他数据根的进程仍可查看和编辑自己的历史，但不能开放游戏输入。

固定顺序为先取得数据根占用，再按需取得扫描占用；获取失败或结果不明时拒绝相应操作。不将“锁文件存在”或等待超时当作可抢占依据，不删除其他进程正在持有的锁对象；崩溃后的拥有权由 OS 释放语义处理。T2 负责核对两平台原语，T4 负责持有与释放。数据根独占使历史编辑、检查点写入和删除只需在拥有它的应用服务内协调，不另建跨进程记录锁或共享存储服务。

MyGo 单实例功能继续承担窗口复用，不代替上述占用。固定 v0.5.5 的监听失败路径仍可能返回成功，故即使框架允许启动，也必须通过数据根占用后才能访问历史。[固定实现](https://github.com/egoist/mygo/blob/4d8673cd2658a2c6e86b26c44751e57bf8174f91/single_instance.go) 这些是契约修订，尚未实现或在多进程中验证。

只有 [T5 的详情归属判断](t5-zzz-inventory-traversal.md#4-一件物品何时可以进入识别队列)确认截图属于当前目标、当前几何和选中物品后，内核才接纳一项物品观测并分配会话内单调序号；接纳同时建立待处理记录，再送识别。截图所有权移交或复制必须在平台复用原生缓冲之前完成。输入已投递但未取得可信详情时只保留导航失败证据，不能虚构一件物品或增加已采集计数；用于选择核对的参照物截图也不重复计数。

每个已接纳序号恰好得到一次原始处理结局。结果以会话和序号关联，按序号展示，但不要求早序号成功后才能接纳后面的结果。重复提交、旧会话回调和已终结条目的迟到结果不再改写数据；人工修订是另一类明确操作。停止与结果并发时以服务接纳顺序判断，不以两个 goroutine 的墙钟时间猜先后；临界区内不做截图、推理、磁盘写入或 UI 调用。

原始处理状态采用排队、运行、已产出、失败、未处理五类，未处理另记取消或中断原因；字段质量独立采用自动接受、待校对、人工确认或未评价。已产出可以包含待校对字段，失败条目经人工补录后也保留原始失败来源。任一时刻，已采集数等于五类原始处理状态之和；封存后排队与运行均为零。可用数量只按当前字段完整性和校验结果计算，不能把“已经处理”直接显示成“全部正确”。

### 隐藏、恢复与退出

| 入口或事件 | 主控建议的公共行为 |
| --- | --- |
| 开始扫描 / 开始并隐藏 | 开始前显示前台限制、已注册停止方式及“请在 30 秒内切回目标游戏”的提示；先完成不依赖前台的预检，选择隐藏时再确认托盘/菜单栏入口并隐藏。首版等待用户切回游戏，不调用强制激活；从进入该等待开始计时，30 秒内前台、页面、范围和几何全部核验通过才开启输入。到期仍未就绪则以准备超时收尾，保存后显示原因；倒计时本身不授权输入。这是初始交互预算，随正式功能验收核对。 |
| 隐藏后继续 | 保留应用进程和同一会话，停止方式继续有效；隐藏不授予游戏后台、被遮挡或最小化时继续输入的权限。进度只更新状态，不调用激活窗口的操作。 |
| 首次关主窗口 | 建议选择停止并保存退出或隐藏后继续，提供记住选择；设置中可修改，取消选择则保持窗口。弹出选择前若仍在采集，先请求停止；选择隐藏也不撤销已发生的停止。为连续采集而隐藏应优先使用开始并隐藏入口。 |
| 已选择隐藏模式时关窗 | 仅隐藏窗口；若用户先点击扫描器导致游戏已失焦，仍按失焦停止，不能因随后隐藏而自动恢复。托盘不可用时不隐藏唯一入口，停止采集后展示原因。 |
| 恢复可交互主窗口 | 托盘“打开主窗口”、Dock 激活、第二实例通知及浏览器深链接等入口统一处理：若处于准备或采集，先关闭输入许可并请求停止，再显示收尾进度，待收尾保存完成后开放校对。可在扫描期间将菜单标为“停止扫描并打开”；恢复只查询现有会话，不能重复开始。系统已先激活应用时由失焦保护兜底。已在正常收尾时打开窗口不自动取消剩余识别。 |
| 停止按钮 / 全局快捷键 / 托盘停止 | 幂等请求停止；允许不显示主窗口，保留结果和会话供之后查看。托盘菜单交互若使游戏失焦，也不能免除停止。 |
| 关窗选择退出 / 菜单退出 / macOS ⌘Q | 明确退出优先于隐藏偏好：停止输入、结束工作者、保存、释放资源，再正常退出。重复退出只连接同一收尾，退出期间的关闭回调不得转成隐藏。 |
| 保存失败或原生调用尚未返回 | 保持进程和可恢复的界面入口，显示具体未完成项并允许重试保存；不清空结果、不释放仍在使用的原生对象、不谎报退出完成。系统强制结束只恢复已落盘部分。 |

恢复交互窗口会结束本次采集，是基于已确认前台限制的设计建议，不额外引入透明悬浮窗或自动暂停恢复。`ShowInactive` 虽有官方支持，仍可能遮挡采集区域，因此首版不以它承诺边扫边交互。正常隐藏应拦截关闭并隐藏仍存活的主窗；关闭与退出事件统一接入上述异步收尾，不调用跳过事件的 `App.Exit`。相关官方依据见第 2 节，实际回调与平台焦点顺序仍需实机验收。

[DXGI 的 AcquireNextFrame](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgioutputduplication-acquirenextframe)的等待不能取消，因此若采用 DXGI，必须使用有限等待并检查取消，处理访问丢失与帧释放。Go context 本身不会终止任意 Win32 或 C API。

### 完整性与身份

| 维度 | 候选语义 |
| --- | --- |
| 终止原因 | 正常结束 / 用户取消 / 故障，附最初触发、阶段和后续问题；异常重开另标中断恢复。 |
| 覆盖范围 | 指定游戏、实体、语言、筛选条件和可见库存范围；以该范围为分母。 |
| 覆盖结论 | 全部 / 部分 / 无法确认。由游戏适配器提供遍历与结束依据，内核记录，不根据 OCR 成功数猜测。 |
| 识别质量 | 每项自动接受、待校对、已人工确认或未评价；OCR 分数是模型输出，不是已经校准的正确概率。 |
| 计数 | 已访问、已采集、已处理、可用、待校对、未处理；定义与原始处理状态对应。已访问须有导航依据，不以点击次数代替。总数未知保持未知。 |

全部覆盖需要同时检查范围与起点、遍历连续性、滚动/末页证据和可用的同范围总数信息，具体游戏证据见 [T5](t5-zzz-inventory-traversal.md#5-滚动衔接重复物品与末尾)。容量上限或全品质库存数不能直接当作 S 级筛选结果数。连续画面相同既可能是到达底部，也可能是两件相同物品，不能单独证明结束。扫描期间应保持库存、筛选与排序不变；若检测到变化，撤销完整覆盖结论。视觉扫描无法提供游戏数据库级原子快照。

每件观测用“会话 ID + 采集序号”标识，保留页面/格位等导航证据。两个属性完全相同的驱动盘必须保留两个观测；属性哈希只适合作为比较线索。该标识不冒充跨会话稳定的游戏实例 ID，跨次库存合并是消费方另行定义的问题。

保留原始 OCR 文本、规范化前后值、校验问题、模型/字典/适配器版本及对应裁剪。错误或歧义不静默修正为某个合法值。人工校对增加修订记录，原始结果仍可回看。字段范围由第 6 节维护；未知锁定、弃置或装备者按其实际原因保存，不转换为否定状态。

### 保存、校对与导出

首版采用用户数据目录中的会话文件与证据子目录，不增加数据库服务。持久化从扫描过程中开始，不能等用户点击导出才保存。用户已确认历史和截图默认保存在本机、由用户手动清理，并要求合理目录与清理功能；具体设计见下方[本地目录、保留与清理](#本地目录保留与清理)。证据随会话保留，不自动淘汰待校对依据；内存中的图片、待写证据与缩略图均有界。开始前检查保存位置和空间，写入失败时停止采集，不继续声称证据已保存。

| 保存内容 | 需要保留的语义 |
| --- | --- |
| 会话外壳 | 格式版本、会话标识、客户端与游戏、范围、资源/适配器版本、开始与结束、终止原因、覆盖证据及计数；按 [JSON 遍历账目](scan-json-format.md#遍历账目)保留已访问位置、非 S 跳过项和视口衔接，不只保存已接纳 S 级的详情。 |
| 物品观测 | 会话内序号、导航与帧来源、证据标识、原始处理结局、文字/图标原始结果及规范化字段、问题和质量状态。 |
| 人工修订 | 目标物品、该物品修订号、修改前后值及人工确认；保留原始观测，不修改扫描覆盖依据。 |
| 保存检查点 | 已确认写入的结果修订号、条目状态和证据引用；未保存内容与已保存内容明确区分。 |

界面快照修订号、物品修订号和持久化结果修订号分开使用。进度通知变化不制造字段冲突；保存完成某个较旧修订时，不将之后的修改误标为已保存。人工修改先校验，再交串行写入者保存；失败保留待保存修改和上一份有效结果。T6 建议将保存局部修改与确认整件分开：保存后仍有未知或未完成整件核对时保持待校对；全部必需字段完整、校验通过并经用户确认后才记录整件人工确认。人工修改不能把部分扫描改成全部覆盖，具体操作见 [T6](t6-review-export-workflow.md#2-结果浏览与逐件校对)。

建议用有界批次写证据并保存结果检查点，避免每识别一行就重写全部会话。新检查点使用新的代次文件，完整写入、同步和关闭后才报告该修订已保存；它引用的证据必须先写入并可校验。保留当前与上一份有效检查点，新代次无效时仍可读取旧代次，不原地截断唯一副本。普通进程异常后只恢复最近可验证的检查点，标记中断；排队或运行条目转为中断未处理，未知覆盖不能升级为全部。没有有效检查点时显示无法恢复，不凭残留截图拼出完整会话。断电、磁盘故障及文件系统持久性另作故障验收，不承诺未落盘数据可恢复。

访问账目、已接纳物品记录及相关计数必须来自同一检查点快照。取消、故障收尾或中断恢复时，已分配访问号但尚未接纳 S 级、也未确认非 S 跳过的进行中访问转为 `unresolved`；保留已知品质，无品质依据时用 `unknown`，`sequence=null`，并记录停止原因，中断恢复使用 `interrupted` 事件。不增加访问号或虚构物品，覆盖不能为全部。已经接纳的 `capturedS` 保持不变；中断恢复时只将其中排队或运行的识别任务标为中断未处理，不能将已接纳物品降成未采集。访问与物品无法对账的检查点无效，应回退上一有效代次，不通过删除记录凑齐计数。

Go 官方明确说明非 Unix 平台的 `os.Rename` 不保证原子操作，不能把“临时文件改名”当成 Windows 上绝不损坏的证明；采用新代次并保留旧有效文件是本方案的理由。`File.Sync` 的结果及关闭错误仍需处理。检查点批次和间隔由真实写入负载定，不作为首版用户调优选项；存储落后时限制采集速度。[Go 文件操作说明](https://pkg.go.dev/os#Rename) · [Sync](https://pkg.go.dev/os#File.Sync)

导出读取一个已保存的固定结果修订，带版本的公共外壳加明确的 ZZZ 驱动盘载荷；未保存修改先保存或显示阻塞原因，不能悄悄导出旧值。完整会话导出保留失败、待校对和未处理项；仅可用项导出带筛选方式、来源会话和排除数量，不能标作完整库存，消费方不得据此删除未出现物品。数量未知用未知表达。若导出包含可回看的图片引用，配套证据须一并交付且使用相对引用；单独的数据 JSON 不声称包含证据。T6 负责文件选择与展示，导出目标写入失败不改变内部已保存会话。

[T6 的文件方案](t6-review-export-workflow.md#3-保存重新查看与导出建议)采用含截图的 ZIP 档案与仅可用记录的 JSON 两种用途，并支持打开本应用档案为独立本地副本；保留来源标识与修订，不覆盖已有会话或跨次合并。用户于 2026-10-16 明确选择先做 youkai 自有 JSON，外部接入等具体需求出现后评估。[JSON v1 契约](scan-json-format.md)集中定义两种视图、精确数值与单位、未知状态、修订和证据引用；这是文件设计，尚未实现或通过往返验收。

重开或导入时，按 [JSON 当前校验契约](scan-json-format.md#当前校验与导入)重新检查当前数据，原始观测和人工修订保持原样。校验结果与所用资料独立保存；资料不足或出现冲突时阻止可用导出，并展示原因，旧人工确认不能绕过当前检查。校验变化增加持久化结果修订，不凭空制造一次人工修改或确认。

2026-10-16 用户在解释后确认按推荐的校对方案推进：自动识别并通过全部必需检查的记录可直接导出，异常或不确定记录经校对确认后再纳入，不强制全盘逐件人工确认。导出前展示纳入、排除数量及扫描覆盖结论；全部已采集观测和截图仍保存在本机及完整档案中。自动接受只是通过当前识别和校验门槛，不等于客观零错误；用户可主动检查任意记录。说明与示例见 [T6](t6-review-export-workflow.md#导出前校对的已确认规则)。

### 本地目录、保留与清理

2026-10-16 用户确认默认保留历史与证据截图、主动清理，并要求设计存放目录和清理入口。以下为主控据此制定的方案，尚未创建目录、实现文件操作或删除数据。

| 用途 | Windows x64 的建议位置 | Apple Silicon macOS 的建议位置 |
| --- | --- | --- |
| 持久数据 | `%LOCALAPPDATA%\Youkai\` | `~/Library/Application Support/Youkai/` |
| 可重建缓存 | `%LOCALAPPDATA%\Youkai\cache\` | `~/Library/Caches/Youkai/` |
| 诊断日志 | `%LOCALAPPDATA%\Youkai\logs\` | `~/Library/Logs/Youkai/` |

路径由平台目录 API 解析，表中的变量是展示记法，不拼接用户名或假定系统盘。Windows 通过 Known Folder 的 `FOLDERID_LocalAppData` 定位，Mac 通过框架的用户数据、缓存和日志路径定位。选择 Windows 本地目录是为了将大量截图与漫游配置分开。[Windows 标准目录](https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid) · [MyGo 目录接口](https://mygo.egoist.dev/docs/app#directories)

MyGo 当前 0.5.5 官网说明 Windows 的 `PathUserData` 默认在 `%APPDATA%`，`PathCache` 默认在 `%LOCALAPPDATA%\<Name>`，且支持 `App.SetPath`。本方案在应用初始化时明确配置数据、缓存与日志路径，使 Windows 缓存清理只作用于 `cache` 子目录，不能把整个本地数据根当缓存。Mac 沿用系统目录的用途区分；原始证据不放入可丢弃缓存。[Apple 文件存放说明](https://developer.apple.com/documentation/foundation/using-the-file-system-effectively) 这些是文档依据与设计建议，固定依赖后的实际路径行为仍需验证。开发与正式构建保持不同数据根，其配套缓存和日志也分别命名，不因设置应用名称或覆盖路径而混用；同根占用者统一管理这三类目录。

持久数据根内的最小结构如下；内部检查点与公共导出文件格式分别维护，不要求保存过程生成公共 `scan.json`：

```text
Youkai/
  settings.json
  sessions/
    <local-record-id>/
      checkpoints/
        <saved-revision>.json
      evidence/
        <evidence-id>.png
      resources/
        <resource-id>.json
```

- 每次扫描和每次导入档案均有独立的本地记录标识，目录只用该标识；日期、游戏、客户端和数量从检查点读取供界面显示。来源会话 ID 与采集序号继续按公共结果契约保留，同一来源的两个导入副本不共享可删除目录。
- `checkpoints` 保留当前和上一份有效代次；证据、原始识别和修订都随记录保留。`resources` 保存本次采集配置等少量复核资料，模型和运行库继续放安装资源目录，不逐次复制。首版不做跨会话图片去重或共享文件池，删除一条记录不会依赖其他记录的引用计数。
- 缓存只包含可由持久记录重新生成的缩略图、列表索引等内容。活动导入、导出或保存的暂存文件按操作占用，不能当闲置缓存清理；崩溃残留须先判断不再被占用。缓存可有界淘汰，日志按大小轮转，这不属于自动删除用户历史。
- 历史结果及原始截图不按天数或数量自动删除；正常升级和卸载不主动移除历史。空间不足时提示清理并阻止开始，写入中失败则按已有停止保存规则处理，不能为腾空间静默删除旧扫描。安装目录、当前工作目录和系统临时目录不承担持久历史存储。
- 用户导出的 ZIP/JSON 由其选择位置保存，属于独立文件；应用清理不删除这些副本，也不删除导入来源。导出目标不能位于应用管理的数据、缓存或日志根中，以免误纳入清理范围。首版提供打开数据目录入口，暂不增加目录迁移或网络共享存储功能。

清理按以下公共约束执行，界面布局由 T6 维护：

1. 分开提供清缓存、清旧日志和删除选中历史。删除历史以整条本地记录为单位，连同其结果、修订、证据和专属缓存清理；首版不提供只删原始截图却继续宣称档案完整的模式。删除前显示日期、客户端、记录数量、文件容量和未校对情况，允许先导出档案。
2. 建议历史删除使用明确的“永久删除”操作，确认后执行，不默认具备回收站恢复能力。批量选择只是清理入口，不等于自动按时间删除。应用不清空系统回收站、不跟随记录中的任意路径，也不触及安装资源或其他应用文件。
3. 已持有数据根占用的应用服务按本地记录标识取得独占删除权；活动扫描、收尾保存、未保存编辑以及正在读取的导出或导入记录均不可删除，界面显示原因，操作完成后由用户重试。新的读写与删除互斥；打开存储管理若导致恢复主窗，仍遵守先停止采集的公共契约。文件遍历不得跟随符号链接或 Windows junction 到管理目录之外。
4. 删除前先持久化并验证该记录的删除标记，保留本地标识和记录摘要；标记未保存成功就不删除内容。标记存在后该记录显示为待完成清理，不再作为正常会话打开。逐项删除后最后移除标记和目录；中断或部分失败保留标记及剩余内容，报告失败项，后续由用户重试已选择的清理，不误报完成或把残留当完整档案。
5. 清理预览的容量为估计值，执行后按实际已删除文件及剩余文件刷新统计。文件被占用或权限不足时报告真实结果，不显示预估空间已经全部释放；缓存、日志与历史分别计数。后台清理不阻塞 UI，也不通过取消保存或导出抢占文件。

以上设计无需新数据库、常驻清理服务或第二套文件格式。路径解析、独占删除、失败恢复和升级保留由 T4/T6/T7 的正式验收验证，当前无文件删除实测。

## 6. 首版功能范围建议

双平台首发、完整结果校对及两种关窗模式已确认，见 T1。2026-10-16 用户进一步确认首版仅识别简体中文，并接受下述 S 级驱动盘完整覆盖范围。锁定状态必需，装备代理人与弃置标记可行即纳入首版。显示适配先收窄到可验收的配置，Windows 从两种候选尺寸选定，Mac 先支持一组合理且使用较多的尺寸；其他字段处理、交互细节和具体显示参数仍按下文建议验证：

- **平台与游戏入口：**采用 T2 已确认的两平台、三种客户端场景，三者分别完成真实扫描闭环；Windows 两种客户端可共用平台能力，不因此增设截图后端，但入口身份、画面样本和遍历必须分别验证。用户不指定必须兼容的旧系统，由主控按依赖、采集/输入 API 与实测确定下限，策略见 [T7](t7-public-release-acceptance.md#4-依赖与最低系统的核对顺序)；不能把游戏所需 macOS 12+ 写成扫描器支持下限。
- **显示范围起点：**用户接受 Windows 从 2560×1440 与 1920×1080 中二选一，主控暂按首版选定一组标准配置、优先评估 1920×1080 推进，不把两个候选都写成已支持。Mac 首版先测定一组合理且使用较多的尺寸，后续版本尽量覆盖游戏内置尺寸。候选、来源与选择条件由 [T2 第 3.2 节](t2-platform-capture-input.md#32-可验收的窄显示配置候选)维护；单屏、SDR、系统缩放及窗口模式仍是技术候选，不能由尺寸推定。两种 Windows 客户端及 Mac 云客户端分别验证；T2 核对坐标，T5 验证布局后才形成支持矩阵。
- **实体与语言范围：**用户已确认仅识别简体中文游戏界面，覆盖 S 级驱动盘的 1 至 6 号位、0 至 15 级、所固定资料版本的全部套装，以及已装备与未装备的物品。用户另行确认 youkai 自身界面与使用说明首版也仅提供简体中文，决定见 [T1](t1-mygo-ui-distribution.md#已确认的产品选择)；导出中的游戏语言不充当应用界面设置。过滤范围出现在预检、结果和导出里，稀有度作为范围约束，不开放修改成 A/B 级。画面无法确认品质或筛选条件不符时保留异常证据，不仅凭声明范围把观测填成 S 级。
- **完整操作链：**打开并检查支持的仓库 → 确认范围、预览与前台使用说明 → 注册停止方式 → 按用户选择隐藏并让游戏获得焦点 → 确认就绪后扫描至范围结束 → 收尾保存 → 浏览全部结果、对照截图、校对 → 导出并能重新读取。总数不可知时显示数量与阶段，不伪造百分比。
- **操作起点：**用户于 2026-10-16 回复“按你的设计”，采用 T5 推荐的手动准备方式：打开驱动盘仓库并按提示完成筛选、排序和回顶，由程序核验后自动遍历。具体条件与无品质筛选时的访问方式见 [T5](t5-zzz-inventory-traversal.md#1-推荐路径与范围)，首版不包含自动完成这组准备操作。
- **核心结果与校对：**锁定状态已确认必需；套装、槽位、等级、主词条与副词条为建议必需字段。装备代理人与弃置标记按用户要求优先核实并纳入，若存在无法消解的读取问题，再带具体证据讨论范围。完整清单与修订方式见下表；稀有度的范围约束不因人工校对改变。
- **异常闭环：**不支持的布局在输入前拒绝；失焦、切页面、滚动失配、取消和识别故障都能停止操作，保留已完成条目，显示未完成原因并导出部分结果。正常退出保存，重开可查看；没有自动续扫承诺。
- **交付形式：**可在没有 Go、Node、Python 开发环境的 Windows 与 macOS 用户机安装，依赖处理明确；资源就绪后断网可对固定图片完成本地识别和导出，云游戏扫描仍依赖网络。包含支持配置说明与导出字段说明。
- **浏览器打开应用：**已确认通过网页唤起桌面 App，按第 2 节纳入安装注册、未运行时启动和已运行时恢复的验收；浏览器内界面的可行性咨询不扩大首版范围，入口不自动开扫。
- **首版交付目标：**用户将此前公开发布标准澄清为正常构建打包，不走官方分发渠道，没有 Apple Developer 会员或 Windows 代码签名证书；付费签名与公证不作为首版前提。用户拥有 Windows/Mac，会在测试前确保设备和客户端条件；完整功能及数据验收保留，打包路线与首次打开限制由 [T7](t7-public-release-acceptance.md)维护。

首版不纳入第二游戏、后台遮挡扫描、多客户端并发、动态插件、GPU、云 OCR、自动库存删除同步、自动更新和跨重启续扫。它们不妨碍首版形成完整闭环；软件升级暂可通过重新安装完成，结果放用户数据目录。

“查看全部结果”指显示本次 S 级驱动盘范围内的全部观测及处理状态，异常或未处理观测也不能消失。校对只修改扫描器保存的识别结果，不操作游戏中的装备、强化或锁定状态。证据图片、原始 OCR、采集序号、版本、终止原因和覆盖结论为只读来源记录；人工修正字段不能把部分扫描改成全量。字段修正超出声明范围时应提示冲突，不静默扩大范围；具体校验由 T3/T5 与主控对齐。

| 弃置标记 | 用户要求可行即纳入首版；与锁定状态一起核实图标位置和状态规则。 | 已标记、未标记、未知分别保存，可修正；仅改变扫描器记录，不改变游戏标记。 |

用户记忆中的“弃置标与锁定标共用一个位置”尚未由三种客户端样本确认。若核实为同一位置的互斥显示，适配器先识别该区域的锁定、弃置、无标记或无法判断状态，再按已验证规则输出字段；不将两个缺失图标分别默认成 false。图标识别与代理人头像匹配复用当前物品的截图证据，归游戏适配器管理，不强迫文字 OCR 识别图标。图片模糊、遮挡及未收录头像保持未知；固定字段策略要求的字段未知时，不计入自动完整识别成功。

装备状态与代理人识别分别验证能力，文件按 [JSON 字段策略](scan-json-format.md#3-一件驱动盘)表达完整、仅状态或未采集，避免因代理人不可识别而丢掉已知装备状态。当前仍以完整装备字段验证；采用较低能力配置必须有实机依据并回到主控讨论，不由导出或校对操作临时降级。

当前词条类型以 [fairy 标准化资料](../../../fairy/docs/specs/data/panel-attributes.md#音擎与驱动盘)及其[定义文件](../../../fairy/packages/data/definitions/attributes/drive-disc-affixes.json)为参考。这里只列需要识别的类型，不复制数值表作为另一份数据源：

| 槽位 | 当前资料中的主词条候选 |
| --- | --- |
| 1 | 固定生命值。 |
| 2 | 固定攻击力。 |
| 3 | 固定防御力。 |
| 4 | 生命值百分比、攻击力百分比、防御力百分比、暴击率、暴击伤害、异常精通。 |
| 5 | 生命值百分比、攻击力百分比、防御力百分比、穿透率，以及物理、火、冰、电、以太、风伤害加成。 |
| 6 | 生命值百分比、攻击力百分比、防御力百分比、异常掌控百分比、冲击力百分比、能量自动回复百分比。 |

副词条共十种：固定生命值、生命值百分比、固定攻击力、攻击力百分比、固定防御力、防御力百分比、固定穿透值、暴击率、暴击伤害、异常精通。穿透值和穿透率、异常精通和异常掌控不得混用。当前 fairy 已纳入风伤主词条的独立资料证据，但这不代表 youkai 已覆盖对应实机画面；具体显示名称、全等级数值与识别样本仍需核对。

Enka 的[固定版本接口文档](https://github.com/EnkaNetwork/API-docs/blob/88fc20697fda924430943434c11e0c45eb39509f/docs/zzz/api.md#equipment)提供等级、锁定、弃置等数据字段的交叉参考；接口有字段不证明仓库截图能读取，也不使 API 中的游戏物品 UID 成为本扫描器可观测字段。首版仍是可见画面扫描。

每个支持显示配置须记录系统/架构、客户端、窗口模式、内容区像素与逻辑尺寸、缩放、显示器布局、SDR/HDR、游戏语言与布局版本；云入口还需记录可观察的画面区域及画质条件。未知配置先拒绝或要求调整至已验证配置；移动窗口、跨屏、改变缩放等运行中变化按第 5 节停止。全屏或多显示器组合不凭比例换算宣布支持，具体候选和依据由 [T2](t2-platform-capture-input.md)维护。

与 fairy 通过数据和导出契约衔接。若采用 fairy 资料，应在构建资源时读取其固定版本公开 JSON/制品，生成可追溯的识别字典；无需在 Go 程序中运行 Node，也不导入私有 shared。已有 [fairy 消费契约](../../../fairy/docs/specs/data/consumption.md)提供公开 JSON 路径；当前定义明确标为 `enhancement: maximum`，仅有满级主词条值，不能据此完成 0 至 14 级数值校验。M2 必须补齐带固定来源、版本和摘要的全等级规则，再从权威资料构建识别资源；不另手填一份并行真值表。资料未齐时标明校验不可用，不能只凭 OCR 分数自动接受。本轮不修改 fairy、不确认新数据发布版本；若后续选择补充 fairy，另按该项目范围取得授权。

## 7. 验收：可离线完成与双平台实机要求

所有数量和时间指标均为建议验收目标，尚非实测成绩。实施前根据选定范围确认；任何未通过项都不能写为支持能力。

两平台的三种客户端场景分别取得证据后才算首发完成，Windows 完整客户端通过不能代替 Windows 云客户端，Mac 云客户端也不能代替 Windows 云客户端。以下检查随获授权后的正式功能实现，不增加独立 UI 验证版作为前置交付；纯逻辑、真实 OCR 与游戏验收分别报告。

### 不运行游戏的验收

| 检查 | 通过标准 |
| --- | --- |
| 已标注截图与 OCR | 样本收集、标注、划分和分组质量门槛统一见 [T3 第 4 节](t3-ocr-runtime-model-samples.md#4-三组样本与验收)。按三种客户端分别报告整件字段全对率、自动接受错误数、拒识率和校对量；有限样本不构成总体零错误保证。 |
| 图像处理一致性 | 对已知输入核对裁剪、颜色、缩放、张量与解码；错误模型/字典组合明确失败，不生成看似合法结果。 |
| 导航回放 | 用记录的帧和操作序列覆盖同属性相邻物品、翻页重叠、末页、详情迟到、点击未生效与页面切换；不得靠内容去重或固定等待制造成功。回放通过不能代替实机导航。 |
| 会话与竞争 | 同一开始请求即使会话已结束也不重复启动；另一请求在活动期间被拒绝。立即取消、满队列取消、乱序/重复结果、慢订阅和旧事件均有明确结局；停止不取消保存，取消竞态中每个序号只终结一次。恢复交互窗口先停止，取消后隐藏也不恢复，退出中关窗不转成隐藏。假平台可验证调度语义，不能证明 OS 停止时限。 |
| 结果与导出 | 重复物品数量保留，五类处理状态与采集计数对账，全部观测含失败状态均可浏览；旧物品修订不覆盖新值，其他物品变化不制造冲突，旧保存回包不把新修改标为已保存。校对后可追溯、重开及导出再读回一致；仅可用项导出明确排除数，不伪装全量。 |
| 保存与恢复故障 | 证据写入、检查点截断、同步/关闭失败、存储满及导出失败分别注入；新检查点失败不破坏上一有效代次。恢复核对数据、引用与修订，未终结任务标中断，不自动续扫或升级覆盖结论；取消后仍能保存，损坏或缺失证据明确报告。 |
| 本地存储与清理 | 按第 5 节验证数据/缓存/日志隔离、导入副本独立、活动读写与删除互斥、删除标记失败及清理中断。清缓存后结果可重开，批量删除只作用于明确选中的记录；异常链接、导入来源、外部导出与安装资源不被跟随或删除，失败统计如实显示。 |
| 多进程占用 | 同一实际数据根的两个独立进程只能有一个访问历史，覆盖不同路径别名、同时编辑及导出与删除竞争；持有者异常退出后能重新取得占用并恢复。不同数据根的开发版与正式版可各自管理历史，但并发开始仅一个取得扫描占用。获取失败或结果不明时不操作；第二实例恢复主窗先关输入许可。分别在两平台验证真实原语，框架单实例返回 true 不单独算通过。 |
| 浏览器入口逻辑 | 不支持或畸形 URL 不触发业务动作；启动前收到链接、重复链接、隐藏/扫描/收尾/退出中收到链接分别按第 2 节处理。URL 入口不自动创建扫描会话；纯逻辑通过不能替代真实浏览器唤起。 |
| 原生资源与构建 | Windows amd64 与 macOS arm64 分别核对本机开发构建、正式资源合并、真实模型加载、取消与释放；确认当前纯原生工程无需 Web 绑定生成。缺损模型/字典/原生库的表现须与链接加载方式一致，只检查文件存在不足以证明运行库可加载。 |

这里的离线分为“不运行游戏”和“网络断开”；前者中的真实 OCR 测试仍需要对应主机的运行库。当前会话只完成了文档与源码核查，没有语料、应用代码或已运行的上述测试。

### 两平台游戏与安装验收

| 检查 | 通过标准 |

### 推进顺序

2026-10-16，已整理[首版实施清单](scanner-implementation-plan.md)。该文档维护工程顺序、文件落点、阶段产物、通过条件和失败处理；本架构与 T1 至 T7 继续维护对应功能契约，避免重复定义。

首版作为一次完整交付，内部依次检查正式工程与资源、三种客户端单件流程、整仓及日常使用、双平台交付验收。Windows 可先贯通，Mac 原生加载与真实采集提前验证；不另建独立 UI 验证版，不将尚未验证的客户端悄悄移出首版。四个工程里程碑均未开始，资料与制品静态核查不代表应用实施已获授权。

每项任务回报应包含：结论与建议、证据及精确版本、涉及的文件/接口、已完成与未完成的验证、阻塞项及需要主控决定的事项。分析任务以结论和资料为输出，不自行扩展为依赖安装或应用实现；后续任务使用其实际获得的授权。
