## 1. 最小界面与完整使用流程

只维护一个主窗口。侧栏包含扫描、历史、设置三个目的地；扫描与校对是扫描目的地的两个阶段，历史是独立目的地，设置负责关窗、存储、更新、快捷键和关于。队列、OCR 线程、重试阈值等由应用管理，不成为用户开始扫描前的调参任务。

结果区沿用 T1 的列表、截图与字段表单。选择一条记录后能直接看图、修改和确认，不新增整张表逐格编辑或批量确认。首版扫描起点以[已确认的 T5](t5-zzz-inventory-traversal.md#1-推荐路径与范围)为准：用户先打开仓库、准备筛选与排序并回顶。

## 2. 结果浏览与逐件校对

顶部同时呈现库存覆盖、字段质量汇总和保存状态。例如“范围已遍历，3 件待校对，修改已保存”可以同时成立；不能只显示一个绿色“完成”。中断或部分扫描即使所有已采集字段都正确，也持续显示未扫全的原因。

结果表按宽度显示采集序号、套装、槽位·等级、主词条和状态；问题在详情副标题与证据条中，管理状态、装备等复杂字段留给表单。按套装、槽位或状态筛选，以及改变界面排序，都不改变原始采集顺序或物品身份。相同属性的物品保留独立行。默认选择按采集顺序的第一条记录，提供“下一个待校对项”；没有待校对项时仍能浏览全部结果。

右侧同时显示当前记录的上下文截图、可放大的字段裁剪与表单。点选字段可以定位其证据区域；找不到对应裁剪时显示完整上下文和缺失说明，不沿用上一件图片。原始文字、识别问题和修订前后值可展开查看，模型分数不包装成正确概率。

校对操作建议分为两种：

- **保存修改：**校验并保存当前条目的有效修订；允许仍有显式未知字段，继续留在待校对列表。修正一个字段不表示用户已检查整件。
- **确认并下一项：**用户对照截图核对整件，所有必需字段完整且校验通过后，保存修订与本条人工确认，再定位下一个待校对项。保存失败时留在当前项，保留输入并显示重试；不提前显示确认成功或跳到下一件。

人工确认属于具体物品修订；再次修改已确认记录后，需要重新确认，旧修订的确认不自动覆盖新值。重开历史后如当前资料校验失败，保留并展示原确认，同时列出新的冲突或资料缺口；这类记录也进入待处理筛选，未通过前不允许确认或导出为可用数据。v2 的可选 `equipped` 警告不属于资料缺口，不阻止确认或导出。校验结果独立于人工修订，结构与规则统一见 [JSON 当前校验](scan-json-format.md#当前校验)。

切换记录、会话或退出时若有未保存编辑，提供保存、放弃本条编辑或留在当前项；正常浏览不重复弹确认。编辑值存在语法错误时显示在字段旁，不存成合法规范值；仍无法判断的内容可以改为明确未知后保存。资料版本不支持的值保留原文和冲突原因，不为了通过校验强行改成已有候选。

套装、词条类型和代理人等使用固定资料候选；套装与代理人保存 fairy 数值 ID，类型决定单位，百分比与固定数值不能混用。管理状态必须能表达 `locked`、`discarded`、`none` 和未读到的 `null`；装备整体可为 `null`，读到后区分 `equipped`/`unequipped`，`equipped` 的代理人身份优先使用 fairy 数值 ID；v2 中装备者未解析只作为 warning，不阻止导出。所有操作仅修改扫描结果，游戏内状态保持由用户管理。

编辑缓冲、选中项、图片请求与异步保存均绑定稳定物品标识；筛选后第 5 行不等于原来第 5 行。旧图片加载和保存回包不能写入后来选中的记录。确认导致当前项离开筛选结果时，按确认前的顺序寻找下一项，最后一项完成则显示待校对为空，不绕回已经确认的项。

## 3. 保存、重新查看与导出建议

本地会话在扫描过程中保存，用户无需点击导出才保住结果。状态显示区分正在保存、已保存和保存失败；导出失败与内部保存失败分别提示。重新启动读取最近有效检查点，中断的扫描只能查看与校对，重新扫描仍从 T5 要求的起点开始。完整持久化规则引用[公共保存契约](scanner-architecture.md#保存校对与导出)。

[JSON/CSV v2 契约](scan-json-format.md)维护字段表示与读取规则。首版界面并列提供“导出 JSON”和“导出 CSV”两个按钮，不设默认格式；导出前明确展示纳入数量、排除数量、库存覆盖结论和“不含截图”。页面外壳直接写入系统下载目录，重名自动编号，不打开 Save 对话框。两种文件来自同一已保存修订和同一批可用记录：

| 格式 | 内容与语义 |
| --- | --- |
| 导出 JSON | youkai 自有 UTF-8 JSON，只输出当前可用的 S 级盘，保留来源会话、修订、范围、覆盖结论、筛选方式、排除数量和只含实际引用条目的目录子集。套装与代理人使用 fairy 数值 ID；不含截图、原始识别或修订历史，不能恢复本地记录。 |
| 导出 CSV | 与 JSON 同源的单表宽表，一行一件盘，副词条展开为 `sub1` 至 `sub4` 的 attribute/value/unit/rolls；不含截图、问题数组或会话外壳。 |

按用户已确认的校对方案，所有必需字段满足要求、当前校验通过、且属于自动接受或整件人工确认的记录，才进入 JSON/CSV；`equipped` 是 v2 的可选字段，装备状态或装备者未解析只保留 warning，不阻止导出。自动接受的记录不必逐件人工确认，仅修改过但尚未确认的记录不因数值看似合法就自动放行。可用数量为零时显示原因，仍可导出空记录文件。部分扫描允许导出可用记录，但消费方不得据此删除未出现物品；导出前明确展示纳入、排除数量及扫描覆盖结论。

导出先解决当前未保存修改，选取一个已保存的固定修订，再异步写文件；期间关闭重复导出入口，保留该修订及其证据，该记录暂不可删除，导出结束后可重新发起清理。允许取消导出，取消、目标无权限或空间不足不改变内部会话；成功提示必须在写入与关闭成功之后。默认文件名带扫描日期和会话短标识，用户覆盖同名文件时使用明确的文件选择确认，不直接截断唯一已有文件。

首版不提供 ZIP、archive 视图或档案导入导出；“重开”只指从本地历史记录读取已保存结果。资料不足或当前校验冲突时仍可查看原图和本地记录，但相应条目不进入 JSON/CSV。导出文件是独立副本，应用清理不删除它。

JSON 载荷采用稳定标识、十进制数值字符串和明确单位；`managementState` 的三态与 `equipped` 的可空对象分开，未读到、否定和空数组不能互换。具体格式、版本和目录子集统一见 [JSON/CSV v2 契约](scan-json-format.md)，此处不重复定义。后续对接具体工具时验证单位、未知状态和部分库存的约定，不能仅因字段名称类似就宣布兼容。

已读取的 [fairy 包规范](../../../fairy/docs/specs/packages.md)将职责划为计算与标准化资料，不能由此推出已有扫描库存导入接口。保留文件边界，不为 fairy 增加导入器或在线接收服务；目标工具确认后再评估文件适配。

### 导出前校对的已确认规则

2026-10-16，用户在了解两种校对方式后回复“按你的推荐”，确认重点校对问题盘：自动识别并通过全部必需检查的记录可直接进入导出的 JSON/CSV，异常或不确定记录校对确认后再纳入。全部已采集记录和截图先保存在本机；导出只包含可用记录，识别失败、未处理及待校对项仍保留在历史记录中，不因导出筛选而丢失。

例如采集了 100 张盘，97 张必需字段完整并通过自动检查，3 张数值模糊、缺字段或存在冲突。按已确认方案可直接导出前 97 张，界面明确显示“本次已采集 100 张，导出 97 张，另有 3 张待校对未纳入”；用户核对并确认其余 3 张后，可重新导出 100 张。也可以先完成校对再导出，不强迫用户先产生部分文件。这里只是流程示例，不是准确率或漏扫率承诺。

首版不强制全部盘逐件人工确认，也不新增两种长期设置模式；任意记录仍允许用户主动查看和修正。自动接受表示当前必需字段检查没有阻断错误，warning（如装备字段未完成）仍会保留，不能改名为“保证正确”，未识别出的错误仍可能通过检查。人工修正后按第 2 节保存并确认当前修订，不复用修改前的自动接受状态；人工确认本身也不是零错误保证。

### 历史记录与存储管理

用户已确认历史和裁剪截图默认保存在本机，直到主动清理；应用只保存裁剪证据，不保存完整帧。目录、数据分类与删除约束统一见[公共存储契约](scanner-architecture.md#本地目录保留与清理)，本节只定义操作入口：

- 历史列表显示日期、客户端、盘数量、覆盖与校对状态；1440 显示存储占用，1020/860 隐藏该列。支持按日期筛选；行内只保留“打开”和“⋯”，⋯ 提供导出 JSON/CSV、删除截图、删除记录。取消多选批量删除，存储清理归设置；筛选本身不删除内容。
- 扫描完成且识别数据保存后，截图清理入口在设置页；当前页面外壳尚未渲染“保留截图 / 删除截图 / 稍后处理”提示（模型状态保留，属于既有 UI 缺口）。删除截图只移除该记录的裁剪证据，保留结果与修订；待校对项仍在列表中并标注缺图。
- “设置 → 存储管理”展示历史、截图、缓存、日志的分类占用与磁盘可用空间，提供打开数据目录、清缓存、清旧日志、“删除全部截图”和“删除全部记录”。两类删除是独立入口，不以清缓存代替。
- “删除截图”和“删除全部截图”只移除裁剪证据，不删除结果、修订或校对状态；“删除当前记录”和“删除全部记录”移除记录及其结果、修订、证据和专属缓存。
- 所有删除在执行前显示涉及记录数、估计容量和待校对项，并要求明确确认；不静默删除，也不因曾经导出而跳过确认。是否曾成功导出只作提示，不能证明外部副本仍存在。
- 活动扫描、收尾保存、导出中的记录不可删除并显示原因；未保存编辑同样阻止删除。清理部分失败时保留失败条目和重试入口，不把所有选中项从列表抹去；清缓存不改变历史条目的校对与保存状态。
- 页面外壳导出的 JSON/CSV 固定写入系统下载目录，应用清理不删除它们。正常升级、卸载保留历史；想清除历史时在卸载前使用存储管理。数据目录与导出目录分开，首版使用固定系统默认位置和打开目录入口，不增加迁移向导。

## 5. 正式功能验收与后续

以下检查随正式功能完成，规则与假服务、实际 OCR、实际游戏三层分别报告。

| 检查 | 必须通过的行为 |

| 准备与开始 | 错窗口、未知布局、未回顶、筛选不符、排序标签未验证、日常一次面板访问与正式验收独立 Clear 校验不一致、停止方式不可用或保存位置失败时不派发输入；用户切回游戏后重查条件。同一次开始请求不会建立两次扫描。 |
| 连续校对 | 同属性重复盘各有独立行；相邻同详情双盘各保留一次观测；筛选、排序、键盘切换和图片迟到不导致串项。中文输入法、小数与百分比、`managementState` 三态与 `null`、`equipped` 可空对象和副词条增删有实际覆盖。 |
| 保存与确认 | 区分局部保存和整件确认；校验失败、保存失败、旧修订回包和退出未保存编辑均保留可解释状态。最后一个待校对项完成后列表行为正确。 |
| 覆盖与质量 | 全部覆盖但有待校对、部分覆盖但已有字段全对、OCR 失败与中断未处理分别展示；修正字段后不自动消除未扫全标记。排序未验证时不得显示完整覆盖。 |
| 历史与重开 | 正常重开、有效旧检查点恢复、相同来源的独立本地记录、缺图/损坏版本分别验证；重新打开不自动续扫，不覆盖其他会话。首版不提供档案导入。 |
| 存储管理 | 占用计算与批量预览对应实际记录；取消清理不改文件，活动扫描、保存、导出不可删除。删除截图保留记录并标注缺图；删除记录移除结果、修订和证据；删除中断、部分失败及重试均按公共契约显示，外部导出文件保留。 |
| 数据导出 | 按 [JSON/CSV v2 契约](scan-json-format.md)核对固定保存修订、序号、`managementState`、`equipped`、排除数量和精确单位；JSON 与 CSV 来自同一修订和同一批记录；部分结果不能被表示为完整库存。 |
| 性能与平台体验 | 沿用 [T1 的 1,000 与 10,000 项压力输入](t1-mygo-ui-distribution.md#正式功能的验收范围)，检查列表、图片缓存和连续校对；两平台分别验证下载目录写入、同名编号、目录不可写、输入法、托盘/菜单栏及关闭退出。合成数据只验证界面，不证明扫描质量。 |
