## 1. 最小界面与完整使用流程

只维护一个主窗口。队列、OCR 线程和重试阈值由应用管理。

结果区沿用 T1 的列表、截图与字段表单。选择一条记录后能直接看图、修改和确认，不新增整张表逐格编辑或批量确认。首版扫描起点以[已确认的 T5](t5-zzz-inventory-traversal.md#1-推荐路径与范围)为准：用户先打开驱动盘仓库页；扫描器在开始时自动重置筛选、勾选 S 并回顶，不操作排序（[01 D-12](../design/uiux-2026-11/01-functions.md#规格与当前实现的差异)）。

| 用户阶段 | 界面与主要操作 | 不满足条件时的表现 |
| --- | --- | --- |
| 准备 | 显示已找到的客户端和窗口、S 级范围、对应布局的准备提示、保存位置及停止方式；有多个候选窗口时明确选择目标。 | 提示具体缺项及调整方式；不因某个标题相同就替用户选中目标。当前截图不可用时不展示旧预览冒充已通过。 |
| 开始 | 完成资源、保存、权限及停止方式检查；开始前显示切回游戏的操作说明和等待上限。点开始后窗口留在原地，按[公共开始流程](scanner-architecture.md#隐藏恢复与退出)再次核验后才允许输入（“开始并隐藏”不采纳，P-09；界面见 [08 §1.2](../design/uiux-2026-11/08-screens.md#12-扫描区的阶段状态)）。 | 程序不强制激活游戏；等待到期仍未就绪则收尾并显示原因，不因倒计时结束自动开扫。 |
| 扫描 | 显示真实阶段、已采集 S 级盘数量与已验证当前号位（未知不造值）；识别保存仅在收尾呈现；停止快捷键按实际注册结果展示。后台进度与完成提示不抢焦点。 | 无可信总数时只显示数量与阶段；混合品质库存的访问进度与 S 级结果数量明确区分。 |
| 停止或结束 | 恢复入口显示“停止扫描并打开”；收尾期间显示停止操作、结束识别和保存的实际状态。 | 不能在原生任务仍运行或结果未保存时开放校对和新扫描。停止后游戏重获焦点不自动续扫。 |
| 保存完成 | 识别数据已保存后进入结果摘要；截图默认保留，结束时不询问。删除入口在校对后、导出后和清理页（P-13，[08 §2](../design/uiux-2026-11/08-screens.md#2-记录--摘要结果摘要)）。删除截图只移除该记录的裁剪证据，保留结果与修订。 | 保存失败时先重试。 |
| 校对 | 默认显示本次全部观测；筛选待校对、查看截图、修改、保存及确认下一项。 | 失败、未处理和字段未知条目仍在列表中，不在结果生成时消失。 |
| 重开与导出 | 从历史记录重开已保存结果，或导出当前已保存修订的 JSON/CSV；新扫描建立新会话。 | 部分和中断会话保留原因；不通过重开、校对或导出来升级覆盖结论。 |

具体文案是设计建议。默认关窗隐藏、明确退出和网页唤起均按[公共契约](scanner-architecture.md#隐藏恢复与退出)处理；设置可改为“关闭即停止并退出”。

呈现层于 2026-11-15 按 [第五版](../design/uiux-2026-11/13-v5-visual-system.md) 迁移：全局三目的地、记录内摘要/逐件、全部/警告/待处理筛选保持分层。覆盖、质量、保存互相独立；下面的数据与流程契约继续有效。

### 补扫不完整号位（P-12 第一步）

已保存、可读的 Windows 本地记录在摘要中提供“补扫不完整号位（…）”，只列出该记录**计划过且尚未完整**的号位：位置级降级、被结束截断和未到达都包括；已证明完整、没有号位账目、记录仍在运行或保存失败、记录不可读、以及非 Windows 本地记录不提供入口。来源记录本身是部分补扫时，只提供它当时计划过的号位；它没有计划的号位不显示为失败或未到达。

- **选择：**入口打开号位选择，逐项显示编号、状态与原因；可选择一个或多个，默认全选。确认前说明补扫会新建一条独立记录，原记录、图片、修订和已导出文件都不变。
- **准备与开始：**确认后进入普通准备页；窗口候选、确认、只读检查、预检、停止与退出许可、首存、取消和收尾全部沿用普通扫描。补扫意图与准备/开始结果绑定：每次重新选择都是新的准备实例，旧的启动回包或旧会话快照不能清除、阻塞或消费新实例；窗口拒绝、Busy、可恢复的准备失败保留同来源和同选择供重试；受理回包后到匹配会话快照/终态前，开始按钮保持等待门禁，不会重复发起；只有输入许可实际打开、明确取消或改为整仓、离开准备页或更换记录才结束。保存失败的原通知点击若停留在同一准备页，不取消该范围。服务对来源/范围作最终拒绝时，开始按钮保持禁用，必须“返回记录重新选择”或“改为整仓扫描”，绝不隐式降级为整仓；Stop/退出会取消尚未准入的来源校验，取消后不再继续进入适配器、落盘或打开输入许可（已进入的单个读或适配器调用需返回后才被拒绝）。正常开始后的后续扫描是普通扫描。
- **采集：**服务在接入前重新证明来源记录的最新检查点、SessionID 与记录目录一致、客户端、计划范围与所选号位；最新检查点引用的证据必须存在且大小、摘要有效，缺图、坏图、身份不符或 I/O 错误都在适配器与输入许可之前拒绝，且**不回退旧代次**。空、重复、乱序、越界、未计划或已完整的号位同样拒绝；适配器不支持位置子集或没有按请求声明范围时也拒绝，**绝不回退为整仓扫描**。只访问选中号位，执行与全量扫描相同的转盘、筛选、回顶、逐件归属和底部证明流程。
- **记录与结果：**补扫是新会话、新检查点、新历史记录；不写回、复制、迁移或合并原记录，也不修改原记录的修订、确认或已有校验冲突。新记录的内部声明范围保存所选号位与来源记录；覆盖结论固定为“部分”（即使选中全部六个号位，也不会成为全仓 `complete`）。预检失败且完全没有开始时仍为 `partial`，终止阶段表达“没有开始”，实际号位结论保持未知，不伪造账目也不打开输入许可。摘要和历史重开说明这是独立补扫及实际范围；刻意没有选的号位不显示为失败/未到达，已选却未完成的号位如实标注原因。
- **普通入口：**“重新扫描”仍执行整仓扫描，行为不变。
- **导出：**补扫记录按自己的已保存修订导出。JSON v2 的 `session.scope.slots` 只列该会话选中的号位，`coverage.status` 为 `partial`，计数等式仍是该记录的 `capturedCount = items.length + excludedCount`；CSV 列序不变。原记录的导出不受影响。损坏的补扫范围数据（缺少 `positions`/`rescanOf`、空值、错误类型或非法范围）拒绝导出，不按六号位生成误导文件；摘要、历史列表和通知同样不把损坏范围呈现为整仓完成。旧整仓记录仍导出六号位。
### 合并回原记录（P-12 第二步）

- **入口与预览。** 从已收尾并保存的 Windows 本地补扫记录打开“合并回原记录”。预览只列补扫已证明完整、原记录计划过且仍不完整的号位，支持选择其中一个或多个；完整的空号位也可替换。预览显示原记录时间与修订、每个号位的前后件数及将归档的校对修订件数。
- **整体替换。** 号位归属采用采集时记录的转盘位置，包括识别失败及未处理项。任一记录有来源不可证明的观测时拒绝，不从 OCR 或手工编辑的槽位字段猜测。确认时检查两条记录仍是预览中的最新修订，并再次检查号位结论。正在扫描、保存、安装更新或退出时拒绝合并。
- **保存与审计。** 合并在原记录 ID 上追加新修订。未选号位保留原序号、观测与校对；补扫观测从原记录历史最大序号之后继续编号，并保留其采集会话及原序号。被换下的观测、手工修订和证据随合并修订归档，不再计入当前结果；显式删除截图时也清理归档截图，保留观测与修订。补扫记录仍可独立打开和导出，已写出的文件不会被改写。证据复制或检查点保存失败时保留两条原有修订；过期预览必须重新确认。
- **呈现与导出。** 成功后打开原记录，摘要详情按号位列采集会话、保存修订与会话时间窗，并列出归档件数。即使各号位分别完整，结果仍是分批采集的部分覆盖，库存总数未知。JSON v2 记录号位来源与物品原序号。CSV 列序保持原样，两种格式只导出新修订的现行观测。见 [JSON/CSV v2 §2](scan-json-format.md#2-公共外壳)。

## 2. 结果浏览与逐件校对

顶部同时呈现库存覆盖、字段质量汇总和保存状态。例如“范围已遍历，3 件待校对，修改已保存”可以同时成立；不能只显示一个绿色“完成”。中断或部分扫描即使所有已采集字段都正确，也持续显示未扫全的原因。

逐件列表显示采集序号、套装、号位与状态，右侧完整字段按第五版证据顺序呈现；问题在详情副标题与证据条中，管理状态、装备等复杂字段留给表单。按套装、槽位或状态筛选，以及改变界面排序，都不改变原始采集顺序或物品身份。相同属性的物品保留独立行。默认选择按采集顺序的第一条记录，提供“下一个待校对项”；没有待校对项时仍能浏览全部结果。

右侧同时显示当前记录的逐行裁剪（字段裁剪，可放大）与 `Context` 裁剪、以及表单；首版不采集详情面板图（Q-06 选 A，[08 §3.1](../design/uiux-2026-11/08-screens.md#31-三个区域)）。点选字段可以定位其证据区域，定位依据是行角色，角色缺失时按采集顺序列出；找不到对应裁剪时显示缺失说明，不沿用上一件图片。原始文字、识别问题和修订前后值可展开查看，模型分数不包装成正确概率。

校对操作建议分为两种：

- **保存修改：**校验并保存当前条目的有效修订；允许仍有显式未知字段，继续留在待校对列表。修正一个字段不表示用户已检查整件。
- **确认并下一项：**用户对照截图核对整件，所有必需字段完整且校验通过后，保存修订与本条人工确认，再定位下一个待校对项。保存失败时留在当前项，保留输入并显示重试；不提前显示确认成功或跳到下一件。

人工确认属于具体物品修订；再次修改已确认记录后，需要重新确认，旧修订的确认不自动覆盖新值。重开历史后如当前资料校验失败，保留并展示原确认，同时列出新的冲突或资料缺口；这类记录也进入待处理筛选，未通过前不允许确认或导出为可用数据。v2 的可选 `equipped` 警告不属于资料缺口，不阻止确认或导出。校验结果独立于人工修订，结构与规则统一见 [JSON 当前校验](scan-json-format.md#当前校验)。

切换记录、会话或退出时若有未保存编辑，提供保存、放弃本条编辑或留在当前项；正常浏览不重复弹确认。编辑值存在语法错误时显示在字段旁，不存成合法规范值；仍无法判断的内容可以改为明确未知后保存。资料版本不支持的值保留原文和冲突原因，不为了通过校验强行改成已有候选。

### 件的四类与判定顺序

每件只落入第一个命中的类，判定顺序固定为**处理结局 → validation → quality → warning**。四类计数之和等于已采集件数；界面把“待补录 + 待校对”合称“待处理”。

1. **待补录**：处理结局失败（OCR 失败）或中断未处理的件；两者分开展示（[§5](#5-正式功能验收与后续)）。补录前不能导出，手动补录后可变为可用（[JSON/CSV v2 §3](scan-json-format.md#3-一件驱动盘)）。补录保留原始处理结局（`Status`、失败原因或未处理原因），列表标注“已补录”并按当前校验、质量和警告进入其余三类。这里的“失败件”只指处理结局失败，不包括 `validation.status=failed`。
2. **待校对**：`quality=needsReview` 的件，以及历史重开时 `validation.status` 为 `failed` 或 `unavailable` 的件（[JSON/CSV v2 当前校验](scan-json-format.md#当前校验)）；导出无法使用的其他已产生件（例如缺少结构化资料、质量未评价）也归入这一类，因为它们同样需要人处理。带 warning 但同时存在资料缺口或校验失败的件也归入这一类。
3. **有警告但可导出**：带 warning（如装备者未识别）但满足导出规则的件；警告不阻止自动接受（[JSON/CSV v2 §3](scan-json-format.md#3-一件驱动盘)），因此它可能是自动接受的，但不算已通过。
4. **已通过**：自动接受或人工确认、且没有 warning 的件。

服务层统一判定这四类，界面、导出与通知共用同一结果；导出纳入数等于“有警告但可导出”与“已通过”之和。

套装、词条类型和代理人等使用固定资料候选；套装与代理人保存 fairy 数值 ID，类型决定单位，百分比与固定数值不能混用。管理状态必须能表达 `locked`、`discarded`、`none` 和未读到的 `null`；装备整体可为 `null`，读到后区分 `equipped`/`unequipped`，`equipped` 的代理人身份优先使用 fairy 数值 ID；v2 中装备者未解析只作为 warning，不阻止导出。所有操作仅修改扫描结果，游戏内状态保持由用户管理。

编辑缓冲、选中项、图片请求与异步保存均绑定稳定物品标识；筛选后第 5 行不等于原来第 5 行。旧图片加载和保存回包不能写入后来选中的记录。确认导致当前项离开筛选结果时，按确认前的顺序寻找下一项，最后一项完成则显示待校对为空，不绕回已经确认的项。

## 3. 保存、重新查看与导出建议

本地会话在扫描过程中保存，用户无需点击导出才保住结果。状态显示区分正在保存、已保存和保存失败；导出失败与内部保存失败分别提示。重新启动读取最近有效检查点，中断的扫描只能查看与校对，重新扫描仍从 T5 要求的起点开始。完整持久化规则引用[公共保存契约](scanner-architecture.md#保存校对与导出)。历史元数据中的 `FailedCount` / `UnprocessedCount` 只统计尚未补录的件；当前历史界面使用四类 `Counts`，已补录件按当前四类计入。原始处理结局仍保留在记录中。

[JSON/CSV v2 契约](scan-json-format.md)维护字段表示与读取规则。首版界面并列提供“导出 JSON”和“导出 CSV”两个按钮，不设默认格式；导出前明确展示纳入数量、排除数量、库存覆盖结论和“不含截图”。页面外壳直接写入系统下载目录，重名自动编号，不打开 Save 对话框。两种文件来自同一已保存修订和同一批可用记录：

| 格式 | 内容与语义 |
| --- | --- |
| 导出 JSON | youkai 自有 UTF-8 JSON，只输出当前可用的 S 级盘，保留来源会话、修订、范围、覆盖结论、筛选方式、排除数量和只含实际引用条目的目录子集。套装与代理人使用 fairy 数值 ID；不含截图、原始识别或修订历史，不能恢复本地记录。 |
| 导出 CSV | 与 JSON 同源的单表宽表，一行一件盘，带 `sessionId`、套装 ID/名称及可解析的代理人 ID/名称，副词条展开为 `sub1` 至 `sub4` 的 attribute/value/unit/rolls；使用带 BOM 的 UTF-8，不含截图、问题数组或完整会话外壳。固定列序与空值见 [JSON/CSV v2 §5](scan-json-format.md#5-csv-导出)。 |

按用户已确认的校对方案，所有必需字段满足要求、当前校验通过、且属于自动接受或整件人工确认的记录，才进入 JSON/CSV；`equipped` 是 v2 的可选字段，装备状态或装备者未解析只保留 warning，不阻止导出。自动接受的记录不必逐件人工确认，仅修改过但尚未确认的记录不因数值看似合法就自动放行。可用数量为零时显示原因，仍可导出空记录文件。部分扫描允许导出可用记录，但消费方不得据此删除未出现物品；导出前明确展示纳入、排除数量及扫描覆盖结论。

导出先解决当前未保存修改，选取一个已保存的固定修订，再异步写文件；期间关闭重复导出入口，保留该修订及其证据，该记录暂不可删除，导出结束后可重新发起清理。允许取消导出，取消、目标无权限或空间不足不改变内部会话；成功提示必须在写入与关闭成功之后。默认文件名带扫描日期和会话短标识，用户覆盖同名文件时使用明确的文件选择确认，不直接截断唯一已有文件。

首版不提供 ZIP、archive 视图或档案导入导出；“重开”只指从本地历史记录读取已保存结果。资料不足或当前校验冲突时仍可查看原图和本地记录，但相应条目不进入 JSON/CSV。导出文件是独立副本，应用清理不删除它。

JSON 载荷采用稳定标识、十进制数值字符串和明确单位；`managementState` 的三态与 `equipped` 的可空对象分开，未读到、否定和空数组不能互换。具体格式、版本和目录子集统一见 [JSON/CSV v2 契约](scan-json-format.md)，此处不重复定义。后续对接具体工具时验证单位、未知状态和部分库存的约定，不能仅因字段名称类似就宣布兼容。

已读取的 [fairy 包规范](../../../fairy/docs/specs/packages.md)将职责划为计算与标准化资料，不能由此推出已有扫描库存导入接口。保留文件边界，不为 fairy 增加导入器或在线接收服务；目标工具确认后再评估文件适配。

### 导出前校对的已确认规则

2026-10-16，用户在了解两种校对方式后回复“按你的推荐”，确认重点校对问题盘：自动识别并通过全部必需检查的记录可直接进入导出的 JSON/CSV，异常或不确定记录校对确认后再纳入。全部已采集记录和截图先保存在本机；导出只包含可用记录，识别失败、未处理及待校对项仍保留在历史记录中，不因导出筛选而丢失。

例如采集了 100 张盘，97 张必需字段完整并通过自动检查，3 张数值模糊、缺字段或存在冲突。按已确认方案可直接导出前 97 张，界面明确显示“本次已采集 100 张，导出 97 张，另有 3 张待校对未纳入”；用户核对并确认其余 3 张后，可重新导出 100 张。也可以先完成校对再导出，不强迫用户先产生部分文件。这里只是流程示例，不是准确率或漏扫率承诺。

首版不强制全部盘逐件人工确认，也不新增两种长期设置模式；任意记录仍允许用户主动查看和修正。自动接受表示当前必需字段检查没有阻断错误，warning（如装备字段未完成）仍会保留，不能改名为“保证正确”，未识别出的错误仍可能通过检查。人工修正后按第 2 节保存并确认当前修订，不复用修改前的自动接受状态；人工确认本身也不是零错误保证。

### 历史记录与存储管理

用户已确认历史和裁剪截图默认保存在本机，直到主动清理；应用只保存裁剪证据，不保存完整帧。目录、数据分类与删除约束统一见[公共存储契约](scanner-architecture.md#本地目录保留与清理)，本节只定义操作入口：

- 历史列表显示日期、客户端、盘数量、覆盖与校对状态；列的显隐与行内操作以 `design/uiux-2026-11/07–09` 为准，本文只维护数据与流程契约。支持按日期筛选；导出 JSON/CSV、删除截图、删除记录仍为数据与流程契约。取消多选批量删除，存储清理归设置；筛选本身不删除内容。
- 从列表重开先读取并准备真实视图与导出结果，再进入详情；等待、取消、失败重试及就绪复用按 [08 §5](../design/uiux-2026-11/08-screens.md#5-记录列表历史)。取消只撤销打开意图，不中止底层读取；读取结果仍按原通知与有界退出等待契约结算。有效记录的导出构建失败不阻止查看。
- 扫描完成且识别数据保存后不询问截图去留（P-13）。删除截图只移除该记录的裁剪证据，保留结果与修订；待校对项仍在列表中并标注缺图。
- “设置 → 存储管理”展示历史、截图、缓存、日志的分类占用与磁盘可用空间，提供打开数据目录、清缓存、清旧日志、“删除全部截图”和“删除全部记录”。两类删除是独立入口，不以清缓存代替。
- “删除截图”和“删除全部截图”只移除裁剪证据，不删除结果、修订或校对状态；“删除当前记录”和“删除全部记录”移除记录及其结果、修订、证据和专属缓存。
- 所有删除在执行前显示涉及记录数、估计容量和待校对项，并要求明确确认；不静默删除，也不因曾经导出而跳过确认。是否曾成功导出只作提示，不能证明外部副本仍存在。
- 活动扫描、收尾保存、导出中的记录不可删除并显示原因；未保存编辑同样阻止删除。清理部分失败时保留失败条目和重试入口，不把所有选中项从列表抹去；清缓存不改变历史条目的校对与保存状态。
- 页面外壳导出的 JSON/CSV 固定写入系统下载目录，应用清理不删除它们。正常升级、卸载保留历史；想清除历史时在卸载前使用存储管理。数据目录与导出目录分开，首版使用固定系统默认位置和打开目录入口，不增加迁移向导。

### 诊断信息

“复制诊断信息”和“打开诊断目录”的入口位置以 [09 §4.6](../design/uiux-2026-11/09-window-and-interaction.md#46-诊断信息的折叠) 为准。复制文本的内容清单与隐私边界以[开发指南 · 诊断日志](../development.md#诊断日志)为准；同一段文本在各入口共用，“打开诊断目录”复用诊断日志目录，不提供上传。

以下按服务测试、实际 OCR 和实际游戏分别记录。实测结果及首版验收例外见 [M4](scanner-implementation-plan.md#m4双平台交付验收)。

| 覆盖与质量 | 全部覆盖但有待校对、部分覆盖但已有字段全对、OCR 失败与中断未处理分别展示；修正字段后不自动消除未扫全标记。排序未验证时不得显示完整覆盖。 |
| 历史与重开 | 正常重开、有效旧检查点恢复、相同来源的独立本地记录、缺图/损坏版本分别验证；重新打开不自动续扫，不覆盖其他会话。首版不提供档案导入。 |
