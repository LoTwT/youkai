# T6：用户操作、结果校对与导出

更新日期：2026-10-16。状态：主控交互草案，用户已确认自有 JSON、外部接入按需评估，以及历史和截图默认本机保留并提供手动清理。导出前采用重点校对问题盘的方案：自动接受的记录可直接导出，问题记录校对确认后再纳入；其余交互细节尚未逐项确认，未实现或进行 UI 实测。T5 的设计与手动准备方式已获认可；本轮继续评估 T6，不扩大为应用实施。本文维护用户操作和界面呈现，公共状态、保存与结果语义由[架构第 2、5 节](scanner-architecture.md#5-扫描会话与结果语义)维护，完整字段与可编辑范围见[第 6 节](scanner-architecture.md#首版字段清单提案)。

## 1. 最小界面与完整使用流程

建议只维护一个主窗口，包含扫描准备、当前进度与结果三个工作区域，历史扫描作为结果区的会话选择入口。设置只放关窗偏好和实际支持的必要选项；队列、OCR 线程、重试阈值等由应用管理，不成为用户开始扫描前的调参任务。

结果区沿用 T1 的列表、截图与字段表单。选择一条记录后能直接看图、修改和确认，不新增整张表逐格编辑或批量确认。首版扫描起点以[已确认的 T5](t5-zzz-inventory-traversal.md#1-推荐路径与范围)为准：用户先打开仓库、准备筛选与排序并回顶。

| 用户阶段 | 界面与主要操作 | 不满足条件时的表现 |
| --- | --- | --- |
| 准备 | 显示已找到的客户端和窗口、S 级范围、对应布局的准备提示、保存位置及停止方式；有多个候选窗口时明确选择目标。 | 提示具体缺项及调整方式；不因某个标题相同就替用户选中目标。当前截图不可用时不展示旧预览冒充已通过。 |
| 开始 | 完成资源、保存、权限及停止方式检查；隐藏前显示切回游戏的操作说明和等待上限。建议以“开始并隐藏”进入等待用户切回目标游戏，按[公共开始流程](scanner-architecture.md#隐藏恢复与退出)再次核验后才允许输入。 | 程序不强制激活游戏；等待到期仍未就绪则收尾并显示原因，不因倒计时结束自动开扫。托盘或菜单栏返回入口不可用时不隐藏后盲目开始。 |
| 扫描 | 显示阶段、已采集 S 级盘数量和识别进度；停止快捷键按实际注册结果展示。后台进度与完成提示不抢焦点。 | 无可信总数时只显示数量与阶段；混合品质库存的访问进度与 S 级结果数量明确区分。 |
| 停止或结束 | 恢复入口显示“停止扫描并打开”；收尾期间显示停止操作、结束识别和保存的实际状态。 | 不能在原生任务仍运行或结果未保存时开放校对和新扫描。停止后游戏重获焦点不自动续扫。 |
| 校对 | 默认显示本次全部观测；筛选待校对、查看截图、修改、保存及确认下一项。 | 失败、未处理和字段未知条目仍在列表中，不在结果生成时消失。 |
| 重开与导出 | 从历史记录重开已保存结果，或导出当前已保存修订；新扫描建立新会话。 | 部分和中断会话保留原因；不通过重开、校对或导出来升级覆盖结论。 |

“开始并隐藏”和具体文案是本轮建议，不能改写为 T1 已确认的细节。两种关窗模式、明确退出及恢复顺序继续引用[公共契约](scanner-architecture.md#隐藏恢复与退出)；浏览器入口现已由用户单独确认为网页唤起桌面应用，同样经过统一恢复流程。

## 2. 结果浏览与逐件校对

顶部同时呈现库存覆盖、字段质量汇总和保存状态。例如“范围已遍历，3 件待校对，修改已保存”可以同时成立；不能只显示一个绿色“完成”。中断或部分扫描即使所有已采集字段都正确，也持续显示未扫全的原因。

列表建议包含采集序号、套装、槽位、等级、管理状态摘要和待处理问题；复杂词条留给表单。按套装、槽位或状态筛选，以及改变界面排序，都不改变原始采集顺序或物品身份。相同属性的物品保留独立行。默认选择按采集顺序的第一条记录，提供“下一个待校对项”；没有待校对项时仍能浏览全部结果。

右侧同时显示当前记录的上下文截图、可放大的字段裁剪与表单。点选字段可以定位其证据区域；找不到对应裁剪时显示完整上下文和缺失说明，不沿用上一件图片。原始文字、识别问题和修订前后值可展开查看，模型分数不包装成正确概率。

校对操作建议分为两种：

- **保存修改：**校验并保存当前条目的有效修订；允许仍有显式未知字段，继续留在待校对列表。修正一个字段不表示用户已检查整件。
- **确认并下一项：**用户对照截图核对整件，所有必需字段完整且校验通过后，保存修订与本条人工确认，再定位下一个待校对项。保存失败时留在当前项，保留输入并显示重试；不提前显示确认成功或跳到下一件。

人工确认属于具体物品修订；再次修改已确认记录后，需要重新确认，旧修订的确认不自动覆盖新值。重开或导入后如当前资料校验失败，保留并展示原确认，同时列出新的冲突或资料缺口；这类记录也进入待处理筛选，未通过前不允许确认或导出为可用数据。校验结果独立于人工修订，结构与规则统一见 [JSON 当前校验](scan-json-format.md#当前校验与导入)。

切换记录、会话或退出时若有未保存编辑，提供保存、放弃本条编辑或留在当前项；正常浏览不重复弹确认。编辑值存在语法错误时显示在字段旁，不存成合法规范值；仍无法判断的内容可以改为明确未知后保存。资料版本不支持的值保留原文和冲突原因，不为了通过校验强行改成已有候选。

套装、词条类型和代理人等使用固定资料候选；类型决定单位，百分比与固定数值不能混用。锁定和弃置必须能表达未知，装备状态按主控字段定义区分未装备、已装备但代理人未知等情形。所有操作仅修改扫描结果，游戏内状态保持由用户管理。

编辑缓冲、选中项、图片请求与异步保存均绑定稳定物品标识；筛选后第 5 行不等于原来第 5 行。旧图片加载和保存回包不能写入后来选中的记录。确认导致当前项离开筛选结果时，按确认前的顺序寻找下一项，最后一项完成则显示待校对为空，不绕回已经确认的项。

## 3. 保存、重新查看与导出建议

本地会话在扫描过程中保存，用户无需点击导出才保住结果。状态显示区分正在保存、已保存和保存失败；导出失败与内部保存失败分别提示。重新启动读取最近有效检查点，中断的扫描只能查看与校对，重新扫描仍从 T5 要求的起点开始。完整持久化规则引用[公共保存契约](scanner-architecture.md#保存校对与导出)。

用户于 2026-10-16 明确选择先设计合理、准确、高效的 youkai 自有 JSON，外部工具接入等具体需求出现后再评估。[JSON v1 契约](scan-json-format.md)维护字段表示与读取规则；界面保留两种导出用途，并在对话框中明确列出包含数量、排除数量、库存覆盖和是否带截图：

| 用途 | 建议内容与语义 |
| --- | --- |
| 保存可回看的扫描档案 | 一个 ZIP，包含有格式版本的 JSON、全部已接纳观测的处理状态、原始结果、人工修订和配套证据。图片使用档案内相对引用；失败、待校对和未处理项一并保留。“完整档案”只表示本次会话内容完整，不表示游戏库存扫全或字段全对。 |
| 导出可用数据 | youkai 自有 UTF-8 JSON，只输出当前可用的 S 级盘，保留来源会话、修订、范围、覆盖结论、筛选方式及排除数量。界面列表的临时筛选不悄悄改变导出范围。单独 JSON 不含图片，也不声称能恢复完整校对档案或已兼容某个工具。 |

当前建议默认导出档案，数据 JSON 作为明确的另一选项。按用户已确认的校对方案，全部字段满足要求且属于自动接受或整件人工确认的记录，才进入可用数据；自动接受的记录不必逐件人工确认，仅修改过但尚未确认的记录不因数值看似合法就自动放行。可用数量为零时显示原因，仍可导出本次档案。部分扫描允许导出可用记录，但消费方不得据此删除未出现物品；导出前明确展示纳入、排除数量及扫描覆盖结论。

导出先解决当前未保存修改，选取一个已保存的固定修订，再异步写文件；期间关闭重复导出入口，保留该修订及其证据，该记录暂不可删除，导出结束后可重新发起清理。允许取消导出，取消、目标无权限或空间不足不改变内部会话；成功提示必须在写入与关闭成功之后。默认文件名带扫描日期和会话短标识，用户覆盖同名文件时使用明确的文件选择确认，不直接截断唯一已有档案。

建议支持通过“打开扫描档案”重看本应用导出的 ZIP：校验支持的格式版本、记录结构及证据引用，以独立本地副本打开，保留来源会话与修订，不覆盖已有记录或跨次合并库存。重新计算的领域校验与原确认分别呈现，资料不足或冲突时仍可查看和导出档案，但相应记录不进入可用数据。缺图与档案损坏明确报告；外部路径、越界引用和过大内容不能当作正常证据读取。单独数据 JSON 只承担数据交换，不伪造缺失的原始识别及截图。

JSON 载荷采用稳定标识、十进制数值字符串和明确单位；原始未知、否定和空数组分开，人工修订与原始处理状态分开。具体格式、版本和档案引用统一见 [JSON v1 契约](scan-json-format.md)，此处不重复定义。后续对接具体工具时验证单位、未知状态和部分库存的约定，不能仅因字段名称类似就宣布兼容。

已读取的 [fairy 包规范](../../../fairy/docs/specs/packages.md)将职责划为计算与标准化资料，不能由此推出已有扫描库存导入接口。当前保留文件边界，不在本轮为 fairy 增加应用界面、导入器或在线接收服务；目标工具确认后再评估对应文件适配。

### 导出前校对的已确认规则

2026-10-16，用户在了解两种校对方式后回复“按你的推荐”，确认重点校对问题盘：自动识别并通过全部必需检查的记录可直接进入数据 JSON，异常或不确定记录校对确认后再纳入。全部已采集记录和截图先保存在本机，完整档案包含识别失败、未处理及待校对项；它们不因数据 JSON 的筛选而丢失。

例如采集了 100 张盘，97 张必需字段完整并通过自动检查，3 张数值模糊、缺字段或存在冲突。按已确认方案可直接导出前 97 张，界面明确显示“本次已采集 100 张，导出 97 张，另有 3 张待校对未纳入”；用户核对并确认其余 3 张后，可重新导出 100 张。也可以先完成校对再导出，不强迫用户先产生部分文件。这里只是流程示例，不是准确率或漏扫率承诺。

首版不强制全部盘逐件人工确认，也不新增两种长期设置模式；任意记录仍允许用户主动查看和修正。自动接受表示检查没有发现问题，不能改名为“保证正确”，未识别出的错误仍可能通过检查。人工修正后按第 2 节保存并确认当前修订，不复用修改前的自动接受状态；人工确认本身也不是零错误保证。

### 历史记录与存储管理

用户已确认历史和原始截图默认保存在本机，直到主动清理。目录、数据分类与删除约束统一见[公共存储契约](scanner-architecture.md#本地目录保留与清理)，本节只定义操作入口：

- 历史列表显示日期、客户端、盘数量、覆盖与校对状态，以及该记录的存储占用；支持按日期筛选和多选，提供打开记录、导出档案及删除入口。筛选本身不删除内容。
- “设置 → 存储管理”展示历史、缓存、日志的分类占用与磁盘可用空间，提供打开数据目录、清缓存、清旧日志和管理历史。文件统计异步更新；未完成统计时显示计算中，不将旧数值当精确结果。
- 删除预览列出选中记录、合计数量与估计文件容量，并标注仍有待校对或未导出档案的记录。是否曾成功导出只作提示，不能证明外部副本仍存在。明确说明永久删除会包含结果、原图与修订，确认后才执行；首版无需用户逐条重复确认。
- 活动扫描、保存、导入、导出或有未保存修改的记录显示不可删除原因。清理部分失败时保留失败条目和重试入口，不把所有选中项从列表抹去；清缓存不改变历史条目的校对与保存状态。用户在其他目录保存的导出文件不纳入管理。
- 正常升级、卸载保留历史；想清除历史时在卸载前使用存储管理。数据目录与导出目录分开，首版先提供固定系统默认位置和打开目录入口，不增加迁移向导。

## 5. 正式功能验收与后续

不新增独立 UI 验证版。以下检查随获授权后的正式功能完成，规则与可控假服务、实际 OCR、实际游戏三层分别报告。

| 检查 | 必须通过的行为 |
| --- | --- |
| 准备与开始 | 错窗口、未知布局、未回顶、筛选不符、停止方式不可用或保存位置失败时不派发输入；用户切回游戏后重查条件。同一次开始请求不会建立两次扫描。 |
| 连续校对 | 同属性重复盘各有独立行；筛选、排序、键盘切换和图片迟到不导致串项。中文输入法、小数与百分比、未知管理状态和副词条增删有实际覆盖。 |
| 保存与确认 | 区分局部保存和整件确认；校验失败、保存失败、旧修订回包和退出未保存编辑均保留可解释状态。最后一个待校对项完成后列表行为正确。 |
| 覆盖与质量 | 全部覆盖但有待校对、部分覆盖但已有字段全对、OCR 失败与中断未处理分别展示；修正字段后不自动消除未扫全标记。 |
| 历史与档案 | 正常重开、有效旧检查点恢复、档案导出后打开、相同来源副本和缺图/损坏版本分别验证；重新打开不自动续扫，不覆盖其他会话。 |
| 存储管理 | 占用计算与批量预览对应实际记录；取消清理不改文件，活动读写不可删除。清缓存后历史与原图仍可打开；永久删除、删除中断、部分失败及重试均按公共契约显示，外部导出文件保留。 |
