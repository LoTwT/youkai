# T5：绝区零仓库遍历与详情归属

更新日期：2026-11-22。本文维护《绝区零》的仓库预检、筛选范围、详情归属、滚动和结束证据。首版 Windows 本地 1920×1080 的范围门禁见 §3，2026-11-22 的驱动仓库单页入口见 §8，三轮整仓对账和验收例外见 [M4](scanner-implementation-plan.md#m4双平台交付验收)。生产 profile 的自动重访和回顶重建保持关闭（§4–§5）。后续客户端的实测证据见 [M2 样本采集轮](../reports/2026-10-19-m2-macos-sample-round.md)和[重新架构决策](../decisions/2026-10-28-scanner-rearchitecture.md)。会话、结果、保存和导出见[架构 §5](scanner-architecture.md#5-扫描会话与结果语义)。

## 1. 推荐路径与范围

采用已获认可的方向：首版使用单个内置 ZZZ 适配器，用户打开驱动盘仓库，程序核验页面与范围，在经过测绘的区域逐件选择；小步滚动时保留前后重叠，确认实际位置后再继续。一次只推进一个已核实的动作，OCR 在已保存的截图上并行处理。三种客户端共享安全规则、位置账本和故障分类；布局、遮罩、噪声/阈值、时序和导航能力按客户端 profile 分离，各自保存参数。出现实际行为差异时分 profile，不预先维护三套控制器或配置语言；任一客户端的成功不能替代其他客户端。首版只交付 Windows 本地客户端；macOS 云与 Windows 云客户端保留同一原则，由后续版本分别验收。当前 macOS 云客户端只用拖动推进：点击末行与键盘均不能推进列表（F2/F3），见 §5。

**页面结构（macOS 云客户端实测，2026-10-19）：**驱动盘仓库按**转盘位置 × 位置内列表**两层组织——右侧六槽转盘选择位置（编号从左上起逆时针 1–6），左侧列表只显示当前位置的盘（[1] 号位实测 24 行 ≈ 96 件，其他位置未做全量遍历）；当前装备的盘始终置顶（筛选下也是），弃置盘默认排在末尾。遍历因此是两层循环：外层逐位置（转盘切换 + 每位置的重置/回顶准备，见 §3），内层按本节的列表滚动与选择推进。切换转盘位置时未观察到自动带出筛选，但筛选状态跨位置、跨会话保留，每位置都必须重新核验。外层按声明范围选择号位，每个号位独立准备。转盘切到目标号位并核对选中环后，按 §3 单次访问筛选面板，随后用 `TopFrom→TopTo` 回顶并确认稳定、未移动的顶部。顶部证明通过后从 `rowBase=0` 开始记本号位格位账目。号位准备或位置证明失败时，按 §5 的位置级降级记录原因并继续，达到升级阈值时停止整次扫描。物品重访与位置重建属于阶段 5。

**单页结构（4b-1 实现）：**列表、详情与转盘共享一帧，详情不是独立页面；一次访问 = 点击目标 → 同页等待选中框与详情内容变化 → 稳定 → 接纳，没有“关闭详情”步骤。页面判别由两个面板探针（红/白面板色 vs 列表暗色）、漏斗像素与转盘选中弧共同完成；像素匹配器只读取 `Layout.ReadRegions` 声明的区域（`TestPixelMatcherReadsOnlyDeclaredRegions` 随机化区域外像素后要求判定完全不变）。滚动到末端后不再以“滚动条到底”单独结束；底端由两种独立证据之一确认：最后一步位移不足一个完整步进（4 行），或再拖一次为 Stationary。

**2026-11-22 Windows 驱动仓库入口。** Windows 安装版的默认入口改为游戏内“驱动仓库”：单个 9×4 混排列表，无转盘，右侧固定详情。旧“驱动盘仓库”按转盘位置分列表的入口保留为显式 `YOUKAI_GAME_SOURCE=traverse`（客户端仍为 `windowsLocal`）。驱动仓库的页面条件、筛选准备、卡片/详情号位证据、滚轮推进、账目映射和样本边界见 §8；本文其余章节的页面、焦点、遮挡、几何、取消、只读和证据规则仍适用，但“转盘切换 + 位置内列表”的两层循环不适用于驱动仓库。

客户端、实体与字段范围见[架构第 6 节](scanner-architecture.md#6-首版功能范围)。首版采用有限显示配置，布局按 [T2 的尺寸候选](t2-platform-capture-input.md#32-可验收的窄显示配置候选)分别测绘，不预先建设任意尺寸布局系统。

**操作起点（用户 2026-10-16 确认“按你的设计”；2026-10-19 实测轮与 4b-2 决定补充）：** 用户只需打开驱动盘仓库并保持受支持的显示配置；点击开始后，扫描器先解析并锁定游戏窗口，未运行或没有合格窗口立即停止，已打开则自动把游戏应用切到前台一次（扫描期间失焦仍停止），再在预检通过后自动按位置完成转盘切换、打开筛选面板→重置→勾选 S→关闭并校验 Active、回顶，之后开始遍历。不把用户声明直接当作页面已满足条件，也不包含登录、启动游戏或从任意游戏页面自动导航；从待机/主菜单自动打开仓库页尚未实现，当前仍需用户手动进入仓库页。筛选准备及排序证明见 §3；回顶和遍历只在所需准备完成后开始。

生产 profile 仍无 A/B 详情徽章分类。匹配器能以已标定证据判定 `QualityNotS` 时只记格位结局，不接纳；品质不可判定则保留未解决格位，按 §4 的重访和降级条件处理。

| [AdeptiScanner-ZZZ / Form1.cs](https://github.com/D1firehail/AdeptiScanner-ZZZ/blob/96441078aa0309b94836f4702d901688aae752ff/AdeptiScanner%20ZZZ/Form1.cs) 的 `discAuto` | 先识别格位，避开可能触发滚动的边缘；读取倒数第二行后点击末行推进，再比较整行详情图像的哈希。末行还会删除连续相同哈希的尾部条目，用以处理空格位。可继承边缘行为需单独测绘的认识；相同内容不能独自区分空格、重复物品和未移动，所以 youkai 不按这个条件删物品。 |

## 3. 开始前必须核对的页面条件

驱动仓库入口使用本节的页面、范围、顺序与起点门禁，但页面前提与准备动作以 §8.3 为准；它不切换转盘、不按号位逐个准备，而是一次性处理混排列表。

| 条件 | 需要取得的证据与不满足时的处理 |
| --- | --- |
| 页面和目标 | T2 的窗口身份、前台、图像区域与几何有效；视频内明确是驱动盘仓库，列表与详情布局匹配已支持配置。登录、云排队、重连、弹窗及其他页面不开始。OS 窗口可用不替代游戏页面判断。 |
| 范围 | 已具备校准证据的 profile 在同一次面板访问中完成“打开→重置并确认→选择所需品质并确认→关闭并复核”。重置后以新取得的稳定面板帧正向确认重置状态，首版同时确认 S 芯片未选中。随后只点一次 S，等待点击后的稳定帧直接显示 S 填充选中。关闭后在新的仓库帧核对同号位与漏斗 `Active`。重置承担清除其他筛选的职责，普通扫描在上部控件确认后关闭。动作已投递、旧帧或关闭后的漏斗均无法替代对应的面板效果证据。无法证明效果按 §5 降级该号位。 |
| 顺序 | 排序标签须正向识别。严格范围路径及已有排序模板的 profile 在准备时标签不可读即降级当前号位。从扫描首次确认标签起，每次读取到正向识别标签均与基准比较，确认不同即停止整次扫描，保留已接纳结果并令 `sort` 未验证。模板不匹配只表示不可读。Windows 原生与 macOS 云的现有探针只在面板打开时识别“稀有度”，面板关闭时无已标定的排序标签；排序方向不在探针的证明范围内。扫描器不操作排序控件。 |
| 起点 | 必须有可见的顶部依据，或在已获确认的自动准备流程中取得回顶证据。“向上滚动很多次”与画面不再变化都不能单独证明顶部。开始于列表中部时不能标为整仓扫描。（macOS 实测：重置/关闭面板后列表会滚到当前选中盘的位置而非顶部，起点必须重新取得；4b-2 每位置用 `TopFrom→TopTo` 甩动到滑块顶判据，要求滑块起点持续上移；随后继续向顶拖，Lost（Undecided + 稳定滑块的例外见 §5 的 4b-2 实现状态）或仍有位移时不得接受顶部，只有稳定非移动的顶部确认（滑块起点不变 ±2 像素且仍为 Top，或 Stationary 且仍为 Top）才可开始遍历。连续 2 次无进展、确认预算耗尽或超过 16 次时：把该位置标为不完整、记录原因并继续下一个位置（2026-10-31 已实现；首视口重建边界见 §5，见 §5 的“位置级降级”）。） |
| 数量 | 当前界面不显示数量/容量（F1 的仓库页标题区与筛选面板可见范围；用户决定不访问其他页面）。完整性不依赖计数；结果注明“本次未做计数对账”。若将来界面提供可信的同范围计数，再增加对账；容量上限或全品质总数不能冒充 S 级总数；数量未知保持未知，不能用手填数字补成已验证数量。 |
| 可操作位置 | 测绘格位边界、可完整显示的行、选中标记、滚动条及详情区域；记录点击哪些行会自动滚动。只在已验证的稳定区域选择物品，顶部、底部及不足一屏分别验收。 |

**阶段 3 校准边界。** `PanelEvidence.Range` 提供面板帧的 `ResetVerified` 与 `RarityS`。前者来自已校准的重置状态证据，后者来自 S 芯片的填充。当前帧可读的值与动作后生效分开，`range.reset.effectVerified` 和 `range.selectedS.effectVerified` 仅在该动作后的新帧通过稳定确认后为真。`range.verified` 表示普通准备中两个效果与关闭后的仓库证据均通过。Windows 本地客户端验收候选在物理客户区原生 1920×1080 的正常入口启用 `Inventory.RequirePanelRangeProof`，适用于全仓和 P-12 按号位补扫，`YOUKAI_SCROLL_MATCHER=legacy` 只切换滚动匹配。缩放布局丢弃面板探针。未校准 profile 继续用一次面板访问采集，记录 `range.verified=false`，覆盖至多是 `partial`。号位 `complete` 仍表示遍历完成并沿用 P-12 口径。已有排序模板的 profile 在标签不匹配时按位置准备失败处理。

扫描在准备关闭面板并确认漏斗 `Active` 后开始检查其变化，仓库帧直接观察到 `Clear` 即停止整次。漏斗仍为 `Active` 时无法识别筛选的具体变化。当前界面无可信仓库总数，视觉扫描只报告已观察到的变化。阶段 3 的严格路径和停止门禁已用 fake 回放验证，Windows 静态判据已用真实裁剪离线验证，六个号位的同窗人工动作时序与真实关闭帧均已通过本地回放。

严格范围准备在动作后的新帧中同时检查连续性。若重置或选 S 的效果尚未确认时已稳定看到仓库闭合，或关闭等待中稳定看到面板上的 S 已清空，就结束当次范围证明并按号位降级。后续的 S 选中或漏斗 `Active` 无法恢复这份证明。单张过渡帧或无法读取的帧会中断连续计数。等待期间明确看到仓库换号位则停止整次扫描。

**Windows 1920×1080 校准。** 已保留 3 号位 11:55:57 残留套装、12:11:53 重置、12:18:54 勾 S 的原位裁剪。在匹配到面板且固定坐标处的 S 字形成立后，用面板开启时的漏斗颜色与 S 灰证明重置状态。只选 S 步骤要求漏斗蓝、S 芯片蓝及可见 A/B 为中性暗色。残留套装让 S 芯片下移，原点击点 `(1426,604)` 在重置样本内确认。初次静态校准使用 3 号位，样本坐标、哈希和测量见[夹具说明](../../internal/game/zzz/collect/testdata/winlocal-filter/README.md)。13:22:36 的独立闭合裁剪来自后续窗口，实测仓库漏斗探针为 `Active`、转盘探针为 3 号位。面板开关锚点和部分格位在裁剪外，该样本用于独立静态对照。14:33–14:34 取得同窗分段证据。打开、重置、选 S 分别在释放后约 752、500、442 ms 达到现有连续三帧门槛。同次关闭动作补交了帧 4–20 的完整原图。帧 6–20 均匹配仓库、面板关闭、3 号位、`Active` 与 20 格账目，关闭等待在第三个连续匹配帧 8 通过，距释放约 555 ms。现有 2 秒预算和三帧门槛沿用，段间人工空档不计入门禁验证。随后补验 1、2、4、5、6 号位。五个位的打开、重置、只选 S 和整页关闭均在 2 秒内达到连续三帧；关闭确认耗时约 453–562 ms，终帧均验证原号位、`Active` 和 20 格。1、2、4、5 起始已选 S，6 从额外清空后的灰漏斗起步。六个号位的选 S 点击点均为 `(1426,604)`，详见夹具说明。排序变化仍需另一种正向可识别标签的面板样本。

**范围未证明位置已接纳物品（2026-10-29 用户决定；2026-10-31 已实现位置级降级）：** 某位置准备失败或范围未证明而跳过时，结果必须记录原因（内部 `observedScope.positions[]` 的 `stage`/`reasonCode`/`reason` 与日志；见 §5）；该位置此前已接纳物品保留在可用结果与导出中，不计入 `excludedCount`，并在结果界面/诊断标注“该位置范围未证明”；该位置只报 `partial`。公共 JSON/CSV v2 不新增位置级字段，JSON 以 `coverage=partial` 表达；物品仍留在 `items` 中。保留原始观测与序号、不删除/不重编号。依据：范围证明发生在遍历前，此情况少见；每件物品接纳时单独核对 S 徽章，范围未证明影响的是“是否遗漏”，不是“已采是否正确”。JSON v2 不变。有排序探针的 profile 在准备时标签不可读会降级该号位。

**Windows 阶段 3 真机结果（2026-11-20）。** Jane 在原生 1920×1080 客户区验收普通准备、全仓遍历与 P-12 独立补扫。GUI 正常启动。验收基线为 `7ea3590d6e03981c1c9d61c04fc2b42a5ebc44c6`，所应用的 `t5-stage3-windows.patch` SHA-256 为 `81aeda536f93c456210ce64e80b64cd09067f134d8c6e22ab73528a4912fe65c`。正常 UI 全扫共接纳 1,010 件，1–6 号位分别为 98、118、98、226、247、223。六个号位的范围均已证明，格位账目结清，覆盖为 `complete`，无号位降级。134 件有识别警告，仍可导出。该数字属于字段识别结果，格位完整性由已证明的遍历账目判定。

## 4. 一件物品何时可以进入识别队列

一次选择包括动作前画面、目标格位、输入结果和动作后画面。控制者先取得队列容量并重查平台条件，再发一次短点击；接纳截图前必须满足以下条件：

1. 列表仍属于同一范围，目标格位有物品且位置可对应。选中标记位于该目标，必要时核对先前选中标记已离开；不能用鼠标位置代替游戏内选中状态。动作前画面可以复用上一件接纳后的稳定帧作为首个稳定样本，但仍须用新鲜或复用帧确认目标仍占用、列表仍是当前内容。
2. 详情区域完整可见，必需字段布局已结束过渡；使用文字和图标区域的稳定性，排除背景动画、鼠标和云客户端提示造成的假变化。稳定画面本身不证明是新物品。
3. 选中与详情之间有经过样本验证的关联证据。先核对格位与详情共同可见的套装、槽位、等级等特征，再结合动作后的内容变化或就绪信号；特征一致仅作支持，因为不同物品可以相同。不能只用固定延时、模型高分或新的采集时间戳接纳旧详情。
4. 当前截图及其区域仍属于同一窗口、几何和采集流。满足归属条件后才按公共契约接纳一次观测；导航尝试与用于核对的截图不另算一张盘。

首次读取已经选中的物品没有上一件详情可比较，需单独验证初始选中与完整页面的稳定状态。不能强制要求每一件文字都发生变化，否则一件库存和相同物品无法处理；也不能因此对后续物品放宽旧详情检查。

驱动仓库还要把卡片号位、详情独立号位和详情标题 `[N]` 三处作为同一事实核对；选中卡滚出视口后旧详情仍可能停留在右侧，不能只凭同一号位或新的采集时间接纳。具体门禁与冲突处理见 §8.4。

**准备前提。** 接纳循环在本号位的筛选准备与稳定顶部成立后开始。严格范围路径和旧 profile 的兼容边界见 §3，失败按 §5 分级。

**单件重访（阶段 5，本机 fake 验证）。** 普通目标在首次观察后仍选中，但详情尚未稳定归属，或已稳定但品质、词条数仍不可读时，扫描器可在原地再观察一次。须已证明本号位的完整筛选范围、稳定顶部，并且点击前和失败帧都显示顶底同屏。原账目必须仍是第 0 行起算、占用一致、目标为 `unresolved` 且无序号。重访不发送游戏输入；新窗口沿用原点击前的比较基准，每帧核对号位、选中格、有效漏斗、上下边界和账目，仅用独立新帧重新证明归属及可判读字段。每会话最多一个额外的 `ActionBudget` 观察窗口。内部格位的 `revisitFromFrameId` 与最终判定帧关联两次尝试。只有接纳分配序号，OCR/字段识别失败沿用逐件校对。计数口径见[决策 §9.4](../decisions/2026-10-28-scanner-rearchitecture.md#94-scan-json-formatmd已同步选定-a)。

普通目标仍选中、但此路径没有范围或位置证明、预算已用尽或重访仍未取得可接纳详情时，该号位以 `stage=detail` 降级。相同详情已有独立的参照格往返验证规则；参照失败或选中位置不可归属时保留原停止行为。跨视口排队返回任意未解决格仍待后续证据。

**4b-1 标定结果（macOS 云客户端，1920×1080；证据见报告 §6/§7 与 `internal/game/zzz/collect/testdata/maccloud/manifest.tsv`）：**详情行固定矩形与识别裁剪同一标定（name/level/main/sub1–sub4）。七行灰度 MAD 的同内容对（每个证据目录的 frame-0000/0001，n=236）最大 1.01、p95 0.88；六组完整视口内正交相邻格对（n=186）中 183 对 >4.0（最小 4.07），2 对 <2.0（0.42、0.62），1 对在带内（2.38）。3.72 那对是**对角非相邻**（s6 r3c3→r4c0），不属于相邻对统计。没有任何同内容对超过 2.0，因此 2.0/4.0 不会造成误接纳；低 MAD 的相邻对先进入相邻同详情的参照往返，无法完成时才以 `detailUnattributed` 安全停止（真实重复盘已由 2026-10-20 现场轮 seq 812/813 验证；更多场景的最终阈值仍待验收）。S 徽章金色像素 251–256（面板遮罩帧 0），判据 ≥150；第四副词条数值列墨迹 0–21（3 条）对 132–426（4 条），判据 ≤50 / ≥80。像素匹配器只返回 S 或未知；A/B 徽章分类（4b-3）未实现，S 筛选失效时停止而不是猜测品质。

**归属规则（单页）：**点击前目标必须已有选中框并且占用；点击后选中框必须到目标，详情先在连续 `StableFrames` 帧内保持同一内容并跨过 `DetailStableSpan`（默认 200ms，实测详情在 374–415ms 稳定），再拿这个**稳定画面**与基线比较：`Different` 才按 `transitionVerified` 接纳；`Same` 或落在 `2.0–4.0` 同/异阈值带内（`Undecided`）都视为“未被证明不同”，等待到预算结束仍如此则进入相邻同详情的参照往返。过渡动画中的单帧 `Different` 不作为已变化证据，否则相同内容的相邻盘会被误判为普通切换并跳过参照核验。基线取该位置上一件已接纳的详情；位置首件尚无已接纳详情时回退到点击前帧。首件若已选中（初始读取）不要求内容变化，但必须从首个可判定详情起保持稳定。选中框动了而稳定画面始终 `Same`/`Undecided` 且无法完成参照核验时停止并报 `detailUnattributed`；相邻同详情的参照往返已实现，并已在 2026-10-20 现场轮 seq 812/813 的真实相邻同详情盘上取得 `referenceVerified` 证据，更多场景的最终阈值仍待验收。规则上相邻且详情完全相同的 S 盘各算一件，无法完成参照核验时停止并保留未解决位置，不能合并、丢弃或按属性去重。详情可判定但条数不明时报 `detailUnresolved`；已接纳截图的投影或入队失败报 `evidenceFailed`。这些情况都保留位置未解决，不跳到下一件。

**相邻相同详情：**如果该布局有独立、经过验证的选中和详情就绪证据，可保留两次不同位置的观测；两件 S 盘各算一件，永不按属性或图像哈希去重。如果只能看到高亮移动而无法排除旧详情，候选做法是在同一可操作区域选择一件已知且可区分的物品，确认其详情后再回到目标，取得关联证据；每一步都等待自己的结果，最多做一轮，不把它当成超时后的重复点击。找不到可用参照或仍不明确时停止并保存诊断，不能复制上一件结果。**该参照往返已实现，并在 2026-10-20 现场轮 seq 812/813 的真实相邻同详情盘上验证；更多场景的最终阈值仍待验收**；此限制必须纳入重复物品验收；无法通过时仍是适配缺口，不宣布已支持。

等待详情时可在截止时间内重新观察，不因到期而盲目补点。首次动作效果尚不明确时，不发送验证用的下一次动作。原地重访条件见本节“单件重访”；参照格核验无法归属时停止。超时时间、稳定采样跨度与相似阈值来自原三种场景的调参资料（首版使用 Windows 本地客户端样本，两种云客户端样本随后续版本），并用未参与调整的序列验收；两张相同帧或等待某个毫秒数都不是普遍正确性保证。

管理状态与装备从同一次已确认归属的详情和列表格读取，并保留对应裁剪。管理状态以列表盘格右下角角标为主：红色垃圾桶为 `discarded`，灰色锁为 `locked`，无图标为 `none`；顶部“拆解”左侧指示只确认锁定/未锁定维度，不能区分弃置与无标记，弃置/无标记仍由列表角标区分。列表与顶部在锁定维度冲突或任一不可读时记 `null`，不填 `none`。锁定角标带有闪光动画，单帧可能漏检；多帧采样与颜色加形状分类是 PR 6a 的待验证项，不能写成已确认可靠。

装备以详情页等级右侧头像判断“已装备”并做身份匹配，列表格右上角头像用于确认；冲突或不可读时整个 `equipped` 记 `null`。当前代理人装备和他人装备都属于 `equipped`，当前装备置顶只影响遍历顺序。代理人身份使用 fairy 数值 ID（例如耀嘉音 `1311`）。fairy 的 `partnerInfo.iconPath` 有 57/60 个 `IconRoleCircle` 圆形头像，缺失 3 个（`1381`、`1531`、`1551`）；实拍一致性与缺失头像的处理待 PR 6b 验证，不能写成已完成。扫描不点击状态切换按钮。

## 5. 滚动衔接、重复物品与末尾

驱动仓库使用滚轮单格推进，选中卡滚出视口后没有选中框锚点；其位移由滑块行程与前后卡片徽标重叠共同判定，见 §8.5。旧仓库的拖拽、选中框和“4 行一步”标定不适用于驱动仓库。

维护当前已确认的格位顺序和未访问位置。**阶段 2（已实现，2026-10-30）**以选中框位移为主要滚动证据：遍历推进到滚动时，最后访问的格位（通常 r4c3）天然持有选中框，拖动后由选中框所在行计算位移（例如 r4c3 → r0c3 为 4 行），选中格必须留在视口内；选中框滚出视口或读取不可用时回退归一化特征判定，并要求滚动条滑块佐证，仍不足则 fail-closed 不提交。列表内容、像素/特征匹配与滚动条降为辅助核对；F6 表明整屏内容无法唯一对应，不能单独承担位移或重定位。每次推进前保存可比较的重叠区域；短滚动后重新测量格位，用多处共同特征和实际位移辅助关联前后位置。至少保留一整行可用重叠作为起始候选，实际需要多少由布局与重复物品样本决定。无需每次都对整屏物品做 OCR。归一化特征（零均值归一化相关）在可比支持区域上比较，均匀/低信息量区域不得因最佳候选分数高而接受（信息量门槛），最佳对次优整行候选差距不足时判 undecided；灰度 MAD 绝对阈值保留为质量闸门与像素相同帧的停稳证明，不得单独否决选中框与滚动条一致的位移。

**滚动动作标定（macOS 云客户端实测，2026-10-19）：**列表滚动按整行吸附（实测行距 147 帧像素；慢拖基本 1:1 后吸附，快甩有惯性多滚 1 行以上）。已验证步进：**413 点拖拽 / 1000–1200ms = 精确 4 行**（两种时长均实测 3/3 精确；更短时长的拖拽无已保存的位移证据，不做结论，正式版以每步位移校验兜底），每步用列表区位移测量校验（588 帧像素 = 正常 4 行，< 588 = 已到底）。2026-10-25 现场轮中 1000ms 拖拽在部分滚动后继续惯性下滑 1 行，导致相对拖拽前帧失去完整重叠；普通滚动改用同一标定范围内更慢的 1200ms。**顶/底判据：再拖一次，前后帧列表区误差 < 4（内容移动时帧间误差约 6–7）**。4b-2 另接受最后一步位移不足整步作为底端独立证据。拖拽停稳以实现中的“相对 candidate 连续观测不变”判据为准，`ScrollBudget` 默认 5s：2026-10-21 现场轮曾在位移 4 行后 3s 内未停稳而安全停止，故把预算放宽到 5s；仍需更多样本确认。点击到详情稳定实测 374–415ms，推算每件约 0.5s、每位置约 1 分钟、全程约 6 分钟（推算值）。完整标定表与证据目录见[实测报告 §5](../reports/2026-10-19-m2-macos-sample-round.md#5-滚动与时延标定)。

**停稳模型（阶段 2 已实现）：** F7 显示拖动后 0–500ms 列表不动、约 1s 才开始移动、2s 仍在移动（迟到+惯性），最终 4 行。`awaitScroll` 因此先观察到“移动已开始”（相对拖动前帧的位移、Lost，或零位移归一化相关明确低于静止阈值且支持区域信息量达标——零位移 MAD 单独不算移动证据，云编码噪声会把静止帧推到 5–10；近均匀内容上的噪声会把 ncc0 拉到 ≈0，没有信息量佐证的低相关同样不算），再判停稳；停稳 = candidate 相对自身**连续 2 次**的独立观测稳定（macOS 云 profile 的 `SettleObservations`，来自 `ScrollTiming`：`MotionStartBudget` 2.5s / `SettleBudget` 4s / 2 次确认），每次确认都必须是**新的 fresh 帧**且必须证明相对 candidate 零位移：与 candidate 相同的内容、选中框仍在同一格位、零位移 MAD 低于静止阈值、信息量足够的零位移 NCC 不构成运动反证且滑块无两端一致的可测平移，或唯一零位移 NCC（≥0.92、对次优整行候选差距 ≥0.05、信息量达标）通过标定门槛；零位移 MAD 单独（包括恰为 0）不构成证明——重复行可让整行移动保持近零误差，重复行造成的 NCC 并列同样不构成证明。Windows 底部裁剪只少读滑块前缘 2px（368–931→370–931，终点与列表像素不变）属于单边测量伪差，不否决静止。平台空闲复用帧是中性观测——它重复的是最近一个 fresh 帧已判定过的内容，同一空闲状态在复查间隔内被反复送回只是同一次观测，不计数也不重置（避免“新帧 X + X 的复用拷贝”凑满两次）。**残余风险**：若帧源在 candidate 之后长时间只回送空闲复用帧而无任何 fresh 帧，停稳确认永远凑不满，等待会耗尽预算并按 unsettled Lost 安全停止——这是 fail-closed 的可接受行为（2026-10-30 两组现场序列保留的帧全部为 fresh 帧，云视频流持续产出新帧）；阶段 5 按实机样本再评估是否需要把复用确认以某种独立观测形式计入。迟到惯性带来的更大总位移会替换 candidate 并重置计数，底部回弹同理。等待截止时间至少为 `waitStart + MotionStartBudget`（F7：迟到起步窗口内的静止不构成“动作未生效”的终局，不触发重拖；配置更短的 `ScrollBudget` 也不会绕过该下限）；临近预算末尾才观察到移动时，停稳窗按 `SettleBudget` 从移动时刻起算放宽（只放宽不缩短）。拖拽出现位移后不得叠加下一次动作。阶段 5 用 `scroll-ok` 诊断记录的 `motion_frame`/`settled_frame` 与逐帧到达时间标定重试预算（决策 §10），不另做独立时序重测。阶段 1 已修正等待终局的汇总（最后一次判定为准）与重拖条件（仅在确认未动时重拖、重拖取新基准），见下文“阶段 1 动作状态”。

**阶段 2 滚动证据（`ScrollEvidenceMatcher`，2026-10-30 已实现，默认启用）：**在像素匹配器之上按决策 §4.3 K2 分层判定 `MatchScroll`，同帧读取选中框锚点（格位选中边框探针，两框唯一才算读数）、列表视口样本与滚动条滑块：① 像素相同帧（零位移 MAD < 4）直接判 Stationary（均匀内容也成立），但选中框明确移动或滑块两端一致地按标定下限可测平移（仅单边变化不算）时必须否决静止，转由后续位移/未决判定处理——重复行列表的整行移动可只改变选中框与滑块，使零位移 MAD 仍远低于静止阈值；② 归一化相关判静止——零位移 NCC（严格按 dy=0 计算，不取容差窗内最佳：静止不容窗口，亚行蠕动不得借邻近位移的分数）≥ 0.92、对次优整行候选差距 ≥ 0.05、支持区域灰度标准差 ≥ 12（信息量门槛），选中框明确移动或滑块两端一致地按标定下限可测平移（仅单边变化不算）时不得判静止；③ 选中框位移为主要证据——前后帧选中框同列且行差 1–4 行时，该行的 NCC ≥ 0.90、信息量达标，且没有其他整行候选**显著超过**它（超过量 > 并列容差 ε=0.005，见下）；竞争差距 ≥ 0.05 即直接判 Displaced（证据带 `basis=selection+feature`）；差距不足 0.05（含 |差距| ≤ ε 的并列或近似并列）时，仅当滑块按下面第 ④ 条的规则（方向与幅度，±20%）独立佐证该行数、且该实测行程与其他未被特征排除的同向候选行数对应的行程可区分，才判 Displaced（`basis=selection+feature+scrollbar`），否则 undecided。0.05 差距阈值、0.90 NCC、信息量门槛与 ε 均不放宽；若某候选超过选中行超过 ε，选中框与特征矛盾，即便滑块同意选中框的行数也判 undecided（镜像方向的反向候选不参与滑块可区分性检查：滑块方向已与选中框一致，反向位移要求滑块反向移动，二者不能同时成立）。**并列容差 ε=0.005 的依据：**NCC 在标定支持区域（≥ 2000、macOS 云客户端约 5.5×10⁴ 个样本）的 8 位灰度上累加，少量灰度级的量化/编码噪声对相关系数的影响约 10⁻³ 量级，浮点累加的舍入约 10⁻¹²；ε=0.005 高于该测量分辨力，又比 0.05 的竞争门槛小一个数量级（2026-10-31 现场真实行与相邻行的差距为 0.029–0.038，不会被当作并列）。显式 ε 取代旧的“浮点相等/差值为负”判断，使真正周期性内容上的判决不取决于舍入偏差的方向。MAD 绝对阈值只记入证据不再否决（2026-10-28/30 现场帧：选中框 r4c3→r0c3、4 行 NCC 0.918–0.978、次优 ≤0.78，而 MAD 8.4–13.1 超出旧上限）；同格选中框存在时特征不得单独声称位移（矛盾即 undecided）；④ 无可用选中框对（滚出视口、双侧无选中或读取不可用）时特征路径单独判定——NCC ≥ 0.93、竞争差距 ≥ 0.05、信息量达标，且滑块按方向移动并落在“声称行数 × 每行滑块位移 ± 20%”内（`basis=feature+scrollbar`；每行滑块位移由观测到的滑块几何推得：滑块长/轨长 ≈ 可见行/总行数，固定常数在不同列表长度下不成立；容差低于 1/最大行数，错一行即拒绝），滑块按自身几何铺满全轨（距轨长不足少量像素）视为下方无内容、不可佐证任何位移——不按推导步数阈值判定，六行列表（可见五行、恰可滚一行）的单行滚动仍可佐证，否则 undecided；⑤ 以上都不成立时运行旧 MAD 搜索：内容变化越过 Lost 阈值且最佳位移不是整行 → Lost，其余 undecided（消融与回退：`YOUKAI_SCROLL_MATCHER=legacy` 使用纯像素匹配器判定，行为与阶段 2 之前一致；掩码夹具在两种判定下逐对给出相同结论，2026-10-30 两组失败序列在旧判定下仍复现现场失败）。

**并列容差与滑块可区分性的风险分析（2026-10-31）：**按决策 §4.2（选中框为主证据、内容特征只用于筛候选）、§4.3（最佳对次优竞争、差距不足不得由特征单独裁决）与 §4.8（不猜行数，证据不足即重建位置或把位置标为不完整），本修补需要回答：内容周期性、选中框读错一行、而特征因周期性无法区分两行（差值 ≤ ε）时，若滑块行程恰好落在错误行数的 ±20% 容差内，会不会提交错误位移？结论：
- **整数行程的单行误差不会通过。** 容差 0.20 低于 1/ScrollMaxRows（0.2 < 1/4，建模的最大单次位移为 4 行；错一行被拒绝需要容差 < 1/n）；声称 n 行时实际 n±1 行的行程为 (n±1)/n：n=2–4 时 n−1 行为 0.5–0.75、n+1 行为 1.25–1.5，n=1 时为 0 与 2，均在 [0.8, 1.2] 之外。
- **测量误差会打开一个窄窗口。** 行程读数与每行行程推导都非精确：声称 4 行时，“4 行”带为 3.2–4.8 行，“3 行”带为 2.4–3.6 行，重叠区 3.2–3.6 行；按 2026-10-31 位置 6 的几何（每行约 12px）约为 38–43px（约 5px 宽）。一段实际 3 行、被测量成 3.2–3.6 行的行程会同时满足两者；若不检查可区分性，滑块会把错误的 4 行“佐证”成通过。
- **因此本 PR 收紧为可区分性检查。** 实测行程必须落在其他未被特征排除（与选中行差距 ≤ 0.05）的同向候选行数的容差带之外，落入任何一条即 undecided。镜像方向的反向候选（如 -4）不参与：滑块方向已与选中框一致，反向位移要求滑块反向移动，两个方向不可能同时成立；这正是“行内容完全相同”的合成序列中唯一略高于 +4 的候选（差值约 4×10⁻⁵）能被正确排除的原因。
- **残余风险与未覆盖项。** 若同一行程的测量误差 ≥ 20%（如实际 3 行被读成 ≥ 3.6 行），重叠区检查无法识别，理论上仍可能接受错误的 4 行；10-31 的现场读数误差为 2–4%（49 vs 48.0px、44 vs 42.4px），远低于该阈值。进一步降低需要与滑块独立的第二位证人（静止证人、位置级降级），由其他 PR 负责，本 PR 不新增。

宣布全部覆盖，必须同时满足：范围已按 §3 在单次面板访问内证明（确认重置、确认选 S、关闭后同号位且漏斗 Active）；排序标签已读取且在扫描期间保持不变；起点与顶部已取得稳定非移动的确认；每次移动连续且无无法解释的跳跃；每个占用格位有结局（S 接纳、非 S 跳过或未解决）；相邻且详情完全相同的 S 盘各自接纳；末端有独立的底部/列表结束证据。**不要求同范围总数**：当前界面不显示数量（F1），结果注明“本次未做计数对账”；若将来取得可信同范围计数再增加对账。覆盖完整与结果完整分开：上述条件成立时 `coverage` 可为 `complete`，未解决格位仍在可用结果/导出中标出。排序或范围未证明时整仓 `coverage` 至多为 `partial`。确认排序标签变化会停止整次扫描。OCR 是否成功另行报告。

**覆盖账目（阶段 3）。** 预检与 Collect 结束后分别上报 `observedScope`。预检上报未落盘时以 `storageFailure` 结束，输入许可从未打开。结束后的上报由最终检查点持久化。`countReconciled:false` 对应“本次未做计数对账”，不推断 `expectedCount`。每个 `positions` 条目记录 `range`、`slotLedger` 与遍历结论，位置级失败另记 `stage`、`reasonCode`、`reason`。整仓 `coverage=complete` 要求六个号位均已遍历完成、范围已证明且排序已验证。已开始但未满足完整条件时为 `partial`，无号位账目时为 `unknown`（声明范围限定补扫见下）。

取得稳定顶部后才建立 `slotLedger`。`rowBase` 从 0 开始，只在已停稳且验证非零整行位移、重叠区域逐格一一对应、完整覆盖且占用一致后前进。每个占用格位保留零基 `absoluteRow`、`column`、首次观测帧、状态及可用的判定帧；`admitted` 带已分配的 `sequence`，`notS` 与 `unresolved` 无序号。仍未读取的已见占用格和停止时未成功接纳的尝试均为 `unresolved`，空格与未验证视口无格位条目。`visits` 统计 `admitted` 和 `notS`。重叠重见保留身份与原结局，参照物不产生新记录。

格位仅在本次扫描的当前号位连续遍历内有身份。位置丢失时账目停在最后已证明的视口。回顶、重访或重建后，旧绝对行和内容指纹均不足以继承旧结局，须重新证明范围、顶部和逐行对应，见阶段 5。普通准备的 `range.verified` 只证明本号位当次重置和选择后的状态。恢复须用当时的新观测证明当前范围与之前范围等同，保留阶段 5 的独立只读门禁。内部账目字段不进入公共 JSON v2，计数仍为 `capturedCount = items.length + excludedCount`。

**首视口重建（阶段 5，本机 fake 验证）。** 首次向前滚动失证且原顶部仍有已接纳的选中格作锚时，可在本会话尝试一次。旧帧只作比较证据。先用新帧证明滑块两端向下平移、长度一致及当前位置连续停稳，随后在只读复查中，连续新帧须同时证明原排序标签、S 选中和所有其他筛选均清空，才能关闭面板。普通准备的重置效果只证明当时的范围；失证后的复查必须直接读取当前范围。Windows 现有探针只能读出重置状态与 S 品质。缺少其他筛选的独立探针时，该号位按原滚动失败降级；具备探针但复查不可读时，按范围失败降级。复查中确认其他筛选已启用或 S 已清除时，整次停止。确认同号位和 Active 后走既有有界回顶、顶部停稳流程。关闭复查面板后若仍看到面板，且新帧无法确认原排序、S 或其余筛选清空，本号位立即降级；后续号位可用已有准备流程收起面板。新顶部须同时通过原选中格、逐格占用、滑块两端、选中详情与独立零位移匹配的核验。对原首屏每个已接纳或已排除的格位，还须核对同坐标格内像素完全一致；格内动画或内容变化导致无法对应时保留旧账目，按号位降级。成功后沿用原首屏账目，跳过已接纳格，再由正常前进路径逐行验证重叠、追加新行。内部 `rebuild` 记录原基准、复查面板及顶部确认帧。复查期间观察到错页、换号位、筛选或排序变化、截断或过期帧会停止整次扫描。

账目未保存每个旧视口在失证前后的对应证据，因此更晚的视口或底部确认失证时，保留最后已证明的格位并降级。两条恢复路径均需 profile 显式启用 `EnableBoundedRecovery` 并完成 §3 的范围证明。Windows 本地 1920×1080 已启用普通准备的范围证明；所有生产 profile 的 `EnableBoundedRecovery` 均保持关闭。关闭时沿用原详情归属与接纳规则：详情持续闪烁且无法归属、已停稳但品质或副词条数未知时，整次停止。本机一次观察及一次重建的会话上限是本切片的保守边界。Windows 本地客户端仍需取得同格迟到/相同详情、首滚失证到停稳、复查原筛选、回顶与再次前进、截断/换号位等故障注入序列，以及动作时间戳和人工逐格对照，才能标定实际预算。

滚动与顶部、底部确认以等待阶段最新的页面和号位观测决定是否可继续。较早的位移候选只用于停稳判定与诊断。最新一帧离开仓库，或已验证的仓库页显示其他号位、转盘不可读或网格不可验证时，整次扫描停止，保留已有格位账目。普通滚动或底部确认失证时，只有最新一帧仍验证原号位才按位置级失败降级。

确认位移停稳的新帧须与候选帧逐格占用一致。静止比较成立而格位占用冲突时，拒绝该位移并保留上一个已证明的账目。只有底部标记暂时不同，则在原等待预算内从零重新累计连续确认。预算内始终无法取得完整一致的确认序列时按号位降级。短步到底使用通过停稳确认的底部标记，追加拖拽确认底部使用静止终帧的底部标记，两条路径都须核对格位账目。

每次回顶确认拖动（含重试）前，必须取得当前仓库和当前号位的观测。明确识别到筛选面板或其他号位时立即整次停止。暂时不可读可在原预算内继续等待，截止时仍没有当前仓库证据则停止，不能从旧基线发输入。

**范围限定补扫（P-12 第一步，已实现，2026-11-19）：**会话的声明范围（`SessionShell.Scope`）可选带 `positions`（严格升序、去重、1–6）与 `rescanOf`（来源记录 ID）；没有这两个成员的旧记录仍是完整 1–6 范围。带范围的会话只按该顺序执行选中号位的转盘切换、筛选准备、回顶与遍历，`observedScope.positions` 也只包含选中号位。范围为空、重复、乱序、越界、重复 JSON 字段或与来源记录不一致时，服务在取得扫描占用前拒绝，遍历的 `PositionScoped` 接缝也会在预检前拒绝，不回退为整仓扫描。声明范围存在但字段缺失、为空、类型错误或范围非法时，记录本身仍可打开（不扩大正常加载失败范围），但摘要标明范围无效、不提供补扫入口，导出明确失败而不是按六号位生成。范围限定的会话即使六个号位全部完整也固定 `coverage=partial`，因为一次会话并没有覆盖整个仓库；预检失败、未打开输入且没有任何号位账目时同样保持 `partial`，终止信息表达“没有开始”，不得伪造执行过的号位。记录的号位账目、降级与停止语义和全量扫描相同。遍历过程保持来源记录原样。采集结束后的显式合并见 [T6 P-12 第二步](t6-review-export-workflow.md#合并回原记录p-12-第二步)。

**位置级降级（阶段 5 最小切片，已实现，2026-10-31）：** 每个位置独立准备和遍历；以下失败在既有动作重试之后不再终止整次扫描，而是结束当前位置，记录原因并继续下一个位置：

| 分类 | 现有触发点 | 记录与结果 |
| --- | --- | --- |
| 位置准备失败 | 转盘点击后仍未切到目标位（`navigationMismatch`）；筛选面板打不开、关闭后漏斗非 Active、面板意外关闭（`navigationMismatch`）；回顶在连续 2 次无进展、16 次上限或确认等待未决时无法证明顶部（`navigationMismatch`），且最后一次观测仍是仓库列表、转盘位置未变 | 位置 `complete=false`，`stage` 为 `wheel`/`filter`/`top`，`reasonCode` 保留底层故障码，`reason` 写明说明；此前已接纳物品保留；继续下一位置 |
| 位置证明失败 | 滚动终局未决、位移但无唯一对应、位移后未停稳或对应关系被拒（`positionLost`/`navigationMismatch`）；底部确认 Lost、位移或未决（`navigationMismatch`）。以上只在等待的最后一次观测仍是仓库列表时降级；最后一帧不是列表（弹窗、加载页、断流）仍属会话致命，保留的位移候选不能掩盖页面级原因 | 位置 `complete=false`，`stage` 为 `scroll`/`bottom`，其余同上；不猜跳过行数，不重访已接纳物品 |

每个位置重新执行转盘切换、筛选准备和回顶；只有上一位置以降级结束、且失败时已验证的筛选面板确实开着，下一位置的建列表阶段才允许通过关闭控件关闭该面板（显式标记，见 `pendingPanelClose`）。其他情况下出现筛选面板仍是会话致命；扫描器只在批准的筛选准备中自行打开面板。位置账目写入内部 `observedScope.positions[].stage/reasonCode/reason`，同时写入日志 `youkai: collect: position=N incomplete ...`；结果界面在覆盖结论旁列出不完整位置及其原因。公共 JSON/CSV v2 不新增位置级字段，仍以 `coverage=partial` 表达，物品仍在 `items` 中且不进 `excludedCount`（[决策 §9.4](../decisions/2026-10-28-scanner-rearchitecture.md#94-scan-json-formatmd已同步选定-a)）。

**升级阈值。** 一次扫描内累计的不完整号位达到 3 个或所选号位总数（取较小值）时，整次扫描以 `positionFailureLimit` 失败结束，消息列出每个不完整号位。整仓扫描累计 3 个失败时已涉及半数号位，可能是采集、筛选或转盘的系统性故障。补扫 1–2 个号位时，全部所选号位不完整才触发该阈值；若至少一个号位完整、且未发生会话级故障，补扫正常结束并保留 `coverage=partial`。已接纳物品始终保留。

**2026-10-20 现场复跑：**位置 1 的筛选面板在真实《云·绝区零》窗口上读出 `sort:"verified"`、`sortLabel:"稀有度"`，模板探针不只对 M2 样本成立。随后一次干净运行（15:27–15:43）完成六位置：1,005 件采集、1,005 件产出、0 未处理；`coverage:"complete"`，位置 1–6 均为 `complete:true`、`topVerified:true`、`bottomVerified:true`，视口数依次 6/7/7/14/16/14，访问数 97/114/104/225/249/216，排序始终为已验证的“稀有度”。该验证只覆盖标签，不读取升降序方向。同日更早一次运行在位置 1 第 3 视口、48 次访问后因 Lucia 抢占前台报 `focusLost`，覆盖正确保持 `partial`，保留了失败路径的现场证据。

末端证据优先研究滚动条触底、列表尾部结构与最后占用格位，具体信号必须由当前布局样本验证。滚动后无变化、详情重复、OCR 数量达到估计值，都不能单独作结束条件。没有独立末端证据时保留部分或无法确认，不能为了自动结束而降低标准。

空库存必须由支持范围内明确的空列表状态证明；只有空白截图或计数 OCR 为零时不成功。单件、不足一行、整屏恰好填满、最后一行缺列和全部物品内容相同分别处理，不把它们视为普通多页的缩小版。锁定、弃置和已装备盘若属于声明范围，也必须各自覆盖。

## 6. 保存什么证据，怎样验收

驱动仓库除详情图外还要保存该卡的左上号位徽标、详情标题区和详情独立号位徽标裁剪；它们是“卡片号位 = 详情号位 = 标题 `[N]`”的证据，见 §8.6。

每件保留公共契约要求的详情图和字段来源，另附目标格位、对应的导航步骤与接纳理由。范围已证明且接纳帧漏斗为 `Active` 时，内部 `capture` 带 `rarityFilter:"S"`，可选带一次性的 `scrollEvidence`（记录进入该视口的最近一次已核实位移：前后 frame id、rows、matches 数量与 matcher evidence），同一视口不重复。滚动前后的选中框位置（行、列）与选中格是否仍在视口内已随阶段 2 落地：`MatchScroll` 的判定证据与滚动诊断清单记录前后帧选中框槽位（`selection_before`/`selection_after`），选中格滚出视口即表现为 after 侧无选中框并触发特征+滑块回退路径。同一次面板访问只记录一份 `range`，包含打开、重置、勾选 S 和关闭的帧号与可读状态，另记录重置和勾选动作是否通过新帧确认，旧 profile 可能只有页面、排序与漏斗证据。面板诊断裁剪随可校准控件区域补齐。按 §5 记格位状态，准备和位置级失败保留已接纳观测。**重访（阶段 5）**只对尚未确认采集的失败发生，重访前后的帧、判定与替换关系留在内部诊断；不分配新 `sequence`，旧尝试不进入公共计数。保留滚动等待的帧序列裁剪、逐帧匹配清单与位置对应（失败时按尝试分别保留，阶段 1；成功滚动自阶段 2 起同样落盘帧时间诊断；诊断产物的格式、上限与保留策略见[开发指南的扫描耗时诊断](../development.md#扫描耗时诊断)）；输入失败另记事件。这些是按会话保存的有限诊断记录，只保存裁剪与必要上下文，不保存完整帧，不新增事件服务或常驻录像。候选帧和已接纳结果分开，验证用参照物和重叠重见不会制造新访问或重复观测；磁盘写入失败仍按公共停止契约处理。

会话外壳同时保存遍历的号位级结论：每个号位（1–6）的编号、是否完整、失败阶段与原因码，以及排序是否验证；保存范围见[架构 §5 的保存内容](scanner-architecture.md#保存校对与导出)。摘要与通知读取该结论，不直接解析 `observedScope`；旧检查点没有该字段时按 `observedScope.positions` 回读，读不出即无法列出号位。

T3 的独立图片只能验证裁剪和字段。T5 需要初始页面、操作及时间、选中变化、详情到达、滚动和末端的时序资料。合成序列用于验证规则。2026-10-29 的 F1–F7/F4b 已提供 macOS 云客户端的部分现场序列（证据在仓库外的 `~/Library/Logs/Youkai Dev/probes/20261029-f1f7/`），完整扫描验收仍待完成。Windows 本地 1920×1080 的阶段 3 真机结果见 §3，首版三轮整仓对账与其余字段免验结论见 [M4](scanner-implementation-plan.md#首版字段验收决定)。Windows 云客户端随后续版本补做 F8。

| 性能 | 分开记录输入至可核实响应、稳定等待、截图、滚动核对与 OCR 时间；报告每件和整仓时间及停止原因分布。边缘动作或少等几帧的收益不足以抵消漏扫和串盘，公开参考速度不作为本项目成绩。 |

通过有限验收集可以要求没有已知错误，不能承诺未来所有画面自动 100% 正确。真实重复盘与误判旧详情都须保留在验收集中，不能通过删掉困难样本让结果显得更好。

## 7. 成本、可改变结论的证据与后续

工作量归架构“仓库遍历与会话控制”的估算。首版新增成本集中在 Windows 本地客户端的页面测绘、关联与滚动序列标注、重复物品验证；两种云客户端的同类工作随后续版本保留，包括云视频中时序和相似阈值的回归。已确认的手动准备起点减少自动筛选、排序与回顶的操作分支，但范围与顶部的程序核验仍然必需；暂不凭没有样本的界面给精确日数。

最脆弱的前提是：支持的游戏画面能提供足够证据，区分所选物品、列表实际位置与末端。F6 已表明整屏内容不能唯一重定位，F5 表明选中框只在选中格留在视口内时可用；若拖动迟到/惯性使选中格离开视口，而像素、滑块和连续覆盖仍不能恢复唯一位置，当前实现（2026-10-31）把该位置标为不完整、记录原因并继续后续位置；首视口有界重建和缺少跨视口对应证据的边界见 §5。后续可在用户确认下缩窄显示配置或调整交互，不能把无法判定改成成功。客户端范围只能按用户决定调整；用户在 2026-11-03 已决定首版只保留 Windows 本地客户端，其余客户端移入后续版本（见[架构 §6](scanner-architecture.md#6-首版功能范围)）。

单个 Lost 判决也可能是停稳前的动画帧（`s2-21-totop-1→2` 即如此）；本轮已改为在 ScrollBudget 内继续观察，到预算仍无停稳确认才判 Lost。判 Lost 后的页面状态与降级边界见 §5 分类表。回顶的正式证据是滑块起点不变（±2 像素）且仍为 Top；位移判据未决不推翻该证据（2026-10-20 实测轮六位置均为该形态）。5s `ScrollBudget` 与回顶 567 像素 / 150ms 仍待更多实机标定；位置/物品重试次数归阶段 2/5，见[决策 §10](../decisions/2026-10-28-scanner-rearchitecture.md#10-归属阶段的事项)。

## 8. Windows 驱动仓库（单页混排入口，2026-11-22）

本节是 Windows 本地 1920×1080“驱动仓库”入口的权威说明。它与 §1–§7 的旧“驱动盘仓库”入口并列，不替换旧入口；两者共享焦点、遮挡、几何、取消、只读、证据和故障分级规则，但页面、列表结构、号位来源和滚动证据不同。

### 8.1 入口与范围

- **默认入口：** Windows 安装版在没有环境变量时接入 `PageDriveStorage`（驱动仓库）；记录客户端仍为 `windowsLocal`，来源标签明确写出“驱动仓库”。
- **旧入口：** `YOUKAI_GAME_SOURCE=traverse` 继续接入旧的 `WindowsLocalProfileFor` / `PageWarehouse` 转盘入口，包含 `YOUKAI_GAME_CLIENT=local` 与固定目标所需的 `YOUKAI_GAME_EXE`。不要用旧入口的布局或滚动参数推断驱动仓库。
- **支持面：** 只支持 Windows 本地完整客户端、简体中文、窗口/无边框模式、实际客户区 1920×1080。1920×1080 以外的尺寸、Windows 云客户端、macOS 云客户端和其他语言界面均拒绝开始，不做比例缩放或猜测锚点。
- **起点：** 用户手动进入驱动仓库页。扫描器不自动登录、不启动游戏、不从主菜单/其他页面自动导航，也不操作排序控件。安装版默认入口不因目标唯一而自动开始；仍须用户确认目标并点开始。

### 8.2 页面与布局

### 8.3 开始前的准备

驱动仓库没有转盘切换。一次准备只做一次筛选面板访问，然后回顶：

1. 点击漏斗 (148,929) 打开面板；页面判别由两个面板探针、漏斗与详情/列表区域共同确认。
2. 在面板中点击重置 (1431,1028)，以新的稳定面板帧正向确认重置状态：漏斗回到 clear，S 芯片为 clear；旧帧或动作回执不能代替效果。
3. 只点击 S (1425,441)，以新的稳定面板帧确认 S 填充为 active。可见 A/B 邻位必须保持中性暗色；若效果未出现，按位置/会话门禁停止，不叠加点击。
4. 在面板打开时读取“稀有度”排序标签；标签不可读或与“稀有度”模板不匹配即按位置准备失败处理，不猜测升降序，也不操作排序控件。
5. 关闭面板 (148,929)，在新的仓库帧确认同一页面、漏斗 Active、目标范围与列表形状；随后用滚轮向上回顶，直到滑块顶部和列表都稳定不移动。
6. 只有顶部、范围（重置 + S 选择 + 关闭后 Active）、排序标签和页面证据齐备后才建立格位账目；任何一项失败都保留已接纳结果并按位置/会话故障分级停止，不把“看起来在顶部”当成顶部证明。

已标定的颜色与控件样本：关闭页漏斗 active=(13,142,254)、clear=(16,16,16)；面板内漏斗 active=(13,92,167)、clear=(12,12,12)；S 填充 active=(0,139,255)、clear=(28,28,28)；A/B 邻位约 (11,11,11)。面板 S 字形成功覆盖打开、重置、仅选 S 三种状态；仅在选中时字形边缘更亮，因此使用两个字形掩码按前景 F1 判定，而不是把未选中状态当成“无 S”。排序模板复用既有 Windows “稀有度”裁剪 (1285,124)–(1467,201)。

### 8.4 卡片号位、详情号位与接纳

驱动仓库的每张卡左上角有号位徽标；右侧详情在标题后缀显示 `[N]`，并在标题下方重复一个独立号位徽标。遍历层核对卡片徽标与详情独立徽标；标题 `[N]` 是识别侧的独立交叉核对，二者都不能替代另一处：

- 卡片徽标是目标卡号的**主证据**。当前样本中 1–4、6 为数字形状，5 为 S 形状；S 形状映射为号位 5，不能解读为稀有度字母。详情独立徽标使用同一套图标，标题 `[N]` 使用普通数字字体。
- 卡片徽标按前景 F1 在声明的窗口内搜索，允许 1–2 px 的滚动偏移；每个号位保留多个真实状态/列位的掩码。低于分数下限或与次优号位差距不足时分别报未知或冲突，绝不选第一个模板。
- 点击前先核对目标卡：卡片占用、选中框在目标卡、卡片徽标可读且等于当前遍历号位。点击后等待选中框与详情稳定，确认详情属于本次动作：详情独立徽标和卡片徽标一致；任何一处不可读或冲突都停止该号位，不复制上一件结果。标题 `[N]` 由识别侧交叉核对，见下一条。
- 详情比较基线必须使用**本次点击前的稳定帧**，而不是上一个已接纳详情。右栏可能在点击前已经显示一份不同于上次接纳帧的旧详情；若拿旧接纳帧作基线，点击后原样停留的同号位旧详情会被误认为“已变化”。选中卡滚出视口后，旧详情同样可能停在右栏，仅凭同号位或新帧不能归属。
- 补扫的同详情参考往返只从**声明号位内**、占用且号位已知的可见卡中选择参考格；范围外卡不得点击，哪怕它最终不会被接纳。没有可用范围内参考格时按未归属停止，不退化为点击范围外，也不扫描整仓。
- 选中卡滚出视口后，旧详情可能仍然停留在右栏，且旧详情与目标卡可能恰好同号位。此时仅凭“详情号位相同”或“又有新帧”不能证明归属；必须有本次动作后的选中/详情变化、位置对应或完整稳定比较证据。不能把旧详情记给滚出视口的卡。
- 识别侧把名称行 OCR 出的 `[N]` 与遍历确认的卡片号位交叉核对。两者不一致时记录 `slotPositionMismatch`、把槽位置为未知，不选择任一读数；该件进入待校对/失败路径，不能静默保存冲突号位，也不能用 OCR 的 `[N]` 反向覆盖遍历证据。
- 点击与滚轮只落在已标定的卡面、漏斗、面板控件和列表安全区域；不点击底部拆解、锁定/升级/装备、弃置或任何破坏性按钮。扫描期间游戏必须保持前台、未最小化、未遮挡。

### 8.5 滚轮推进、末尾与选中卡滚出

- 采样标定：一个滚轮格约等于一行（约 174 px），可见 4 行中保留 3 行重叠。实现使用 `platform.InputScroll` 的 `WheelSteps=-1` 作为正常前进、`WheelSteps=3` 作为回顶；每次动作仍由前后帧验证实际位移，不按滚轮格数直接推定行数。
- 驱动仓库的 9×4 卡片会重复相同的卡面与等级文本，归一化特征在真实一行位移后仍可能偏好零位移。因此无选中框可用的场景不能只靠像素特征：必须同时满足
  1. 滑块按自身几何移动的行程与声称行数一致（方向与幅度，±20% 容差，且不能同时符合另一个竞争行数）；滑块起点和终点必须同向移动；只有尾边被轨道端点夹住时，单边移动才可作为末端边界例外。只动起边（或只动尾边且不在端点）不证明一行。方向必须按物理符号比较：行前进对应滑块下移，回移对应上移，不能先取绝对值再判幅度；卡片映射与滑块反向时两个证人矛盾，必须保留未决/降级。
  2. 前后视口重叠区域的占用与卡片徽标逐格一一对应，所有重叠占用卡的号位都已知且相同；并且目的格相对点击前必须至少有一个占用/号位变化。重复号位或静止的同号位卡面不能只靠“相同”证明前进了一行。
  两个证人只接受唯一行数；零个或多个候选、目的格无变化、任一徽标未知/冲突、重叠占用不一致或滑块不佐证时，保留最后已证明的账目并停止/降级，不回退到“整屏特征最佳行数”猜一行。驱动仓库始终使用带滑块与徽标证据的匹配器；`YOUKAI_SCROLL_MATCHER=legacy` 不再适用于该页面，避免移动中的滑块被裸 MAD 判成末端静止。
- 选中卡滚出视口是合法状态：没有选中锚点不等于没有移动；只要滑块和徽标重叠证明唯一一行，仍可继续。反过来说，选中框留在视口内也不能阻止对实际滚动的判断；有选中框和无选中框都走同一正向证据：滑块两边同向且方向/幅度符合声明行，卡片徽标重叠给出一致行号。选中位移与滑块/重叠任一矛盾时保留未决，不能靠换到另一分支或零位移相关性放行。
- 顶部复检的点击前帧必须已经在顶部，复检前后滑块两边都要静止（只允许不超过移动下限的测量抖动），并且列表像素必须独立证明零位移；共享 Stationary 的 Undecided/MAD 结果、只有滑块不动或只有顶部位置都不够。从非顶部帧滑入顶部是滚动，不是静止证明。末端复检同样要求滑块两边静止，再额外发一格滚轮确认列表没有继续前进；任一滑块边明显移动或列表位移都使末端不成立。
- 末尾由“滑块到顶/到底 + 最后一格滚轮前后列表与滑块都稳定不移动”确认；样本中额外一格滚轮后最后一行和滑块保持不变。底行 1 个占用卡 + 8 个空位时，空位是已观察的真实空格，不是漏读，也不进入物品计数。
- 不把页面计数、OCR 件数、旧详情或“看起来没有变化”单独作为末尾或覆盖完整证据。

### 8.6 账目、补扫与覆盖

- 一次驱动仓库扫描是**一遍按出现顺序的连续遍历**；所有六种号位混在同一列表，每张占用卡以卡片徽标记录其号位。格位账目保留绝对行、列、首次观测帧、状态、号位和可用的接纳序号。
- 只有以下证据同时成立，才把这次遍历的格位映射到现有六份号位账目：范围已证明、顶部与末端已证明、完整连续的混排遍历、重叠逐格对应、每个已见占用格有结局、真实空格已记录。缺一项都不能把“某号位”标成完整；失败时保留已接纳物品并报告 `partial`。
- 范围限定补扫仍遍历整个混排视口并在每个已见卡上读取号位；只接纳声明号位内的卡，其他号位只记为 `outOfScope`，不点击、不接纳、不计数。它不能静默退化为整仓扫描，也不能把“六份号位账目都有条目”当成整仓 `complete`：整体覆盖固定为 `partial`，除非另有完整范围会话。补扫、记录重开、逐件校对和合并回原记录沿用 [T6](t6-review-export-workflow.md#补扫不完整号位p-12-第一步)；JSON/CSV v2 字段与列序不变。保存的格位账目还保留真实空格（报告状态 `empty`）和其他号位的 `outOfScope` 条目，便于复核空号位与跳过依据；这些条目不增加 `visits`，也不进入公共物品计数。空格也必须带自己的绝对行、列和首次观测帧，不能把未赋值的 `(0,0)/frame 0` 当成所有空格的共同身份。
- 全局失败（页面离开、失焦、遮挡、几何/权限/采集流变化、筛选或排序变化、取消、存储/运行库故障）停止整次并保留已接纳结果；已识别的位置范围内不要用未证明的剩余行补成完整。旧记录的可读性、修订、证据与导出行为不因新入口改变。
- 准备完成后的每一帧仍受范围监控：列表页从 `Active` 变 `Clear` 即停止；打开面板后，任一后续面板帧必须继续命中“稀有度”模板，且面板内的 S 必须仍为 `Active`（`Clear`、未知或不可读都不能沿用旧范围证明），模板失配、标签变化或 S 变化即停止，详情等待也不能跳过这些面板帧。不能用旧的 `range.verified` 覆盖后来发生的筛选/排序变化。

### 8.7 证据、回放与未覆盖项

驱动仓库的页面、面板、卡片/详情徽标裁剪来自 2026-11-22 的私有 1080p 手工样本；原始整帧和附件包不入库，仓库只保留二进制字形掩码、布局常量和无样本单测。当前私有回放（`YOUKAI_STORAGE_SAMPLES` 指向样本目录）和公开的脚本化入口测试已覆盖：

- 初始/顶部、单行滚轮后、底部、底部复检四类列表帧；顶部与单行后的 36 个混排号位全部可读，单行滚动由滑块行程和卡片徽标重叠验证为 1 行；底部最后一行为 1 个占用卡 + 8 个空位。
- 六份详情裁剪的独立号位；面板打开、重置、仅选 S、排序“稀有度”四种状态；把单行后的卡片号位窗口遮黑的对照帧返回 Undecided，未回退到重复卡面的整屏特征。
- 页面标题、漏斗、选中框、占用条、管理锁和滚动条端点。
- 一条通过真实 `Inventory`/扫描内核的脚本化动作序列：从中段回顶（两次正向滚轮，刻度分别为 `3`）、两次连续推进（`-1`）、独立末页复检（第三次 `-1`）、54 件逐件归属与完整覆盖；动作断言精确到 4 次面板点击、53 次卡片点击、全部滚轮刻度与落点，并用接纳帧 ID 读取该帧的实际选中卡、右栏详情和保存图像，核对逐件唯一身份及详情归属。另一条只补扫 3 号位，断言始终不点击其他号位、覆盖保持 `partial`，并保存 45 个 `outOfScope` 与 9 个接纳格；同号位同详情且唯一可用参考在范围外时，流程在参考归属前停止且不点击范围外卡。匹配器由脚本化页面证据提供；像素匹配由独立回放覆盖，脚本不冒充真机。
- 私有裁剪的原始单行对照通过；只改三处选中框探针使选中框按正确方向留在视口后，同一裁剪仍必须接受一行。选中框与滑块反向的合成帧、以及顶部 Undecided 列表的合成帧必须拒绝。测试核对的是接纳帧而非同一赋值路径；临时把转场接纳改成点击前图像+帧 ID 时，全扫和补扫用例必须失败，变异不提交。

仍未由这批样本覆盖、不能写成已支持：全空列表、相邻且详情完全相同的驱动盘、完整库存与计数的逐件对账、3 副词条详情、未锁定/已弃置卡、粉色头像之外的装备状态、真实像素回放中的回顶滚轮完整动作序列、其他显示尺寸或客户端、以及 Windows 真机字段验收。页面可见计数只作界面观察，不与本次 S 范围对账。这些缺口的处理保持保守：未知即未知，冲突即停止或待校对，不以总数或旧详情补成完整。
