## 1. 推荐路径与范围

采用已获认可的方向：首版使用单个内置 ZZZ 适配器，用户打开驱动盘仓库，程序核验页面与范围，在经过测绘的区域逐件选择；小步滚动时保留前后重叠，确认实际位置后再继续。一次只推进一个已核实的动作，OCR 在已保存的截图上并行处理。三种客户端使用相同的证据规则，各自保存布局和时序参数；出现实际行为差异再分支，不预先维护三套遍历器或配置语言。

**页面结构（macOS 云客户端实测，2026-10-19）：**驱动盘仓库按**转盘位置 × 位置内列表**两层组织——右侧六槽转盘选择位置（编号从左上起逆时针 1–6），左侧列表只显示当前位置的盘（[1] 号位实测 24 行 ≈ 96 件，其他位置未做全量遍历）；当前装备的盘始终置顶（筛选下也是），弃置盘默认排在末尾。遍历因此是两层循环：外层逐位置（转盘切换 + 每位置的重置/回顶准备，见 §3），内层按本节的列表滚动与选择推进。切换转盘位置时未观察到自动带出筛选，但筛选状态跨位置、跨会话保留，每位置都必须重新核验。**4b-2 实现顺序：**外层按 1→6 推进；每个位置先等仓库页稳定，若转盘不在目标位则点击该位并有界等待选中环；然后打开筛选面板→重置→勾选 S 稀有度→关闭→要求漏斗为 Active（S 未生效即停止；重置与 S 共用这一次面板访问，旧筛选是否清除并入该证据，见 §3 的残余风险）；随后用 `TopFrom→TopTo` 向顶部甩动直到滑块顶判据成立（每次甩动须使滑块起点上移，连续 2 次无进展或超过 16 次停止），到顶后再向顶拖一次：正式顶部证据为滑块起点不变（±2 像素）且仍为 Top；Stationary 只作辅助信号，不单独作为正式验收依据（2026-10-20 冻结）。最后清空本位置的 visited/viewport 并从 0 开始内层遍历。S 选中态尚无像素探针；日常流程仍只做一次面板访问，并在关闭后校验 Active，旧筛选残留是已知残余风险。正式验收恢复独立 Clear 校验；日常探针失败时，只在验收流程中二次打开面板确认，产品流程不自动补开。任一校验失败即停止并保留已接纳结果，不做补偿动作（用户 2026-10-19/20 决定）。

**单页结构（4b-1 实现）：**列表、详情与转盘共享一帧，详情不是独立页面；一次访问 = 点击目标 → 同页等待选中框与详情内容变化 → 稳定 → 接纳，没有“关闭详情”步骤。页面判别由两个面板探针（红/白面板色 vs 列表暗色）、漏斗像素与转盘选中弧共同完成；像素匹配器只读取 `Layout.ReadRegions` 声明的区域（`TestPixelMatcherReadsOnlyDeclaredRegions` 随机化区域外像素后要求判定完全不变）。滚动到末端后不再以“滚动条到底”单独结束；底端由两种独立证据之一确认：最后一步位移不足一个完整步进（4 行），或再拖一次为 Stationary。

客户端、实体与字段范围见[架构第 6 节](scanner-architecture.md#6-首版功能范围)。首版采用有限显示配置，布局按 [T2 的尺寸候选](t2-platform-capture-input.md#32-可验收的窄显示配置候选)分别测绘，不预先建设任意尺寸布局系统。

**操作起点（用户 2026-10-16 确认“按你的设计”；2026-10-19 实测轮与 4b-2 决定补充）：** 用户只需打开驱动盘仓库并保持受支持的显示配置；点击开始后，扫描器先解析并锁定游戏窗口，未运行或没有合格窗口立即停止，已打开则自动把游戏应用切到前台一次（扫描期间失焦仍停止），再在预检通过后自动按位置完成转盘切换、打开筛选面板→重置→勾选 S→关闭并校验 Active、回顶，之后开始遍历。不把用户声明直接当作页面已满足条件，也不包含登录、启动游戏或从任意游戏页面自动导航；从待机/主菜单自动打开仓库页尚未实现，当前仍需用户手动进入仓库页。实测轮已确认：存在可用的筛选面板（套装、状态、主属性词条）与可重复执行、结果固定的重置；漏斗图标颜色（蓝=有筛选 / 暗=无，帧像素判据见报告 §4）是低成本预检/重置校验信号；默认“稀有度”排序下重置不恢复排序，扫描不能假设固定顺序，也不操作排序控件。排序采用严格方案：先读取并验证排序标签；未验证时 coverage 只能 `partial`/`unknown`，不得声称 `complete`。**面板确有稀有度 S/A/B 控件：**证据是 `/tmp/m2-samples/s2-02-panel-slot1-after-reset/frame-0001.png` 约 (1225,615) 的白色 S 片；A/B 徽章与选中态尚无样本。按用户 2026-10-19 决定，每位置重置后勾选 S，只显示/接纳 S；A/B 不进入列表、不录入。重置与 S 共用一次面板访问：关闭后要求 Active（否则筛选未生效）；S 选中态尚无像素探针，旧筛选是否清除并入同一次校验。日常流程保持一次面板访问；正式验收另做独立 Clear 校验，日常探针失败时才在验收流程中二次打开面板确认。任一校验失败都停止并保留已接纳结果，不猜测、不继续。

本轮不实现 A/B 徽章的像素分类（4b-3 不做）：S 筛选使 A/B 不进入列表；若筛选失效则停止而不是尝试分辨品质。选中态像素探针待实机补样本后再加入；在此之前不以“点过 S 控件”代替漏斗与徽章的观测证据，也不新增让用户选择的扫描模式。

| 范围 | 记录品质及所有会限制库存的筛选，包括套装、槽位、等级、锁定、弃置、装备等实际存在的条件。若目标是全部 S 级，其他筛选不能排除其中物品；不能只看到 S 级标签就宣称整仓。无法观察的隐藏筛选须通过已验证的重置方式排除，否则拒绝开始。（macOS 实测：默认视图 ≠ 无筛选，接手时可能残留套装/状态筛选；重置行为经用户确认——面板“重置”可重复执行、结果固定。4b-2 日常流程在每个位置执行一次面板访问：打开→重置→勾选 S→关闭并要求漏斗 Active。S 选中态尚无像素探针，日常流程仍只做一次面板访问并在关闭后校验 Active，旧筛选是否清除并入同一次校验；旧筛选残留是已知残余风险。正式验收恢复独立 Clear 校验，日常探针失败时只在验收流程中二次打开面板。失败即停止并保留已接纳结果，避免 S 筛选未生效时录入 A/B。判据与像素值见[实测报告 §4](../reports/2026-10-19-m2-macos-sample-round.md#4-筛选行为发现t5-遍历设计输入)。） |
| 顺序 | 固定并记录一种经验证的游戏排序及方向，扫描期间不改排序、筛选或物品状态。无需新增扫描器排序算法，也不假定 UI 排序有稳定的内部物品 ID。（macOS 实测：默认“稀有度”排序下弃置盘排末尾、当前装备盘置顶；**重置不恢复排序**——用户确认，扫描不能假设固定顺序，也不操作排序控件。排序采用严格方案：先读取并验证排序标签，未验证时 coverage 只能 `partial`/`unknown`，不得声称 `complete`；遍历只依赖位移对应与位置账目。**已实现：**筛选面板排序区域 `(1100,205)-(1260,275)` 与内置“稀有度”参考模板做灰度 MAD 匹配（阈值 5.0；三张面板样本间 MAD ≤0.02，1164×762 实时窗口帧归一到标定流后 2.76，偏 10 像素的候选 ≥16.5）；每次打开面板都检查，任一次不匹配即保持 `sort:"unverified"`。当前只验证这一个已标定标签，不对任意排序文字做 OCR，也不操作排序控件；换排序后扫描会安全地保持未验证而不是猜标签。**方向边界：**探针不读取升降序方向；方向变化不会被视为排序变化，`sort:"verified"` 与 `coverage:"complete"` 均不声称方向已验证。） |
| 起点 | 必须有可见的顶部依据，或在已获确认的自动准备流程中取得回顶证据。“向上滚动很多次”与画面不再变化都不能单独证明顶部。开始于列表中部时不能标为整仓扫描。（macOS 实测：重置/关闭面板后列表会滚到当前选中盘的位置而非顶部，起点必须重新取得；4b-2 每位置用 `TopFrom→TopTo` 甩动到滑块顶判据，要求滑块起点持续上移，最后再拖一次取得“滑块起点不变（±2 像素）且仍为 Top”的正式确认；Stationary 仅作辅助。连续 2 次无进展或超过 16 次停止。） |
| 数量 | 核实计数标签究竟表示全部库存、筛选后结果还是容量上限。只有与当前遍历范围对应且可可靠读取的数才作预期数量；混合列表总数不冒充 S 级总数。数量未知保持未知，不能用手填数字补成已验证数量。 |
| 可操作位置 | 测绘格位边界、可完整显示的行、选中标记、滚动条及详情区域；记录点击哪些行会自动滚动。只在已验证的稳定区域选择物品，顶部、底部及不足一屏分别验收。 |

预检保留一份范围与布局快照。筛选、排序、库存数量或布局在运行中发生可观察变化时，停止本次扫描并撤销原来的整仓结论。视觉扫描不能证明游戏库存从未在不可见处改变，结果仍是声明条件下的观测。

## 4. 一件物品何时可以进入识别队列

一次选择包括动作前画面、目标格位、输入结果和动作后画面。控制者先取得队列容量并重查平台条件，再发一次短点击；接纳截图前必须满足以下条件：

1. 列表仍属于同一范围，目标格位有物品且位置可对应。选中标记位于该目标，必要时核对先前选中标记已离开；不能用鼠标位置代替游戏内选中状态。
2. 详情区域完整可见，必需字段布局已结束过渡；使用文字和图标区域的稳定性，排除背景动画、鼠标和云客户端提示造成的假变化。稳定画面本身不证明是新物品。
3. 选中与详情之间有经过样本验证的关联证据。先核对格位与详情共同可见的套装、槽位、等级等特征，再结合动作后的内容变化或就绪信号；特征一致仅作支持，因为不同物品可以相同。不能只用固定延时、模型高分或新的采集时间戳接纳旧详情。
4. 当前截图及其区域仍属于同一窗口、几何和采集流。满足归属条件后才按公共契约接纳一次观测；导航尝试与用于核对的截图不另算一张盘。

首次读取已经选中的物品没有上一件详情可比较，需单独验证初始选中与完整页面的稳定状态。不能强制要求每一件文字都发生变化，否则一件库存和相同物品无法处理；也不能因此对后续物品放宽旧详情检查。

**准备前提（4b-2）：**本节的接纳循环只在该位置的筛选准备完成后开始：日常流程打开面板→重置→勾选 S→关闭，漏斗为 Active 才继续；正式验收另做独立 Clear 校验，日常探针失败时才在验收流程中二次打开面板。S 控件选中态尚无像素探针，旧筛选是否清除并入同一次 Active 校验；旧筛选残留是已知残余风险。失败即停止并保留已接纳结果。

**4b-1 标定结果（macOS 云客户端，1920×1080；证据见报告 §6/§7 与 `internal/game/zzz/collect/testdata/maccloud/manifest.tsv`）：**详情行固定矩形与识别裁剪同一标定（name/level/main/sub1–sub4）。七行灰度 MAD 的同内容对（每个证据目录的 frame-0000/0001，n=236）最大 1.01、p95 0.88；六组完整视口内正交相邻格对（n=186）中 183 对 >4.0（最小 4.07），2 对 <2.0（0.42、0.62），1 对在带内（2.38）。3.72 那对是**对角非相邻**（s6 r3c3→r4c0），不属于相邻对统计。没有任何同内容对超过 2.0，因此 2.0/4.0 不会造成误接纳；低 MAD 的相邻对只会以 `detailUnattributed` 安全停止（相邻同详情的参照往返已实现；真实重复盘样本与最终阈值仍待验收）。S 徽章金色像素 251–256（面板遮罩帧 0），判据 ≥150；第四副词条数值列墨迹 0–21（3 条）对 132–426（4 条），判据 ≤50 / ≥80。像素匹配器只返回 S 或未知；A/B 徽章分类（4b-3）未实现，S 筛选失效时停止而不是猜测品质。

**归属规则（单页）：**点击前目标必须已有选中框并且占用；点击后选中框必须到目标，详情先在连续 `StableFrames` 帧内保持同一内容并跨过 `DetailStableSpan`（默认 200ms，实测详情在 374–415ms 稳定），再拿这个**稳定画面**与基线比较：`Different` 才按 `transitionVerified` 接纳，`Same` 则进入相邻同详情的参照往返。过渡动画中的单帧 `Different` 不作为已变化证据，否则相同内容的相邻盘会被误判为普通切换并跳过参照核验。基线取该位置上一件已接纳的详情；位置首件尚无已接纳详情时回退到点击前帧。首件若已选中（初始读取）不要求内容变化，但必须从首个可判定详情起保持稳定。选中框动了而稳定画面始终 `Same` 且无法完成参照核验时停止并报 `detailUnattributed`；相邻同详情的参照往返已实现，真实重复盘样本与最终阈值仍待验收。规则上相邻且详情完全相同的 S 盘各算一件，无法完成参照核验时停止并保留未解决位置，不能合并、丢弃或按属性去重。详情可判定但条数不明时报 `detailUnresolved`；已接纳截图的投影或入队失败报 `evidenceFailed`。这些情况都保留位置未解决，不跳到下一件。

**相邻相同详情：**如果该布局有独立、经过验证的选中和详情就绪证据，可保留两次不同位置的观测；两件 S 盘各算一件，永不按属性或图像哈希去重。如果只能看到高亮移动而无法排除旧详情，候选做法是在同一可操作区域选择一件已知且可区分的物品，确认其详情后再回到目标，取得关联证据；每一步都等待自己的结果，最多做一轮，不把它当成超时后的重复点击。找不到可用参照或仍不明确时停止并保存诊断，不能复制上一件结果。**该参照往返已实现；真实重复盘样本与最终阈值仍待验收**；此限制必须纳入重复物品验收；无法通过时仍是适配缺口，不宣布已支持。

等待详情时可在截止时间内重新观察，不因到期而盲目补点。首次动作效果尚不明确时，不发送验证用的下一次动作。完成有界观察及符合前述条件的参照核验后，仍无法确认详情归属时停止本次采集，按未解决位置记账，不跳到下一件。超时时间、稳定采样跨度与相似阈值来自三种场景的调参资料，并用未参与调整的序列验收；两张相同帧或等待某个毫秒数都不是普遍正确性保证。

管理状态与装备从同一次已确认归属的详情和列表格读取，并保留对应裁剪。管理状态以列表盘格右下角角标为主：红色垃圾桶为 `discarded`，灰色锁为 `locked`，无图标为 `none`；顶部“拆解”左侧指示只确认锁定/未锁定维度，不能区分弃置与无标记，弃置/无标记仍由列表角标区分。列表与顶部在锁定维度冲突或任一不可读时记 `null`，不填 `none`。锁定角标带有闪光动画，单帧可能漏检；多帧采样与颜色加形状分类是 PR 6a 的待验证项，不能写成已确认可靠。

装备以详情页等级右侧头像判断“已装备”并做身份匹配，列表格右上角头像用于确认；冲突或不可读时整个 `equipped` 记 `null`。当前代理人装备和他人装备都属于 `equipped`，当前装备置顶只影响遍历顺序。代理人身份使用 fairy 数值 ID（例如耀嘉音 `1311`）。fairy 的 `partnerInfo.iconPath` 有 57/60 个 `IconRoleCircle` 圆形头像，缺失 3 个（`1381`、`1531`、`1551`）；实拍一致性与缺失头像的处理待 PR 6b 验证，不能写成已完成。扫描不点击状态切换按钮。

## 5. 滚动衔接、重复物品与末尾

维护当前已确认的格位顺序和未访问位置，列表内容只用于辅助匹配。每次推进前保存可比较的重叠区域；短滚动后重新测量格位，用多处共同特征和实际位移关联前后位置。至少保留一整行可用重叠作为起始候选，实际需要多少由布局与重复物品样本决定。无需每次都对整屏物品做 OCR。

**滚动动作标定（macOS 云客户端实测，2026-10-19）：**列表滚动按整行吸附（实测行距 147 帧像素；慢拖基本 1:1 后吸附，快甩有惯性多滚 1 行以上）。已验证步进：**413 点拖拽 / 1000–1200ms = 精确 4 行**（两种时长均实测 3/3 精确；更短时长的拖拽无已保存的位移证据，不做结论，正式版以每步位移校验兜底），每步用列表区位移测量校验（588 帧像素 = 正常 4 行，< 588 = 已到底）。**顶/底判据：再拖一次，前后帧列表区误差 < 4（内容移动时帧间误差约 6–7）**。4b-2 另接受最后一步位移不足整步作为底端独立证据。拖拽停稳以实现中的“相对 candidate 连续观测不变”判据为准，`ScrollBudget` 默认 3s 为待实机标定的初值。点击到详情稳定实测 374–415ms，推算每件约 0.5s、每位置约 1 分钟、全程约 6 分钟（推算值）。完整标定表与证据目录见[实测报告 §5](../reports/2026-10-19-m2-macos-sample-round.md#5-滚动与时延标定)。

**4b-1 滚动证据（像素匹配器）：**`ListViewport` 为 60,195–512,930，灰度采样步长 x=3、y=2。零位移误差 <4 判 Stationary；否则在 ±720 帧像素内搜索整行位移（行距 147，容差 ±3），最佳误差 ≤10 且比零位移低 ≥3 才判 Displaced；不满足且零位移误差 ≥10 判 Lost。搜索要求至少保留一行（147−3 帧像素）重叠——否则边缘 27 像素的相同黑边会在误差 0 处伪造位移（4 行步进的记录帧对曾出现该假匹配，已由最小重叠约束排除）。滚动条判据：`ScrollTrack` x=47、y=220–904，取亮度 >110 的最长连续段；Top = 起点 ≤229，Bottom = 终点 ≥898。顶端必须配一次“再拖一次”的正式确认：滑块起点不变（±2 像素）且仍为 Top；Stationary 只作辅助信号（实时动画/回弹下像素判据常未决，2026-10-20 冻结）；底端由“滑块 Bottom + 最后一步位移不足整步”或“Bottom + Stationary”之一确认（短列表的滑块可同时满足 Top 与 Bottom，`s2-04` 即如此）。

实测帧对：`s1-step-1→2/2→3/3→4` = 4 行（误差 6.9–7.2），`s1-step-4→5` = 3 行（9.7），`s1-step-5→6` = Stationary（2.0），`totop-2→3` = 3 行向上（7.0），`totop-3→4` = Stationary（1.5）；`totop-1→2` 零位移误差 13.3 且无可对齐整行位移，判 Lost（见报告 §5 的帧对更正）。`s2-70-unlocked-equipped` 的漏斗为 Active，与“只有 n5/n6/d1 带筛选”的初稿假设不同——筛选状态跨采集保留，预检必须逐次读漏斗，不能按样本组推断。

**4b-2 实现状态：**遍历已是位置×列表两层循环。日常流程每位置自动执行转盘切换、一次筛选准备（打开→重置→勾选 S→关闭校验 Active）、回顶（失败即停，保留已接纳结果）；正式验收另做独立 Clear 校验。回顶正式确认使用“滑块起点不变（±2 像素）且仍为 Top”（2026-10-20 实测轮：六个位置的确认像素判据均为 undecided，滑块始终保持在 Top，扫描正常完成 995 件），Stationary 只作辅助。`visited` 与 `viewport` 每位置重置，`viewportIndex` 在每个位置内重新从 0 计数。末端接受两种独立证据之一：滑块 Bottom 且最后一步位移小于一个完整步进（4 行），或 Bottom 后再拖一次为 Stationary；空列表以“20 格全空、滑块铺满全轨、再拖一次 Stationary”正常完成 0 件。拖拽参数为 1000ms、10 步；`ScrollBudget` 默认 3s（初值，待实机标定）与回顶 567 像素 / 150ms 仍是待实机标定的初值。**滚动提交规则：**第一个相对拖拽前帧的 Displaced+Matches 只作为 candidate；后续 fresh 帧相对 candidate 为 Stationary 才接受该 candidate，若相对拖拽前帧仍是 Displaced+Matches 则把 candidate 更新到最新总位移（rows/matches 必须一致）。总位移变成 Lost、或到 ScrollBudget 仍无停稳确认时返回 Lost，安全停止且不提交 `visited`/`viewport`；无 candidate 时 Stationary 仍是到预算结束的判定，不早退。`MatchScroll` 的 Lost 不再即时终止（可能只是停稳前动画帧），但到预算仍无确认时停止（T5 §7）。回顶甩动期间 Lost 仍按现有策略允许：本位置尚无访问记录，Lost 视为已移动并继续，下一次甩动重新建立基准。滚动步进仍由匹配器验证实际位移，不按拖拽时长推定行数；`applyTransition` 仍只接受唯一、完整、一一对应的 correspondence，并保留至少一行重叠。每次成功滚动记录 before/after frame id、rows、matches 数量与 matcher evidence，由下一个接纳件以 `scrollEvidence` 带出一次。

| 情况 | 建议规则 |
| --- | --- |
| 前后位置唯一对应 | 仅在已证明的对应关系上移动当前位置，已经访问的重叠格位不再次接纳；新出现的位置按顺序处理。不根据滚轮刻度、滚动时长或“图变了”推定前进一行。 |
| 同一行多张盘或整行内容相同 | 属性与图像哈希不能充当实例身份。可结合滚动过程中的可测运动、格位边界、选中位置及滚动条辅助核对；滚动条单独只能表明大致进度，不能给出精确行号。存在多个可能对应关系时不任选一个。 |
| 边缘点击意外带动列表 | 当前坐标对应立即失效；只有布局已明确描述并验证该行为，且取得新的位置对应时才能继续。不能把旧格位坐标下的详情直接记给原目标。首选通过稳定区域选择减少这种情况。 |
| 一次移动太远、丢失重叠或画面模糊 | 在期限内继续观察；不能恢复唯一位置时停止，不猜测跳过了几行，不反向乱滚寻找看似相同的物品。已核实结果保留为部分结果。 |
| 空格与尾行 | 依据物品格位的占用证据识别尾行，不点击所有预设列后再删除相同结果。真实相同盘各自保留，空格不产生物品记录。 |

宣布全部覆盖，必须同时满足：起点与范围已核验；排序标签已读取并验证；准备阶段已由 Active 漏斗与 S 徽章证明 S 生效，正式验收另有独立 Clear 证据（日常流程仍保持一次面板访问，见 §3）；每次移动连续且无无法解释的跳跃；范围内所有占用位置已访问且 S 级详情均已接纳；相邻且详情完全相同的 S 盘各自接纳；末端有独立的底部/列表结束证据；若存在可信的同范围计数，与遍历账目一致。排序标签未验证时只能声明部分或无法确认；OCR 是否成功另行报告，不能用可用结果数量证明走完列表。

**覆盖账目（已实现）：**`observedScope` 在预检后与 Collect 结束后各上报一次，携带 `sort`、`sortLabel`、`coverage` 与逐位置 `positions`（position、viewports、visits、topVerified、bottomVerified、complete）。`coverage` 只有在六个位置全部 `complete`、每个位置的顶部与底部证据都成立、且所有已打开面板的排序标签均验证时才是 `complete`；有账目但不满足时为 `partial`，没有位置账目时为 `unknown`。`expectedCount` 仍不由遍历推断。停止或故障时保留当前未完成位置的账目，供结果层如实判为部分覆盖。

**2026-10-20 现场复跑：**位置 1 的筛选面板在真实《云·绝区零》窗口上读出 `sort:"verified"`、`sortLabel:"稀有度"`，模板探针不只对 M2 样本成立。随后一次干净运行（15:27–15:43）完成六位置：1,005 件采集、1,005 件产出、0 未处理；`coverage:"complete"`，位置 1–6 均为 `complete:true`、`topVerified:true`、`bottomVerified:true`，视口数依次 6/7/7/14/16/14，访问数 97/114/104/225/249/216，排序始终为已验证的“稀有度”。该验证只覆盖标签，不读取升降序方向。同日更早一次运行在位置 1 第 3 视口、48 次访问后因 Lucia 抢占前台报 `focusLost`，覆盖正确保持 `partial`，保留了失败路径的现场证据。

末端证据优先研究滚动条触底、列表尾部结构与最后占用格位，具体信号必须由当前布局样本验证。滚动后无变化、详情重复、OCR 数量达到估计值，都不能单独作结束条件。没有独立末端证据时保留部分或无法确认，不能为了自动结束而降低标准。

空库存必须由支持范围内明确的空列表状态证明；只有空白截图或计数 OCR 为零时不成功。单件、不足一行、整屏恰好填满、最后一行缺列和全部物品内容相同分别处理，不把它们视为普通多页的缩小版。锁定、弃置和已装备盘若属于声明范围，也必须各自覆盖。

## 6. 保存什么证据，怎样验收

每件保留公共契约要求的详情图和字段来源，另附目标格位、对应的导航步骤与接纳理由。每件 `capture` 带 `rarityFilter:"S"`（准备阶段已确认重置并勾选 S 后 Active），可选带一次性的 `scrollEvidence`（记录进入该视口的最近一次已核实位移：前后 frame id、rows、matches 数量与 matcher evidence），同一视口不重复。按 §5 的账目规则记录每个新访问位置的 S 级接纳或未解决结局；A/B 不进入列表、不产生跳过记录，S 筛选失效才是预期停止项。保留滚动前后裁剪与位置对应；输入失败另记事件。这些是按会话保存的有限诊断记录，只保存裁剪与必要上下文，不保存完整帧，不新增事件服务或常驻录像。候选帧和已接纳结果分开，验证用参照物和重叠重见不会制造新访问或重复观测；磁盘写入失败仍按公共停止契约处理。

T3 的独立图片只能验证裁剪和字段。T5 需要带顺序的资料：初始页面、操作及其时间、选中变化、详情到达、滚动和末端。合成序列可检验规则；真实游戏和云视频行为仍须在获相应授权后取得，当前没有样本或采集授权。

| 验收层 | 必须覆盖与通过条件 |
| --- | --- |
| 离线规则与序列回放 | 点击未生效、高亮先变而详情迟到、旧详情清晰且可 OCR、首件与相同相邻盘、整行相同、空格保留旧详情、分数行移动、多行跳跃、S 筛选未生效/面板意外关闭、惯性继续移动后停稳、位移到预算仍不停稳、排序或筛选变化、断流画面重复、底部与中途冻结。另覆盖独立 Clear 校验与日常一次面板访问的差异、排序标签缺失或不可读、锁定角标闪光造成的单帧漏检、相邻同详情双盘。预期不明确的序列应停止，不能输出全量成功；不凭脚本预设位置证明图像判断正确。 |
| 标注与独立验收 | 人工标注每一步应选中哪个位置、哪些帧仍是旧详情、实际位移与是否到底。调参和验收按完整扫描序列划分，同一次扫描的相邻帧不得跨组；同库存关联遵循 [T3 划分规则](t3-ocr-runtime-model-samples.md#收集标注与划分)。 |
| 三种客户端实机 | 按[架构整仓验收](scanner-architecture.md#两平台游戏与安装验收)分别做至少三次人工基准库存扫描；逐出现次数、位置和字段核对，无已知漏扫、重扫、详情错配或提前完整。空仓、单件、相同盘、跨屏重叠、末行以及管理状态分别覆盖；缺失样本的情形标未验证。相邻同详情双盘必须各自出现并各计一件，不得按属性合并。 |
| 管理状态与装备 | 盘格右下角角标与顶部“拆解”左侧指示在锁定维度的一致性；详情等级右侧头像与列表格右上角头像的一致性；三态管理状态、装备与未装备、当前装备与他人装备分别覆盖。顶部不能区分弃置与无标记，弃置/无标记以列表角标为准。冲突或不可读必须记 `null`，不能落成 `none` 或未装备。锁定角标闪光下的多帧采样与颜色加形状分类、代理人头像实拍一致性分别按 PR 6a/6b 的验证结果判定，未通过前不宣称可靠。 |
| 异常与结束 | 云延迟、画质变化、连接页面、失焦、遮挡、取消和队列背压分别验证。导航失配关闭输入并保留已接纳结果；恢复焦点或连接不自动续扫；正常结束后的剩余 OCR、保存和导出仍按 T4/T6 验收。 |
| 性能 | 分开记录输入至可核实响应、稳定等待、截图、滚动核对与 OCR 时间；报告每件和整仓时间及停止原因分布。边缘动作或少等几帧的收益不足以抵消漏扫和串盘，公开参考速度不作为本项目成绩。 |

通过有限验收集可以要求没有已知错误，不能承诺未来所有画面自动 100% 正确。真实重复盘与误判旧详情都须保留在验收集中，不能通过删掉困难样本让结果显得更好。

## 7. 成本、可改变结论的证据与后续

工作量归架构“仓库遍历与会话控制”的估算。新增成本集中在三种场景的页面测绘、关联与滚动序列标注、重复物品验证，以及云视频中时序和相似阈值的回归。已确认的手动准备起点减少自动筛选、排序与回顶的操作分支，但范围与顶部的程序核验仍然必需；暂不凭没有样本的界面给精确日数。

最脆弱的前提是：支持的游戏画面能提供足够证据，区分所选物品、列表实际位置与末端。若重复列表没有可判别的位置线索，或云客户端的高亮与详情长期无法关联，当前方案应停止并报告适配缺口；后续可在用户确认下缩窄显示配置或调整交互，不能自行删掉已确认的客户端，也不能把无法判定改成成功。

单个 Lost 判决也可能是停稳前的动画帧（`s2-21-totop-1→2` 即如此）；本轮已改为在 ScrollBudget 内继续观察，到预算仍无停稳确认才判 Lost。回顶的正式证据是滑块起点不变（±2 像素）且仍为 Top；位移判据未决不推翻该证据（2026-10-20 实测轮六位置均为该形态）。3s 预算与回顶 567 像素 / 150ms 仍待实机标定。
