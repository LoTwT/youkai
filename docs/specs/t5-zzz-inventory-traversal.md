# T5：绝区零仓库遍历与详情归属

更新日期：2026-10-16。状态：用户已认可本轮推荐设计与手动准备起点；具体视觉参数、当前页面证据和工程验收尚未完成，应用实施仍未授权。本文维护 ZZZ 页面的预检、选中、滚动和结束证据；公共生命周期、结果标识、保存与导出由[架构第 5 节](scanner-architecture.md#5-扫描会话与结果语义)维护，字段与实体范围由[第 6 节](scanner-architecture.md#6-首版功能范围建议)维护。

## 1. 推荐路径与范围

采用本轮获认可的方向：首版使用单个内置 ZZZ 适配器，用户打开驱动盘仓库，程序核验页面与范围，在经过测绘的区域逐件选择；小步滚动时保留前后重叠，确认实际位置后再继续。一次只推进一个已核实的动作，OCR 在已保存的截图上并行处理。三种客户端使用相同的证据规则，各自保存布局和时序参数；出现实际行为差异再分支，不预先维护三套遍历器或配置语言。

已确认的范围是 Windows 完整客户端、Windows 官方云客户端和 macOS App Store 云客户端，只支持 S 级驱动盘，锁定必需，装备代理人与弃置按可行即纳入推进。用户已进一步确认简体中文、六个槽位、0 至 15 级、固定资料版本全部套装以及已装备和未装备的盘，统一见[主控范围](scanner-architecture.md#6-首版功能范围建议)。首版采用有限显示配置，具体布局仍按 [T2 的尺寸候选](t2-platform-capture-input.md#32-可验收的窄显示配置候选)分别测绘；后续逐组扩展游戏内置尺寸，不预先建设任意尺寸布局系统。扫描时游戏前台、停止后校对、异常后不自动续扫继续适用。

2026-10-16，用户在本轮方案与操作起点选择后回复“按你的设计”。按推荐方案确定：用户先打开驱动盘仓库，并按已支持布局的提示完成筛选、排序和回到顶部，扫描器负责核验后自动遍历；首版不自动完成这组准备操作。不把用户声明直接当作页面已满足条件，也不包含登录、启动游戏或从任意游戏页面自动导航。是否存在可用的 S 级筛选控件、排序的实际名称及如何证明顶部，均未取得当前客户端样本；接受设计不等于这些控件已验证。

如果游戏可明确筛选 S 级，优先在核验后的 S 级列表中遍历；如果无法按品质筛选，同一遍历路径可以访问混合品质列表，只为已确认的 S 级接纳详情，明确的 A/B 级记作跳过位置。不能因遇见第一张 A/B 级就结束，也不能把未知品质记为跳过；品质在有界观察结束后仍不明确时，停止本次采集并保存未解决位置，不继续下一格。后一方式增加访问成本，但不扩大导出的实体范围；是否需要它由实际页面决定，不新增让用户选择的扫描模式。

## 3. 开始前必须核对的页面条件

| 条件 | 需要取得的证据与不满足时的处理 |
| --- | --- |
| 页面和目标 | T2 的窗口身份、前台、图像区域与几何有效；视频内明确是驱动盘仓库，列表与详情布局匹配已支持配置。登录、云排队、重连、弹窗及其他页面不开始。OS 窗口可用不替代游戏页面判断。 |
| 范围 | 记录品质及所有会限制库存的筛选，包括套装、槽位、等级、锁定、弃置、装备等实际存在的条件。若目标是全部 S 级，其他筛选不能排除其中物品；不能只看到 S 级标签就宣称整仓。无法观察的隐藏筛选须通过已验证的重置方式排除，否则拒绝开始。 |
| 顺序 | 固定并记录一种经验证的游戏排序及方向，扫描期间不改排序、筛选或物品状态。无需新增扫描器排序算法，也不假定 UI 排序有稳定的内部物品 ID。 |
| 起点 | 必须有可见的顶部依据，或在未来获确认的自动准备流程中取得回顶证据。“向上滚动很多次”与画面不再变化都不能单独证明顶部。开始于列表中部时不能标为整仓扫描。 |
| 数量 | 核实计数标签究竟表示全部库存、筛选后结果还是容量上限。只有与当前遍历范围对应且可可靠读取的数才作预期数量；混合列表总数不冒充 S 级总数。数量未知保持未知，不能用手填数字补成已验证数量。 |
| 可操作位置 | 测绘格位边界、可完整显示的行、选中标记、滚动条及详情区域；记录点击哪些行会自动滚动。只在已验证的稳定区域选择物品，顶部、底部及不足一屏分别验收。 |

预检保留一份范围与布局快照。筛选、排序、库存数量或布局在运行中发生可观察变化时，停止本次扫描并撤销原来的整仓结论。视觉扫描不能证明游戏库存从未在不可见处改变，结果仍是声明条件下的观测。

## 4. 一件物品何时可以进入识别队列

一次选择包括动作前画面、目标格位、输入结果和动作后画面。控制者先取得队列容量并重查平台条件，再发一次短点击；接纳截图前必须满足以下条件：

1. 列表仍属于同一范围，目标格位有物品且位置可对应。选中标记位于该目标，必要时核对先前选中标记已离开；不能用鼠标位置代替游戏内选中状态。
2. 详情区域完整可见，必需字段布局已结束过渡；使用文字和图标区域的稳定性，排除背景动画、鼠标和云客户端提示造成的假变化。稳定画面本身不证明是新物品。
3. 选中与详情之间有经过样本验证的关联证据。先核对格位与详情共同可见的套装、槽位、等级等特征，再结合动作后的内容变化或就绪信号；特征一致仅作支持，因为不同物品可以相同。不能只用固定延时、模型高分或新的采集时间戳接纳旧详情。
4. 当前截图及其区域仍属于同一窗口、几何和采集流。满足归属条件后才按公共契约接纳一次观测；导航尝试与用于核对的截图不另算一张盘。

首次读取已经选中的物品没有上一件详情可比较，需单独验证初始选中与完整页面的稳定状态。不能强制要求每一件文字都发生变化，否则一件库存和相同物品无法处理；也不能因此对后续物品放宽旧详情检查。

**相邻相同详情：**如果该布局有独立、经过验证的选中和详情就绪证据，可保留两次不同位置的观测。如果只能看到高亮移动而无法排除旧详情，候选做法是在同一可操作区域选择一件已知且可区分的物品，确认其详情后再回到目标，取得关联证据；每一步都等待自己的结果，最多做一轮，不把它当成超时后的重复点击。找不到可用参照或仍不明确时停止并保存诊断，不能复制上一件结果。此限制必须纳入重复物品验收；无法通过时仍是适配缺口，不宣布已支持。

等待详情时可在截止时间内重新观察，不因到期而盲目补点。首次动作效果尚不明确时，不发送验证用的下一次动作。完成有界观察及符合前述条件的参照核验后，仍无法确认详情归属时停止本次采集，按未解决位置记账，不跳到下一件。超时时间、稳定采样跨度与相似阈值来自三种场景的调参资料，并用未参与调整的序列验收；两张相同帧或等待某个毫秒数都不是普遍正确性保证。

锁定、弃置与装备者优先从同一次已确认归属的详情及选中格位读取，并保留对应裁剪。图标共用位置及状态是否互斥仍待样本确认；没有显示不能自动填为未锁定、未弃置或未装备。扫描不点击状态切换按钮。若装备者必须悬停或另开只读页面才能观察，先拿真实证据评估额外动作，再带回主控，不默认删掉该需求。

## 5. 滚动衔接、重复物品与末尾

维护当前已确认的格位顺序和未访问位置，列表内容只用于辅助匹配。每次推进前保存可比较的重叠区域；短滚动后重新测量格位，用多处共同特征和实际位移关联前后位置。至少保留一整行可用重叠作为起始候选，实际需要多少由布局与重复物品样本决定。无需每次都对整屏物品做 OCR。

| 情况 | 建议规则 |
| --- | --- |
| 前后位置唯一对应 | 仅在已证明的对应关系上移动当前位置，已经访问的重叠格位不再次接纳；新出现的位置按顺序处理。不根据滚轮刻度、滚动时长或“图变了”推定前进一行。 |
| 同一行多张盘或整行内容相同 | 属性与图像哈希不能充当实例身份。可结合滚动过程中的可测运动、格位边界、选中位置及滚动条辅助核对；滚动条单独只能表明大致进度，不能给出精确行号。存在多个可能对应关系时不任选一个。 |
| 边缘点击意外带动列表 | 当前坐标对应立即失效；只有布局已明确描述并验证该行为，且取得新的位置对应时才能继续。不能把旧格位坐标下的详情直接记给原目标。首选通过稳定区域选择减少这种情况。 |
| 一次移动太远、丢失重叠或画面模糊 | 在期限内继续观察；不能恢复唯一位置时停止，不猜测跳过了几行，不反向乱滚寻找看似相同的物品。已核实结果保留为部分结果。 |
| 空格与尾行 | 依据物品格位的占用证据识别尾行，不点击所有预设列后再删除相同结果。真实相同盘各自保留，空格不产生物品记录。 |

宣布全部覆盖，必须同时满足：起点与范围已核验；每次移动连续且无无法解释的跳跃；范围内所有占用位置已访问，S 级详情均已接纳，其他品质有明确跳过依据；末端有独立的底部/列表结束证据；若存在可信的同范围计数，与遍历账目一致。OCR 是否成功另行报告，不能用可用结果数量证明走完列表。

末端证据优先研究滚动条触底、列表尾部结构与最后占用格位，具体信号必须由当前布局样本验证。滚动后无变化、详情重复、OCR 数量达到估计值，都不能单独作结束条件。没有独立末端证据时保留部分或无法确认，不能为了自动结束而降低标准。

空库存必须由支持范围内明确的空列表状态证明；只有空白截图或计数 OCR 为零时不成功。单件、不足一行、整屏恰好填满、最后一行缺列和全部物品内容相同分别处理，不把它们视为普通多页的缩小版。锁定、弃置和已装备盘若属于声明范围，也必须各自覆盖。

## 6. 保存什么证据，怎样验收

每件保留公共契约要求的详情图和字段来源，另附目标格位、对应的导航步骤与接纳理由。按 [JSON 遍历账目](scan-json-format.md#遍历账目)记录每个新访问位置的 S 级接纳、明确非 S 跳过或未解决结局，并保留滚动前后裁剪与位置对应；输入失败另记事件。这些是按会话保存的有限诊断记录，不新增事件服务或常驻录像。候选帧和已接纳结果分开，验证用参照物和重叠重见不会制造新访问或重复观测；磁盘写入失败仍按公共停止契约处理。

T3 的独立图片只能验证裁剪和字段。T5 需要带顺序的资料：初始页面、操作及其时间、选中变化、详情到达、滚动和末端。合成序列可检验规则；真实游戏和云视频行为仍须在获相应授权后取得，当前没有样本或采集授权。

| 验收层 | 必须覆盖与通过条件 |
| --- | --- |
| 离线规则与序列回放 | 点击未生效、高亮先变而详情迟到、旧详情清晰且可 OCR、首件与相同相邻盘、整行相同、空格保留旧详情、分数行移动、多行跳跃、排序或筛选变化、断流画面重复、底部与中途冻结。预期不明确的序列应停止，不能输出全量成功；不凭脚本预设位置证明图像判断正确。 |
| 标注与独立验收 | 人工标注每一步应选中哪个位置、哪些帧仍是旧详情、实际位移与是否到底。调参和验收按完整扫描序列划分，同一次扫描的相邻帧不得跨组；同库存关联遵循 [T3 划分规则](t3-ocr-runtime-model-samples.md#收集标注与划分)。 |
| 三种客户端实机 | 按[主控整仓验收](scanner-architecture.md#两平台游戏与安装验收)分别做至少三次人工基准库存扫描；逐出现次数、位置和字段核对，无已知漏扫、重扫、详情错配或提前完整。空仓、单件、相同盘、跨屏重叠、末行以及管理状态分别覆盖；缺少样本的情形标未验证。 |
| 异常与结束 | 云延迟、画质变化、连接页面、失焦、遮挡、取消和队列背压分别验证。导航失配关闭输入并保留已接纳结果；恢复焦点或连接不自动续扫；正常结束后的剩余 OCR、保存和导出仍按 T4/T6 验收。 |
| 性能 | 分开记录输入至可核实响应、稳定等待、截图、滚动核对与 OCR 时间；报告每件和整仓时间及停止原因分布。边缘动作或少等几帧的收益不足以抵消漏扫和串盘，公开参考速度不作为本项目成绩。 |

通过有限验收集可以要求没有已知错误，不能承诺未来所有画面自动 100% 正确。真实重复盘与误判旧详情都须保留在验收集中，不能通过删掉困难样本让结果显得更好。

## 7. 成本、可改变结论的证据与后续

工作量仍归主控“仓库遍历与会话控制”的原估算，不能把本轮文档当作已完成其中的工程工作。新增成本集中在三种场景的页面测绘、关联与滚动序列标注、重复物品验证，以及云视频中时序和相似阈值的回归。已确认的手动准备起点减少自动筛选、排序与回顶的操作分支，但范围与顶部的程序核验仍然必需；暂不凭没有样本的界面给精确日数。

最脆弱的前提是：支持的游戏画面能提供足够证据，区分所选物品、列表实际位置与末端。若重复列表没有可判别的位置线索，或云客户端的高亮与详情长期无法关联，当前方案应停止并报告适配缺口；后续可在用户确认下缩窄显示配置或调整交互，不能自行删掉已确认的客户端，也不能把无法判定改成成功。

本轮已完成固定源码对照，用户已认可设计与手动准备方式；没有扫描速度、准确率或兼容性实测。浏览器打开应用的含义继续留在 T1，不阻塞本项分析。主控接续 [T6](t6-review-export-workflow.md)，整理预检提示、进度和停止到截图校对、保存、重新查看与导出的完整操作流程；T5 的视觉参数和当前页面证据则留待获授权后的真实资料与正式功能验收。
