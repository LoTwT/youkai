# 02 关键约束

第一阶段草案（2026-11-03）。这些约束决定了旅程的形状，第二阶段的布局不能违反它们。每条只写对用户体验的含义，规则正文以出处为准。编号 `C-xx` 供 03–05 引用。

## 扫描期间的交互约束

| 编号 | 约束 | 对旅程的含义 | 出处 |
| --- | --- | --- | --- |
| C-01 | **扫描期间游戏必须在前台**，且未最小化、未被遮挡；失焦、最小化、遮挡、几何或缩放改变都会停止扫描。 | 扫描时用户的注意力在游戏上，**不能**指望用户在扫描中操作 youkai。所有扫描中的反馈只能被“瞥见”或事后查看；开始前必须讲清楚这条规则。 | [T1 §1](../../specs/t1-mygo-ui-distribution.md#1-已确认选择与界面建议)、[架构 §5 生命周期](../../specs/scanner-architecture.md#生命周期)、[T2 §4.3](../../specs/t2-platform-capture-input.md#43-平台条件失效后的处理) |
| C-02 | **扫描中不能手动操作游戏。** 扫描器从不改排序；排序标签、筛选或布局的可观察变化会停止扫描并撤销完整结论。 | 开始前提示“不要切换应用或手动操作游戏”；结束时如果是这类原因，要说清是“有人操作了游戏”。 | [T1 §2](../../specs/t1-mygo-ui-distribution.md#2-关窗与使用提示)、[架构 §5 完整性与身份](../../specs/scanner-architecture.md#完整性与身份) |
| C-03 | **youkai 窗口在扫描中“点不到”。** 恢复可交互主窗口（托盘、Dock、第二实例、深链接）一律先停止扫描；点击扫描器本身就会让游戏失焦而停止。`ShowInactive` 也不保证不遮挡游戏，首版不承诺边扫边交互。 | “看一眼进度”这个动作本身就会结束扫描。扫描中的状态展示必须假设用户看不到主窗口；恢复入口要明确写出会停止（T1 要求写作“停止扫描并打开”）。 | [架构 §5 隐藏恢复与退出](../../specs/scanner-architecture.md#隐藏恢复与退出)、[T2 §5](../../specs/t2-platform-capture-input.md#5-隐藏恢复与退出契约的平台约束)、[T1 §2](../../specs/t1-mygo-ui-distribution.md#2-关窗与使用提示) |
| C-04 | **全局停止热键**是扫描中唯一不需要切出游戏的停止方式：Windows `Ctrl+Alt+Shift+S`，mac `⌃⌥⌘S`；开始前验证可注册，注册失败不能开始；不依赖可见窗口。 | 热键必须在开始前就让用户记住；停止后不会续扫。托盘“停止扫描”也可用，但用户要在扫描中移动鼠标、点击托盘，推断会让游戏失焦（扫描本来也就停止了，待实测）。 | [架构 §5 生命周期](../../specs/scanner-architecture.md#生命周期)、[T2 §5](../../specs/t2-platform-capture-input.md#5-隐藏恢复与退出契约的平台约束)；具体按键见[开发指南](../../development.md)第 41 行（规格正文未写按键）；`internal/ui/settings_view.go:135-141` |
| C-05 | **准备阶段有 30 秒预算。** 点开始后应用请求激活游戏一次（Windows 可能被系统拒绝），30 秒内前台、页面、范围和几何全部核验通过才开始操作游戏；到期以准备超时收尾，不自动开扫。30 秒是初始值，会随验收调整。 | 用户点开始后要在 30 秒内回到游戏；开始前要告诉用户这个时间。准备中的逐项原因目前只在到期后给出（L-02）。 | [架构 §5 隐藏恢复与退出](../../specs/scanner-architecture.md#隐藏恢复与退出)、[T2 §3.2](../../specs/t2-platform-capture-input.md#windows-扫描前预检w2b权威说明)、[架构 §6 开始前激活](../../specs/scanner-architecture.md#windows-本地客户端遍历状态1920x1080-首次全量真机扫描完成时序未标定) |
| C-06 | **停止是单向的。** 没有暂停续扫，也没有跨重启续扫；重新开始需要等上次收尾完成并重新预检，且从 T5 的起点重新开始。 | 一次扫描失败后只能重扫；失败旅程的出口是“查看已采集部分”或“重新开始”，没有“继续”。 | [架构 §5 生命周期](../../specs/scanner-architecture.md#生命周期)、[架构 §6](../../specs/scanner-architecture.md#6-首版功能范围) |
| C-07 | **游戏起点由用户准备。** 用户手动进入驱动盘仓库页；扫描器自动做转盘、筛选、S、回顶，不做登录、启动游戏或从任意页面导航。 | 首次扫描前要教会用户“打开仓库页”；扫描器会自己改筛选，用户不必提前设置。 | [T5 §1 操作起点](../../specs/t5-zzz-inventory-traversal.md#1-推荐路径与范围) |
| C-08 | **会话内的自动恢复不打断扫描。** 位置准备或证明失败只把该位置标为不完整并继续，累计 3 个不完整位置才整次停止；会话致命故障整次停止。 | 扫描中可能出现“某位置未完成”但扫描继续；结束时要列出不完整位置。 | [架构 §5 生命周期](../../specs/scanner-architecture.md#生命周期)、[T5 §5](../../specs/t5-zzz-inventory-traversal.md#5-滚动衔接重复物品与末尾) |
| C-09 | **进度只显示可证实的内容。** 没有可信总数，不显示百分比；后台进度和完成提示不激活主窗口。 | 进度表达只能是阶段 + 已采集数 + 位置等可证实信息；“完成”不能靠弹窗抢焦点通知。 | [架构 §2](../../specs/scanner-architecture.md#2-界面选择与应用层)、[架构 §6](../../specs/scanner-architecture.md#6-首版功能范围) |
