# 05 状态矩阵

第一阶段草案（2026-11-03）。按旅程步骤列出每种状态下：用户**看到什么信息**（不规定位置和形式）、**能做什么**、**下一步去哪里**、**怎样从失败中恢复**。平台不同时用“Win / mac”标出。旅程编号见 [03](03-journeys-windows.md)、[04](04-journeys-mac.md)，功能与约束编号见 [01](01-functions.md)、[02](02-constraints.md)。

2026-11-03 检查点 1 后修订：首版只支持 Windows 本地客户端，标为 mac 的行仅作后续版本参考；已决定的提案（P-xx，见 [06 第 1 节](06-proposals-and-phase2.md#1-功能提案)）按决定写入并标注编号，展示与导航条款已于 2026-11-05 同步（见 [12](12-implementation-plan.md)），数据与流程契约由各服务层 PR 同步；截图按 P-13（已决定）默认保留、结束时不询问，T6 §1 的对应条款（及架构 §5 清理约束第 1 条）已同步为 P-13（实现状态：随 PR-13 落地）。扫描中的状态按“完全没有反馈”的设计假设写（[06 第 3 节第 1 条](06-proposals-and-phase2.md#3-给第二阶段的输入)）。

状态名以规格为准：会话阶段为准备 → 采集 → 收尾 → 已结束（[架构 §5 生命周期](../../specs/scanner-architecture.md#生命周期)），结束类型为正常结束 / 用户取消 / 故障（[架构 §5 完整性与身份](../../specs/scanner-architecture.md#完整性与身份)）。
