## 3. 给第二阶段的输入

第二阶段负责布局、导航结构和视觉。以下是本阶段得出的、第二阶段必须回应的要点（不是布局方案）：

1. **扫描中用户看不到主窗口。** 主窗口的扫描相关内容主要服务于“开始前”和“结束后”；扫描中的反馈只能经托盘/菜单栏状态和游戏画面传达（C-01、C-03）。设计不要依赖“扫描中看主窗口”。
2. **每个结果相关的视图都要同时回答三个问题**：扫全了吗（覆盖结论与原因）、还要校对几件、保存了吗（C-26）。不能用一个“完成”代替。
3. **开始前的条件要一次看全，并按平台给出。** Windows 与 mac 的条件集合不同（C-10–C-19）；30 秒规则和实际停止热键必须在点开始前可见（C-04、C-05）。
4. **每种失败都要有“原因 + 怎么做 + 下一步入口”。** 05 的 S3、S6 列出了全部失败状态；故障码与英文报错只能放在诊断信息里（C-29、D-04）。
5. **校对是最高频的旅程。** 列表、证据（可放大、能对应字段）和表单需要同时可用；“确认并下一项”应能全程用键盘完成；默认窗口尺寸与 125% 缩放下也要成立（W3、现状 H3/M8）。
6. **导出前要有摘要**：纳入、排除（及去校对的入口）、覆盖结论、不含截图、写入位置；成功后给出打开目录的入口（W4、S8）。
7. **平台差异集中在一处表达**：快捷键写法、托盘与菜单栏的点击语义、托盘图标位置、数据目录位置（C-04、C-13、C-18）。所有恢复入口在扫描中都要写明“停止扫描并打开”（T1 §2）。
8. **首次使用与回访的首屏需求不同。** 首次需要环境准备（W1/M1）；回访更可能是“看上次结果”或“再扫一次”（S1）。
9. **低频功能不挤占主流程。** 清理、更新、关窗偏好、快捷键都是 P2（W6、W7），但清理在“空间不足阻止扫描”时会被主流程直接调用。
10. **核对 MyGo 能力后再定方案**：表格弹性列、图片缩放与平移、日期选择、界面语言固定为中文、系统通知（P-06）、托盘菜单的动态文字（P-02）。
11. **可访问性的最低要求**：关键旅程（W2a、W3、W4、W8）可全程键盘完成；状态不只靠颜色表达。
12. **实现结构问题**（现状 S1–S4）不在设计范围，但第二阶段的布局若要求新的状态（位置进度、预检明细、诊断详情），需要同时列出对服务层快照的要求（P-04）。
13. **导航结构以规格为起点**：T6 第 5 行“当前 UI 外壳”把界面布局定为以该节和 `internal/ui` 为准；规格已有侧栏三个目的地（扫描、历史、设置，扫描与校对是扫描目的地的两个阶段，T6 §1），以及历史行内操作、列显隐和详情同时展示证据与表单等布局条款（T6 §3、T1 §1）。第二阶段要么沿用这些条款，要么经 P-11 由用户决定放开后再改规格。05 的“下一步”列只写目的状态，不写导航方式。
