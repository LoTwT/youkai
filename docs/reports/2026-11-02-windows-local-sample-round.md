# 2026-11-02 Windows 本地客户端 W3a 样本轮

> 本报告是 W3a 离线样本的测量与局限来源；代码与测试落点见 W3b，遍历状态以[架构 §6 的 Windows 本地客户端遍历状态](../specs/scanner-architecture.md#windows-本地客户端遍历状态1920×1080-首次全量真机扫描通过时序未标定)为唯一权威说明。本轮只做只读截图与离线测量；同日晚间的 1920×1080 全量真机扫描见[全量扫描报告](2026-11-02-windows-local-field-acceptance.md)。

## 结论

- **滑块两端（S1）：** 约 28 件、约 1.4 屏的长列表从顶拖到底。x=55 列的亮段顶部帧为 y 148–711、底部帧为 368–931、拖动中为 361–924，滑块长 564 px。`ReferenceCalibration()` 依赖的两个前提——静止短滑块也到达轨道两端、轨道凹槽不亮于 `ScrollbarBrightMin=110`——均已由长列表验证；阈值 151/929 不变。
- **排序标签（S2）：** Windows 的“稀有度”文字外接框为 `(1329,154)-(1396,175)`（67×21）。把 mac 模板 Lanczos 放大到 186×81 后在参考位置附近搜索，最佳 MAD 为 9.37（偏移 `(1,−4)`；记录偏移 `(0,−4)` 处为 10.16），超过 `SortLabelMADMax=5.0`，**不能复用 mac 模板**。从 `S2/frame-0000.png` 截取 Windows 原生模板 `(1285,124)-(1467,201)`（182×77），只在 1920×1080 参考布局声明；缩放档继续丢弃排序声明。
- **面板探针（S2/S3）：** 探针 1 `(1781,39)` 打开色实测 `(196,41,10)`，原云推导值 `(183,56,31)` 在蓝通道只剩 4 级余量，已改为实测值；关闭色 `(15,14,15)` 保留。探针 2 `(1290,65)` 打开色实测 `(255,255,255)`，与现值一致。两个探针在 S2 三帧均判 open、在 S3 三帧均判 closed。
- **悬停（S3）：** 鼠标所在格 R2C3 与 S1 底部帧 `frame-0899` 的同格像素完全相同；整段列表区域并非只有 44 个像素不同（复核见下），但差异随帧变化并集中在卡片区域，与鼠标位置无关，因此不构成悬停高亮，也不干扰选中框判定，不需要改代码。
- **未解决：** 面板内“稀有度 S”按钮在开着两个套装筛选时实测约 y≈704，而 `PanelS` 为 `(1426,604)`；套装行数会让下方控件下移。本轮保留现值，重置后另测。重置 `(1432,1035)`、关闭 `(1804,55)` 与实测位置吻合。

## 1. 滑块两端

测量在 `ScrollTrack` 的 x=55 列、y 145–940 范围，按灰度 >110 取最长亮段：

| 帧 | 亮段 | 长度 | 判定 |
| --- | --- | ---: | --- |
| `S1/frame-0120.png`（顶部） | 148–711 | 564 | `start=148 ≤ 151` → top |
| `S1/frame-0133.png`（拖动中） | 361–924 | 564 | 不满足任一端 |
| `S1/frame-0899.png`（底部） | 368–931 | 564 | `end=931 ≥ 929` → bottom |

- 滑块最暗像素 116，槽为 0；两端各有一个抗锯齿像素 92–93，低于 `ScrollbarBrightMin=110`。
- 阈值保持 `referenceScrollTrackTop=148` + 3 = 151、`referenceScrollTrackBottom=931` − 2 = 929，与 mac 的 2–3 px 静止余量一致。
- **局限：** 最暗滑块像素只比阈值高 6 级；只测了一种列表长度（约 1.4 屏）。更长列表、不同主题或不同 DPI 下的滑块/凹槽亮度未测。

## 2. 排序标签

### 2.1 mac 模板不能复用

Windows 上“稀有度”文字的灰度 >70%（阈值 178）外接框为 `(1329,154)-(1396,175)`，即 67×21。把 `assets/sort-label-rarity.png` 用 Lanczos 放大到 186×81，在参考位置 `(1280,127)` 附近 ±6 px 搜索：

- 最佳 MAD **9.37**，偏移 `(1,−4)`；
- 记录偏移 `(0,−4)` 处 MAD **10.16**（即早先记录的约 10.2）；
- 两者都超过 `SortLabelMADMax=5.0`，且最佳偏移不是零，说明 Windows 原生布局与 mac 模板的重采样结果不一致。

因此 Windows 需要自己的原生模板，且按 `reference.go` 的约定不缩放模板、只在参考画布上比较。

### 2.2 Windows 原生模板

从 `S2/frame-0000.png` 截取：

```text
(1285,124)-(1467,201)   182×77
asset: internal/game/zzz/collect/assets/sort-label-rarity-winlocal.png
sha256: 58b1eeffa3b87129e3d6c0f1cfef66ce38672f9a4977eefccfbb583bb4b107b2
```

- 裁剪边距由 mac 裁剪按 1/0.859 换算后套在 Windows 文字框外：左 44、上 30、右 71、下 26 px；文字完整包在框内。
- 只含面板内像素；x≥1467 的 33 px 窗口内没有灰度 >178 的亮像素，因此不含下拉箭头。
- `ReferenceLayout()` 只在这个 1:1 1920×1080 布局声明 `SortLabel`/`SortTemplate`；`ScaledLayout` 对其他档继续清空两者，不缩小模板。
- **离线复核：** S2 第 0/5/9 帧的排序区域像素完全一致，因此只保留 `frame-0000` 作为 fixture；该裁剪与模板的 MAD 为 0.00。S3 面板关闭帧的同区域 MAD 为 29.35，超过 5.0。
- **局限：** 当前唯一的排序反例是面板关闭帧。生产路径只在两个探针都判 open 时才调用 `sortLabelMatches`，所以真正的风险场景——“面板打开、排序标签不是‘稀有度’”——没有样本。评审的量化检查把模板文字框 `(1329,154)-(1396,175)` 抹成背景灰度 12，得到 MAD **16.44**，是阈值 5.0 的 3 倍多；这说明误匹配可能性低，但仍是合成检查，不是实测帧。下一轮采样应补一帧其他排序标签作为 mismatch fixture。跨次面板打开以及筛选状态变化后的排序稳定性，也需要在全量真机扫描中验证。

## 4. 悬停

S3 的鼠标停在列表 R2C3（client `(398,343)`），S1 `frame-0899` 是同一列表内容。按通道差 >8%（>20.4）比较：

- 鼠标所在格与 S1 同格：**0 个像素不同**，游戏不渲染悬停高亮。
- 整段列表区域 `(70,115)-(596,971)`：S3 `frame-0000` 与 S1 `frame-0899` 有 **1,966** 个像素不同，不是早先记录的 44；S3 相邻帧 `frame-0000` 与 `frame-0005` 也有 5,383 个像素不同，S1 底部相邻帧之间同样有 1–4 千个差异。
- 差异随帧变化（S3 相邻帧、S1 底部相邻帧之间也有数百到数千个差异），集中在卡片边缘/发光区域；鼠标格本身不变，因此不构成悬停高亮，也不干扰选中框判定。**“整段列表只有 44 个像素不同”未复现**；可复现的事实是“悬停格完全相同、列表差异随帧变化且与鼠标位置无关”。

## 5. 未解决与未覆盖

- **面板 S 按钮：** 开着两个套装筛选时，“稀有度 S”按钮实测约 y≈704；`PanelS=(1426,604)` 是套装区为空时的位置。套装行数会让下方控件下移，本轮不修改，待重置后另测。
- **重置/关闭：** `PanelReset=(1432,1035)`、`PanelClose=(1804,55)` 与 S2 面板帧的实测位置吻合。
- **排序反例与稳定性：** 唯一反例是面板关闭帧，而生产路径只在两个探针都判 open 时比较排序标签；打开面板、标签不是“稀有度”的样本尚未采集。把模板文字框抹成背景灰度 12 的合成检查 MAD 为 16.44（阈值 5.0 的 3 倍多），只说明误匹配可能性低，不能替代实测；下一轮补一帧其他排序标签作为 mismatch fixture。跨次面板打开与筛选状态变化后的稳定性同样需在全量真机扫描中验证。
- **时序：** 本轮 1 fps 只用于静态采样，不能标定滚动停稳、拖拽时长或点击延迟；`WindowsLocalProfile` 的时序仍是 macOS 云客户端的未标定初值。
- **像素计数阈值：** S1 只用于滑块两端；选中框、转盘、墨迹、管理状态等计数阈值仍按 mac 面积比缩放，未在 Windows 上逐项标定。
- **OCR：** 本轮没有 OCR 样本或质量结论。
- **真机字段验收：** 本轮没有执行 1920×1080 全量扫描；W3a 只证明离线样本与代码路径，不构成开放档位或 Windows 本地客户端通过验收。同日晚间的全量扫描见[全量真机扫描报告](2026-11-02-windows-local-field-acceptance.md)；它仍不是三次人工基准验收。
